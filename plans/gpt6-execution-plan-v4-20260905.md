# GPT-6 接管执行计划 v4

状态：依据用户既定目标及 2026-09-05 原生 Ask 裁决执行；工程复核持续补充。不是 RC/产品完成声明。旧路线图、执行计划和封存检查点保留，不原地覆写历史。

## 目标与边界

维持一个公共入口、双模式研究输入、应用自有类型化多 Skill 控制图、A/B/C 三独立中文多页面 HTML 门户。实现既定科学证据与完整性门、独立上下文复核、一次性 publication 补件、不可变快照及手动触发后的自动刷新。八适应症×三报告、三宿主、fresh-install、恢复和实际科学/视觉验收保持最终门。

不恢复非 HTML 输出、表格导出、雷达、成熟度排名、定时监测、默认竞品总排名或强制 LangGraph。PDF 原文获取和解析仍属研究输入能力，不与 PDF 输出排除混淆。

本轮工程由主线程与原生 SubAgent 完成，不调用旧执行/会商 runner。产品的独立复核要求不因此取消。用户不承担测试。保留脏树和既有证据，旧中文根零接触；未授权删除、发布、改变访问控制或正式对同事分发。

## 裁决与术语

- 论文保留有效结果，动态状态每次核查，缓存仅加速。
- 历史报告还原截止日当时可知的信息；公开时间与生效、获取时间分开。
- 药智仅同运行短期复用登录观察，失败立即重检；短期具体数值仍为待定义策略。
- 来源实例标识不等于政策家族标识；引入明确映射，不破坏多来源实例身份。
- 首次研究、刷新、重新渲染使用同一个科学接受与产物身份合同；已存在文件不等于已交付。

## 每切片步骤

1. 重开相关当前源码、合同、测试与消费者，声明精确可写集。
2. 明确问题类别：实现缺陷自行修复；科学规则/来源权威/用户可见语义新增裁决用原生 Ask，不重复询问已批准事项。
3. 加真实最小反例并记录 RED；最小完整修复，禁止通过减小检查范围、删除有效谱系或固定 Top-N 绕过。
4. 运行定向测试和受影响的集成/浏览器测试，必要时全仓开发门；严格区分每种范围。
5. 将结果、未解决项和下一安全步骤写回唯一接管检查点。规范、精简回执入版本管理；大产物不无限复制。
