日期：2026-09-05。与 `docs/specs/competitive-intelligence-workflow-design-v1.4-review.md`、`plans/gpt6-goal-prompt-v5-20260905.md` 成套。状态：完整执行计划，按用户要求先交付文档；本文件不代表Goal已设置。本文提出取代 v4 的后续执行安排，不改写历史成果或验收记录。

## 1. 执行方式与原则

先完成并核对设计、计划、新 Goal prompt，再按用户方向进入后续实施。本轮工程只使用主线程和必要的原生 SubAgent，不启动旧执行/会商 runner。主线程负责关键设计、科学合同、集成和最终接受；并行只用于独立可写集或只读审查，不把依赖前置任务分给代理后空等。

每任务统一：读当前合同/消费者 → 具体反例 RED → 最小完整修复 → 定向/相邻回归 → 受影响真实浏览器/宿主验证 → 源码/产物摘要绑定 → 更新一个接管检查点。不能缩小检查范围以获得全绿，也不能把存量脏树推测性拆成历史阶段提交。

产品独立科学复核不因工程禁用 runner 而取消：必须有实际独立上下文和绑定回执；执行者修复后的自测不是独立接受。实质科学/用户行为新选择使用原生 Ask，多选项且说明后果；不重复询问已锁定要求。

## 3. 路线与依赖

P0 文档审定 → P1 统一基础合同 → P2 研究证据与时间 → P3 科学语义与报告视图 → P4 三门户 → P6真实研究；P5包装/宿主可在P1后并行，但最终须与P4/P6同源绑定。P7最终候选验收依赖P2–P6全部通过。旧根退役在最终通过且用户另行批准后单独安排。

阶段不按猜测的周数承诺完成；用可验收成果推进。外部平台访问、必需论文或宿主不可用分别记实际阻断，不能用其他测试充抵。
