# PRD — R2.4 逐对象 GateSpec 与 blocker 闭包

## 目标

依据批准的 v1.3 设计，将现有分散的 GateSpec、恢复检索、独立遗漏复核、科学 QC、
blocker audit 和 no-draft 机制闭合为唯一产品路径。任何报告都必须按锁定候选宇宙逐对象、
逐适用关键单元判定，不能用总覆盖率、删对象、空模块、草稿或占位门户取得通过。

## 用户结果

- 核心问题可回答：完成报告，并在受影响页面显示具体限制。
- 核心问题不可回答：不生成报告门户；内部保留完整机器 blocker audit，对用户只显示
  简洁、中文、可行动的证据不足说明。
- 技术失败、访问阻断、科学无证据、真实零值、不适用和冲突保持不同状态。
- 恢复必须来自两轮不同策略且有真实信息增益回执，最终由独立干净上下文复核。

## 退出条件

1. A/B/C GateSpec 的每个适用关键单元都有对象范围、适用性、上下文、来源角色、披露
   成熟度、新鲜度、缺失/冲突策略、失败代码与恢复路线的可验证合同。
2. 候选宇宙、GateSpec、事实绑定、恢复历史、遗漏结论、科学 QC 和 blocker audit 摘要
   相互绑定；漂移、跨报告复用、自审和删除失败对象均失败关闭。
3. blocker JSON 含 v1.3 要求的完整机器字段；Markdown 只含必要用户信息，不泄漏内部
   枚举、路径、提示词或工程状态。
4. 正向、负向、恢复、幂等、历史快照和 no-draft 产品测试通过；全 integration、全仓
   gate、bundle/fresh-install 通过独立审阅。

## 排除

不实现门户视觉重构、真实药智浏览器、三宿主实机、24 份真实门户、PDF/PPT、监测或 RC。
