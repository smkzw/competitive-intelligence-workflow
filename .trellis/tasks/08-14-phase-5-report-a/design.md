# Phase 5 A 类门户技术设计

## Task 5.2 边界

`pages.py` 是锁定 A 快照到门户页面之间的只读投影视图层。它接收 Task 5.1 已验证的全宇宙分析、产品合同及版本化扩展记录，只输出不可变、可排序、可筛选的页面数据；不改变纳排、成熟度、证据状态或报告可生成性。

## 输入与身份

- 快照身份、产品集合及父子关系以 `ApplicableUniverseSnapshot` 为唯一依据。
- 产品合同必须与快照产品一一对应；缺失、重复、多余或顺序漂移失败关闭。
- 扩展记录必须绑定产品以及自身不可变事实/来源版本；未知产品、未知试验、跨产品关联失败关闭。

## 八类投影

1. 竞争格局：产品、靶点、模态、阶段、地域、生命周期和状态的完整分组维度。
2. 产品总览：全量筛选行和稳定详情路由，不做固定数量截断。
3. 产品档案：逐产品汇集身份、机制、开发、试验、监管、组织、交易、专利和历史责任。
4. 临床组合：产品—试验—地域—阶段—状态与核心角色保持可追溯关系。
5. 监管：同一产品的中国与境外事件分轨，保留事件类型、日期、状态和版本。
6. 企业与交易：组织角色、关系、地域权益、交易事件和公开条款分别建模。
7. 专利与保护：专利族、法域、保护范围、期限和监管独占分别建模。
8. 历史与边缘：暂停、终止、撤回、放弃及邻近机制观察显式保留。

## 关键不变量

- 所有投影的产品 ID 集合必须等于锁定快照；排序仅改变展示顺序，不改变集合。
- 缺失扩展事实用明确状态表达，不用空字符串、默认金额、默认期限或推断结论填补。
- 视图模型只保存专业中文标签；后端枚举可以内部使用，但不直接作为用户标签。
- 页面模板与图形交互属于 Task 5.4，Task 5.2 不提前实现。

## 回退

变更只新增 `reports/a/pages.py`、导出和单元测试；若验收失败，可整提交回退，不影响 Phase 1–4 或 Task 5.1 的证据合同。
