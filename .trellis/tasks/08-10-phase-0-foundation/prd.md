# Phase 0 基线与独立仓

## Goal

完成批准基线、独立仓、依赖锁和康哲设计合同确认前材料。

## Requirements

- 新源码根必须是独立 Git 仓，并由 Trellis 管理；旧工程保持只读。
- 保存用户已批准 v1.2 的独立批准记录和按摘要复制的原始规格，不修改规格正文。
- 建立机器可读迁移清单和旧运行时依赖扫描器；历史材料可保留，但必须显式标为 historical。
- 固定 Python、运行依赖、测试依赖、版本、许可证和用途，生成可冻结重建的 `uv.lock`。
- 稳定读取最新版康哲 `design.md → design_specs/`，按用户 2026-08-11 指示内化为项目自有设计合同；记录来源和项目摘要，此后不再同步通用版。
- 完成公共 Skill、唯一 CLI catalog、页面/筛选/格式机器合同和 Phase 0 测试骨架后，方可进入 Phase 1。

## Acceptance Criteria

- [ ] `git rev-parse --show-toplevel` 精确指向新根，Trellis 六个宿主入口和 296 个受管文件完整。
- [ ] Task 0.1 的失败先行测试、迁移清单、旧依赖扫描器通过并输出 `LEGACY_REF_OK`。
- [ ] Task 0.2 的依赖合同测试通过，`uv sync --all-extras --frozen` 可重建环境。
- [ ] Task 0.3 的稳定双读、内化决定、来源/项目摘要及项目内合同测试可审计；项目运行不依赖通用版。
- [ ] Task 0.4–0.5 的包清单、公共 Skill、CLI catalog、页面/筛选/格式合同测试全部通过。
- [ ] 独立接受者复核 Phase 0 真实文件与测试锚点；失败时只删除新根即可回滚，旧根不受影响。
