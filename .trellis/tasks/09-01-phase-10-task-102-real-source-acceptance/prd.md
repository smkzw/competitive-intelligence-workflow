# Task 10.2 产品需求

## 目标

用当前源码和全新空项目，分别运行三条真实来源路径：A 类特应性皮炎、B 类阵发性睡眠性血红蛋白尿、C 类特应性皮炎。每条路径必须从真实注册平台、监管来源、主要论文/会议/企业披露和批准的中文行业来源收集资料，经关键证据门槛后生成多页面站点式 HTML。

## 用户结果

- 用户只看到医学意义明确的报告及必要的阻断指引，不看到检索日志、后端状态码或工程标签。
- 关键证据不足时不生成草稿；技术/网络/登录问题与“未公开”“穷尽后未找到”分开。
- A、B、C 均需真实物理详情页、图先表后、筛选/下钻/证据定位；首屏核心图表不依赖横向拖动。
- B 必须覆盖疗效、安全性、基线和试验完成/处置；C 必须覆盖登记优先的关键人群、分组、干预、终点和时间点。

## 验收边界

1. 三个项目根在本次 run 开始时新建且为空，不复用 Task 10.1 fixture 输出、Task 9.5 候选报告或旧页面。
2. 每类报告的 exact node 绑定：本次 `run_id`、snapshot、artifact manifest/record、当前 source/package digest、真实文件摘要/字节/mtime、Chromium 与 WebKit 全路由 verdict。
3. 数据截止使用 Task 10.1 的已物化历史 cutoff；截止后首次披露只进入后续刷新候选，不倒灌。
4. 真实来源检索遵循项目来源策略和用户批准的权威中文行业来源；publication 用于结果交叉核验，试验设计优先登记平台。
5. 首版只要求 HTML；PDF、HTML-PPT、PPTX 不预检、不生成、不阻断。

## 非目标

- 不冻结最终 RC，不生成四格式全矩阵。
- 不实施恢复包、迁移、旧根盘点或删除。
- 不做安全专项测试。
- 不以一个既有脱敏 fixture 伪装成真实 fresh-source 验收。
