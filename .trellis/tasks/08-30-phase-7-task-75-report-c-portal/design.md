# Task 7.5 设计约束

## 设计合同

- 项目权威：`contracts/kangzhe/design.md` → `design_specs/ROUTER.md` → `core.md` → `project_profile.md` → `track_site.md`。
- 通用包最新版已核验；项目副本继续独立冻结，不在本任务反向修改通用版。
- 门户采用 `site` 主轨。筛选、联动和下钻是站点页面能力，不叠加 `track_interactive.md` 的单页驾驶舱版式。
- 不使用 1280×720 幻灯片画布，不使用 React/Vue，不依赖远程字体、图片或脚本；`file://` 与静态服务器均可运行。

## 数据与身份

- 输入必须是已通过 Task 7.1 门槛的 `DesignObservation` 集，以及 Task 7.2—7.4 的精确下钻、页面投影和多路径综合结果。
- 页面、图、表、抽屉共享稳定的观察、试验、队列、组别和终点三元身份；不得按显示名或出现顺序重新配对。
- 浏览器不计算科学事实、设计签名或推荐；只做确定性过滤、排序、联动和显示。
- 无关键证据时失败关闭，不生成草稿门户；未公开的扩展统计字段可在关键设计已足够时准确标注。

## 视觉与交互

- 浅色面积不少于 80%，橙黄合计不超过 12%，风险红只用于真实风险或阻断。
- 默认浅色粘性页眉；左上正式 CMS Logo 可读，站点名、导航和搜索互不挤压。
- 图表先回答临床问题，再选择关系图、时间线、范围图、矩阵、小多图、气泡图或雷达图；无原始可逆值时不生成归一化雷达。
- 核心图在默认内容列内完整显示；宽表通过身份列压缩、列分组、同页详情入口或响应式折叠处理，不能把核心比较字段推到视野外。
- 抽屉、筛选、弹层和按钮具备一致焦点、Esc 关闭、焦点返回、减少动态效果和静态冻结。
- 搜索过程、技术诊断和证据门槛计算只进入单独运行记录，不成为报告主要页面。

## 实施分段

1. 保存完整物理页面、真实正负例和交互的 RED。
2. 实现 C 输入适配器、模板、站点资产和构建清单。
3. 运行功能与双内核浏览器测试，修复科学和交互缺陷。
4. 建立当前候选视觉策划书，执行真实截图诊断与定向美化。
5. 由隔离视觉审阅角色检查全部页面和核心路径，Codex 以实际运行时作最终接受。
