# Task 7.5 产品要求

## 用户与目标

默认用户是视觉敏感、不熟悉计算机操作的中文母语资深临床试验医学人员。用户打开报告后，应直接进入临床设计比较，不需要理解工作流、证据门槛或程序状态。

## 页面范围

必须真实生成并互通冻结目录中的十二个静态页面责任，以及每个适格试验的物理详情页：

1. 首页；
2. 设计图谱；
3. 试验档案；
4. 人群与疾病定义；
5. 入选标准；
6. 排除标准；
7. 分组、干预与对照；
8. 终点、定义与时间点；
9. 访视、疗程与随访；
10. 样本量、分析集与统计设计；
11. 设计模式、权衡与可选路径；
12. 资料版本与局限。

## 用户可见要求

- 首页只保留报告名称、适应症和观察截止时间，不解释 C 类报告或系统工作方式。
- 图在前、同一事实集的完整表格在后；空白、未公开、不适用和路径未解析必须准确区分。
- 页面级筛选影响全页；模块级筛选只影响相关模块；图、表、网址和证据抽屉状态一致。
- 能精确下钻到产品、试验、队列/组别、设计要素、原始字段、量表、时间、运算符、阈值、单位和来源定位。
- 设计综合至少呈现两条有证据支持的候选路径及其前提和权衡，不排名、不输出唯一最佳方案。
- 所有用户文字使用中文临床试验语境；试验编号、药物通用名和必要缩写可保留。

## 完成证据

- 真实正例和证据不足负例；不能只用空壳或合成占位页面。
- 静态结构、事实集合、筛选联动、网址恢复、证据抽屉、键盘和无障碍测试通过。
- Chromium 与 WebKit 在 1024、1280、1440、1920 宽度下逐页真实渲染；核心图无需横向拖动即可完整阅读。
- 独立视觉执行后另行完成独立视觉会商；生成者不能自签接受。
