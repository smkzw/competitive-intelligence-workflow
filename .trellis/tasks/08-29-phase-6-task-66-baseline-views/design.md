# Task 6.6 技术设计

## 边界

新增 `src/ci_workflow/reports/b/baseline_views.py`，只消费已校验的 `BaselineObservation`。复用既有披露状态、稳定事实身份和证据定位；不改 Task 6.5 合同、GateSpec/evaluator，不创建物理 HTML 模板。Task 6.9 将本视图模型接入站点壳层并做真实浏览器验收。

## 视图结构

- `BaselineSelectionState`：保存页面级与模块级多选、证据焦点和可逆 URL 状态。
- `BaselineChartPanel`：一个科学兼容桶的图形合同，包含域、变量、图形类型、兼容键、可绘制行、不能绘制的状态行及中文说明。
- `BaselineTableRow`：对原事实的无损投影，保留数值、统计形式、分母、披露状态、差异标签和来源身份。
- `BaselineViewState`：持有完整事实集、当前筛选、确定性默认筛选、图形面板、完整表格、筛选项适用性和证据焦点。

## 确定性规则

1. 先过滤事实，再由同一筛选后集合生成图和表。
2. 以 `compatibility_key` 分桶，不在视图层另写模糊合并规则。
3. 连续变量的中心值与区间统计保持分离；来源明确提供区间的行才绘制区间。
4. 分类比例须有分母；类别是否穷尽不是现有事实字段时，默认禁止 100% 堆叠图。
5. 无可绘制数值时生成披露状态面板，不生成空坐标系。
6. 默认排序只用规范变量优先级、域顺序和稳定身份，不读数值大小。
7. URL 使用标准库 `urllib.parse`；重复参数表达多选，解析后重新走强类型校验。
