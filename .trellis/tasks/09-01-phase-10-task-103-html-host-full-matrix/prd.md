# Task 10.3 产品需求

## 目标

从 Task 10.1 的唯一机器目录读取 `full-matrix-v1`，在全新隔离项目中完成 A/B/C 多页面站点式 HTML、全量首版场景和 Codex/Hermes/OMP 三宿主的 pre-RC 预演。预演只能证明候选能力，不得提前关闭 Task 10.6、恢复演练或旧工程删除责任。

## 用户体验

- 医学经理只看到适应症与 A/B/C 报告选择，不需要理解执行器、摘要或状态码。
- A/B/C 均能通过首页、导航、筛选、搜索和详情下钻直接使用；关键图表在默认内容列内可读。
- 关键证据不足时不生成草稿；技术失败、确实未公开和检索穷尽分别记录。
- 页面使用中文临床试验语境，不显示内部步骤、日志或工程标签。

## 最新范围裁决

ADR 0013 与用户后续指令高于原实施计划中的“四格式”措辞：

- 首版只运行并验收 `html`。
- 不生成、不补造、不验证 PDF、HTML-PPT 或 PPTX。
- 不触发 PPTX 八项确认、PPT Master 作业或多格式部分交付。
- 后续格式仍保留既有 Phase 8 检查点和未来责任，不得在本任务记为接受或不适用。

## 验收标准

1. runner 只能从 catalog 解析适应症、时区、截止、报告、格式和逐文件摘要；命令行不得覆盖科学真值。
2. 新项目根必须不存在或为空；预存 snapshot、manifest、站点或宿主回执均失败关闭。
3. 顺序固定为：catalog/输入核验 → 项目运行 → A/B/C 全路由 ego(lite) 四档桌面视口核验 → 三宿主真实入口 smoke → 项目核验 → 回执聚合；不得使用或回退到其他浏览器。
4. 当前运行必须绑定三个 HTML 产物及其实际文件、摘要、生成时间和浏览器 verdict；旧运行或伪截图不能通过。
5. `--suite full` 为所有 `execution_scope=full-matrix` 的首版 case/子 case 生成 `pre_rc_rehearsal` 回执；恢复、切换及未来格式保持 `pending_future_owner`。
6. 任一子命令、报告、浏览器、宿主或摘要核验失败时，总结果不得输出通过。
7. 成功信号固定为 `PRE_RC_REHEARSAL_OK reports=3 formats=1 hosts=3 ... release_cases_closed=0`。

## 非目标

- 不冻结或发布 RC。
- 不执行 PDF/PPT 相关生成、设计或验收。
- 不迁移、切换或删除旧工程。
- 不进行安全专项测试。
