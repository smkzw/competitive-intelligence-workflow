# Phase 6 技术设计

## 边界与分层

Phase 6 沿用现有科学真源、GateSpec、快照、共用视图/筛选/证据抽屉和康哲站点壳层，不另建第二套管线。

数据流固定为：来源版本与定位 → 事实/声明 → B 关键字段门槛 → 锁定 B 快照 → B 视图模型 → 物理门户 → 当前运行验收。

## 核心合同

- `reports/common/study_roles.py` 是 B/C 共用的试验角色真源；论文分类器只提供独立的 `publication_role`。
- 终点与时间窗兼容规则由版本化 YAML 驱动，运行记录保存规则 ID、原值和差异标签；没有规则即分列。
- B 疗效、安全性、基线、处置模块各自拥有强类型事实记录，但复用共用的快照、行身份、筛选、图表—表格同步和证据抽屉合同。
- 基线阻断在报告快照锁定前执行；处置缺失作为准确披露状态进入视图，不触发报告阻断。
- 物理模板只消费已验收的视图模型，不在模板中重新解释研究角色、兼容性、分母或缺失状态。

## 兼容与回滚

- A 类既有数据合同、页面和产物不修改语义；共用模块变化必须运行 A 回归。
- 每个 Task 独立 RED/GREEN、提交和验收；失败只回滚当前 Task 的新增合同或视图，不删除已接受的 A 基线。
- Phase 6 未通过 Task 6.10 前不发布 B，也不进入 Phase 7。
