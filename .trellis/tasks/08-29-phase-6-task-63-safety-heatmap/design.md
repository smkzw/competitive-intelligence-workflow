# Task 6.3 技术设计

## 数据流

`安全性原子事实 + 研究角色 + 产品默认锚定试验 + 术语映射` → `SafetyFactRow` → `可比语境分组` → `热图单元与完整 AE 视图` → `默认事件子集或用户搜索展开`。

## 合同边界

1. `SafetyFactRow` 保存事件族、来源术语、可选规范术语、试验/产品/组别、分析人群、时间窗、计量方式、分母、披露状态、来源版本和精确定位。
2. `SafetyComparableContext` 只由事件身份、时间窗、分析人群、单位和分母语义确定；热图颜色不得跨语境比较。
3. `SafetyHeatmapCell` 始终保存中文显示值；只有已报告数值和明确为零可进入相对色阶。
4. `SafetyViewSet` 同时保存默认热图行和完整事件行；默认选择只是视图状态，不删除事实、不生成名次。
5. 术语映射是可选的明确谱系，不是强制归一化。无可靠映射时来源术语保持独立。

## 默认事件选择

- 固定安全性总览维度优先保留 TEAE、SAE、AESI；有数据时加入死亡、3 级及以上、导致停药和治疗相关 TEAE。
- 常见不良事件候选取来源高频、任一治疗组发生率至少 5%、任一治疗—对照绝对差至少 5 个百分点及项目适配器标记的临床重要事件之并集。
- 在不删除完整事件集的前提下，以稳定、可解释的信息量规则选择约 10–15 行；同分使用稳定事件身份，不读取产品宣传优先级。

## 关键决策

- 复用 `FactDisclosureState`、Task 6.1 研究角色和既有 A 类安全性合同中的单位语义；不引入新依赖，不复制门户代码。
- 不建立“安全性好坏”分数或排序。色阶只表达同一事件和可比语境中的观察发生率相对高低。
- 技术路线未解决与科学资料未报告分别保存，便于上游恢复而不污染用户判断。
- 权威构建入口重新校验 Pydantic 实例，防止 `model_copy(update=...)` 绕过构造期约束。

## 错误与恢复

- 数值、披露状态、分母或单位自相矛盾时失败关闭。
- 当前筛选无可着色数值时保留状态矩阵与完整表，不生成空色阶或零值。
- 多试验数据默认分列；只有明确标记并具备来源范围的综合分析可作为独立语境展示。

## 兼容与回滚

新代码限于 `reports/b/safety.py` 和两份目标测试。失败时可撤销本任务新增文件，不改变已接受的 Task 6.1–6.2 语义或 A 类产物。
