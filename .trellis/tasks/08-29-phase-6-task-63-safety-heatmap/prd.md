# Task 6.3 安全性热图和完整 AE 视图

## 目标

为 B 类报告建立面向医学经理的多维安全性热图和完整不良事件视图合同，使用户先看到风险分布，再查阅完整数值与来源，同时避免把披露缺口、阈值和技术异常误解为零发生。

## 范围

- 建立 TEAE、SAE、AESI、常见不良事件及有数据时的死亡、3 级及以上不良事件、导致停药不良事件、治疗相关 TEAE 事实与视图模型。
- 建立同一事件、同一可比语境内的热图色阶合同；数值始终显示在单元格中。
- 建立默认约 10–15 行常见不良事件选择和完整事件集搜索/展开合同。
- 保存试验、产品、组别、分析人群、时间窗、分母、来源位置及术语映射谱系。
- 本任务不创建 HTML，不实现疗效—安全性气泡图，不做安全性排名、综合评分或跨试验合并。

## 不可放宽的要求

- 报告值、明确为零、未报告、低于来源列示阈值、不适用、存在冲突和来源路线未解决必须分开；非数值状态不得进入色阶或伪装成零。
- 颜色只比较相同事件且时间窗、分析人群、计量单位和分母语义兼容的单元；不兼容时分列。
- 治疗组与安慰剂/对照组均保留；不得用产品级汇总覆盖具体试验组别。
- 每个产品默认锚定一项核心试验；多试验不得自动合并，除非来源本身报告权威综合分析并保存来源范围。
- MedDRA 可用时保存首选术语、版本、方法和置信度；不可用或不确定时保留来源术语并分开显示，禁止自由翻译强并。
- 默认行选择不构成风险排序；完整事件集不因默认 10–15 行而丢失。

## 验收标准

- [ ] `test_safety_heatmap.py` 覆盖默认维度、同事件可比色阶、试验锚定、治疗—对照并列、默认事件选择、完整搜索展开和无排名。
- [ ] `test_ae_state_semantics.py` 覆盖所有披露状态、数值一致性、阈值语义、技术异常及术语映射保守边界。
- [ ] Task 6.1–6.2、A 类报告及相关来源回归通过；Ruff、strict mypy、差异检查通过。
- [ ] 独立医学经理复核确认安全性风险可快速辨识，且没有把披露差异或不可比数据做成误导性色阶。
