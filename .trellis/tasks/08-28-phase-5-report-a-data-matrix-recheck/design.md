# 技术设计

## 1. 诊断边界

按五段链路核对同一试验：来源清单 → 获取内容 → 规范化结果 → 报告事实 → 默认图表。每段输出稳定的产品、试验和字段标识，定位丢失而不是用总行数推断完整。

## 2. 数据完整性

- 以产品和关键试验为审计主键，统计疗效治疗组/对照组、TEAE、SAE、AESI 与常见 AE 的公开和入库状态。
- ClinicalTrials.gov 结果登记只覆盖一个来源分支。登记无结果时继续检查主要论文、监管/说明书、会议或公司披露以及批准的中文权威来源。
- 只有完成适用来源复核后才更新结果状态。发现已公开但尚未结构化的数值时，进入现有来源包与事实生成路径，不在模板或 JavaScript 中手填。
- 默认图表从结构化事实选择“具有可比值的最佳记录”；不以数组首条记录或单一英文术语作为唯一匹配条件。

## 3. 安全性热图

- 维持产品为行、事件为列；默认事件不超过五项，更多事件按用户选择分块纵向排列。
- 热图网格使用容器实际宽度，首列保留产品名，事件列允许中文短标签换行；单元格不得设置导致整体溢出的固定最小宽度。
- 首页与详情页共用同一渲染器和同一适配合同。完整表格保持独立滚动容器。
- 1024 px 是本次普通桌面最低验收宽度；更窄视口只需不产生文档级横向滚动，并保持可访问的纵向阅读。

## 4. 交付与防旧版

重新生成新的不可变版本目录，写入来源、事实、报告和浏览器验收摘要。最终只交付本次新入口；旧产物保留为历史证据，不再作为当前报告入口。

## 5. 验证

先用失败测试固定产品覆盖与 1024 px 横向溢出，再修复数据链路和共享热图渲染。随后运行 A 类联合回归、全工程检查、双浏览器四视口截图和独立视觉复核。
