# A类报告数值完整性与安全矩阵适配复查

## Goal

让当前交付的 A 类特应性皮炎报告真实呈现已经公开的疗效和安全性数值，并使首页与安全性详情页的安全性热图在普通桌面默认视野内无需左右拖动即可完成横向阅读。

## Requirements

- 不以记录总条数代替覆盖完整性。必须按产品、试验、治疗组、关键终点、安全性维度和来源状态量化覆盖。
- 对完成或已有结果披露迹象的 II/III 期试验，不得仅因 ClinicalTrials.gov 未登记结果就写成“暂无公开关键结果”；必须核对登记、主要论文、监管材料、会议/公司披露及已批准的中文权威来源。
- 将“确实未公开”“检索后未找到”“技术未取得”“已取得但未解析”“已解析但未进入报告”分别记录；技术问题不能伪装成证据缺失。
- 已公开数值必须进入事实集、图和表；不能只在原始来源或 17,007 条事实的总计中存在。
- 首页和安全性页默认热图都采用产品纵向、事件横向的可扫读结构；普通桌面默认视口不得出现热图或文档级横向滚动。
- 完整表格可在自身容器内横向滚动，但不得牵连热图或整页；图先于表。
- 当前交付入口必须指向本次重新生成并验收的不可变产物，不得让用户继续打开旧版页面。
- 中文标签应符合资深临床试验医学人员的阅读习惯，不展示程序或日志术语。

## Acceptance Criteria

- [ ] 形成逐产品、逐试验的疗效/安全性公开性与入库状态审计，能够解释每个缺口落在哪一层。
- [ ] 对所有已标记“有公开关键结果”的产品，疗效和安全性均有可追溯数值；对其他完成或已有披露迹象的关键试验完成多来源复核，发现公开结果则补入。
- [ ] 默认首页疗效和安全性图不因错误的精确字符串、首条占位记录或默认筛选而丢弃已有可比数值。
- [ ] 1024、1280、1440、1920 px 真实浏览器视口下，首页和安全性详情页的热图及整页均无横向滚动；关键标签与数值可读。
- [ ] 自动化测试覆盖产品级数值覆盖、默认图形数据覆盖、旧产物入口和矩阵宽度回归。
- [ ] 重新生成不可变报告，完成 Chromium 与 WebKit 实机复查，并由独立视觉测试者按真实医学经理角色验收。

## Notes

- 先修根因，再重新生成；不得直接篡改已接受产物。
- 不将“页面能打开”或“测试数通过”作为数值完整性的替代证据。
