# Task 9.4 产品需求

## 目标

让 Codex、Hermes、OMP 从各自宿主入口运行同一工作流时，对医学经理呈现相同的最小输入、进度状态、关键证据阻断、用户协助、恢复和站点产物语义。宿主差异只留在工具定位、进程和会话字段中，不能进入科学判断。

## 用户体验

- 用户仍只需选择 A/B/C 一至三类报告、提供适应症并选择输出；首版输出固定为站点式 HTML。
- 主对话只报告已启动、重要里程碑、需要用户资料、部分完成、阻断和全部完成，不刷搜索或诊断日志。
- 缺关键证据时三宿主都不生成草稿，并用简洁中文说明阻断原因、AI 已尝试的方法和用户要做什么。
- 用户补充文件或修复环境后，从同一项目事件与检查点恢复，只重排失败能力及其下游，不重新完成已接受工作。

## 验收标准

1. 基类只允许调用工具、映射中断/恢复、解析最小输入、提供路径、发送必要状态和返回产物。
2. Codex/Hermes/OMP 三个薄适配器对同一 fixture 产生相同语义状态、失败分类、恢复请求和产物摘要。
3. 宿主专有字段不得影响项目合同、来源权重、门槛、事实/声明、正式快照、科学质控或报告内容摘要。
4. 能力缺失只阻断依赖项；首版站点 HTML 不因 PDF、HTML-PPT、PPT Master 或 Office 不可用而阻断。
5. 环境恢复只重排失败能力及其下游；手工收件箱与部分交付在三宿主语义等价。
6. `host-receipt` 绑定包、fixture、真实安装入口、宿主可执行文件/版本、外部进程、会话、运行、事件链和最终 manifest；同进程伪造三宿主、旧回执或 adapter-only JSON 失败关闭。
7. `host-smoke-v1` 在唯一 fixture catalog 登记并绑定逐文件摘要和 case digest。
8. Task 9.4 的源码级与外部入口合同通过；候选包 fresh-install 后的最终三宿主实跑在 Task 9.5 用同一合同复验。

## 非目标

- 不新增 Web 工作台或中心服务。
- 不让宿主适配器持有科学真源或私有恢复状态。
- 不在首版生成/验收 PDF、HTML-PPT 或 PPTX。
- 不实现 LangGraph 扩展，不进行安全测试。
