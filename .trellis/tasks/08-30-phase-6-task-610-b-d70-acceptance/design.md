# Task 6.10 技术设计

## 数据与运行边界

四个验收项目使用独立空目录。三个 D70 案例各自拥有完整输入文件和 catalog 摘要；运行器仅消费注册案例，禁止以运行时开关改变同一输入的预期结果。fresh PNH 项目使用正向 PNH 输入包并走正式项目创建、能力预检与运行路径。

运行证据链为：输入逐文件 SHA-256 → case digest（fixture 场景）→ run event → 当前运行 manifest → 报告快照 → 格式 manifest → 站点摘要。验收只接受同一链上的当前标识与运行起点之后生成的文件。

## D70 语义设计

- 基线门槛按核心试验、可比较组和四类必需字段逐项计算，失败代码包含试验、组别和字段，不生成 B 草稿。
- 恢复案例只补齐缺失基线事实，保留其他输入一致性，验证同一项目重新运行产生新快照。
- 处置缺失案例建模完整字段全集，以类型化“未公开”呈现，不生成零值或空图。
- 部分数据的图表数据集只含可计算观察值；完整表与矩阵保留未公开、不适用、不可比和已公开零值。
- 统计口径兼容性在视图模型阶段决定，模板与浏览器脚本不得重新合并分母或推导人数。

## PNH 正向纵切

PNH 输入包覆盖至少两个关键核心试验、治疗组与对照组、主要疗效、安全性、基线和试验完成情况。关键数值及研究角色保留来源定位和披露状态；验收对 APPLY-PNH 与 APPOINT-PNH 的关键疗效事实设置哨兵断言，防止重复、错组或旧快照混入。

## 门户与视觉

复用 Task 6.9 已验收的 B 多页面门户，不叠加单页驾驶舱轨。项目内 `contracts/kangzhe/design_specs` 为唯一运行时设计合同；最新版通用规范只用于差异核对，项目路由的多页面门户裁决继续保留。

浏览器验收覆盖所有静态页、产品页和试验页，检查默认首屏、图在表前、字体地板、Logo、浅色顶栏、图表坐标与标签、完整表、筛选、网址状态、数据依据、抽屉、键盘、动效冻结、控制台及横向溢出。视觉审阅者直接查看真实截图与可运行站点，不接收测试计数替代视觉证据。

## 失败与恢复

- 命令失败、竞品/试验/关键字段为零、当前运行绑定不闭合或页面数据异常时立即停止顺序流水线并追查根因。
- 网络/技术失败与穷尽检索后未公开分开记录；技术失败按同路径重试、替代路径和诊断后才可形成用户阻断。
- 模型路线不可用时保留命令、耗时和失败类别，不静默换模型；实现与其他可用审阅可继续，但缺失指定审阅必须在结论中明示。
- 修复循环仅修改最小共享原因，完成后重跑受影响测试、全阶段集合和真实浏览器验收。
