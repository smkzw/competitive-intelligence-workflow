# Phase 6 Task 6.10：B/D70 独立验收

## 目标

以当次全新 PNH B 类报告纵切和三个物理隔离的 D70 案例，验证基线阻断、基线恢复、试验完成情况非阻断、分母语义、缺失状态、全页面交互及视觉定稿机制，形成可审计的 Phase 6 最终验收证据。

## 用户与使用场景

- 主要用户为中文母语、视觉敏感、不熟悉工程与 Agent 术语的资深临床试验医学经理。
- 用户只需指定 B 类报告、适应症与 HTML 输出；系统自行完成资料收集、证据判断、报告构建和验收。
- 报告正文不得出现提示词、程序状态、日志标签、测试标签或无必要英文；阻断说明只告诉用户缺什么、已尝试什么、需要协助什么。

## 需求

- 建立 `b-pnh` 正向输入包，并以全新空项目执行真实 PNH B 报告；不得复用旧 manifest 或旧站点冒充本次结果。
- 建立三个逐文件锁定摘要、互不复用输入包的 D70 案例：基线缺失阻断、补齐基线恢复、完成/处置全部未公开但仍可交付。
- 任一核心试验任一可比较组缺少样本量、年龄、性别或适应症严重程度锚点时，B 必须停止生成；补齐后同一项目可形成新快照。
- 完成/处置字段未公开不阻断；部分公开时图只绘公开值，表格和矩阵保留全部预定义状态，未公开不得当作 0。
- 均值/中位数、分箱、量表、方向、时间点不兼容时自动拆分小多图；治疗组和对照组始终并列。
- 分母角色、完成与退出、PD 人数与事件数、非互斥原因不得错误合并、相减或复算。
- 当次运行必须绑定 `run_id`、`snapshot_id`、`manifest_sha256`、case digest、逐文件摘要和不早于运行起点的文件时间。
- 所有 B 页面、产品页和试验页在 Chromium 与 WebKit 的 768/1024/1440 三档视口可读、可筛选、可下钻、可恢复网址状态，无整页横向拖动依赖。
- 交付前视觉定稿机制必须检查中文、字号、字体、段落与卡片间距、配色、阴影、动效、图表、表格、抽屉和跨页交互一致性；数据图先于完整表格。
- 三个指定视觉审阅路线先做真实连通性测试，再以医学经理角色独立试用；不得静默替换失败路线。
- 不做安全性测试，不发布 Phase 6，不启动 Phase 7。
