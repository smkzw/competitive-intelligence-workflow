# Task 10.4 产品需求

## 目标

形成一份机器可验证的旧工程迁移最终处置表，使每个获准保留的资产都能追溯来源、摘要、转换、脱敏和新位置，同时用明确的聚合排除项证明旧实现与敏感运行状态不会进入新包。

## 验收标准

1. 每条记录均含旧路径、realpath、类型、SHA-256、来源/许可、保留原因、新路径、转换、脱敏、验证证据和最终处置。
2. 保留集合只覆盖批准规格、D01–D70 决策上下文、项目内化的两类设计合同、核验 Logo、授权 fixture 和回归断言；不得暗示旧代码或旧事实库已被复用。
3. 旧代码/schema/模板/QC、全局事实库、会话/缓存/明文凭据、绝对路径与兼容包装器全部有 `not_migrated` 处置。
4. `migrated` 项的新仓目标必须存在、位于仓内且摘要与记录相符；集合/转换项必须绑定可重算证据。
5. 清单不得把旧根、全局 Skill 或本机绝对路径变成运行依赖。
6. 文档清楚区分“清单闭环”和后续 Task 10.5/10.8 的真实盘点、切换与删除。

## 非目标

- 不删除、移动或修改旧根中的任何文件。
- 不运行真实 cutover inventory/apply。
- 不冻结 RC，不关闭最终 release case。
- 不重新引入 PDF、HTML-PPT 或 PPTX 首版范围。
