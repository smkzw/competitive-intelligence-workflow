# Task 8.7 设计

## 边界

PPT Master 是可编辑 PPTX 的必经生成器；HTML-PPT、原生 PDF 和网页门户不能充当替代路径。作业控制层只消费当前锁定报告快照和既有 PPTX 格式合同，不改变医学事实、声明、coverage 集或设计母版。

## 决策

1. 以 `(project_id, report, snapshot_id)` 作为作业范围身份，并把快照摘要、声明快照、证据快照和 coverage 集摘要写入锁定记录。
2. 以九个固定阶段构成单一有序链；阶段提交和收据提交是同一个持久化边界，恢复指针只从最新已提交收据导出。
3. 以全局 `ppt_master_global` 比较并设置锁保证所有 A/B/C 作业严格串行；租约过期只能按作业身份回收。
4. 恢复前同时核对作业身份、合同版本、收据链、前置产物摘要和租约时间；任何失败都在新阶段副作用前关闭。
5. 生成器只能把作业推进到“待独立验收”；`accepted` 由独立验收者产生，不能由生成器自签。

## 产物分工

- 类型化作业/收据/快照模型和 JSON Schema：由 Task 8.7 的合同实现负责。
- 恢复指针、前置产物校验及过期/错序/跨报告拒绝：由 Task 8.7 的恢复实现负责。
- 本执行项补充：架构合同、中文操作指引、正负测试向量和 Trellis 验收记录。

权威补充合同：`docs/architecture/format-contracts/pptx-master-job.yaml`。
