# Task 6.9 技术设计

## 架构

新增 B 门户专用渲染适配器，复用已有静态门户壳、离线 ECharts、筛选网址状态和数据依据面板。模板只消费 Task 6.1–6.8 的不可变视图；业务定义、可比性、分母和缺失状态不在 Jinja 或浏览器脚本中重新计算。

数据流：锁定 B 报告快照 → B 门户数据合同 → 各已验收视图状态 → 页面投影 → Jinja 模板 → 静态站点 → 产物清单与浏览器验收。

## 文件边界

- `src/ci_workflow/renderers/portal/report_b.py`：B 门户输入、关系闭合、页面投影、确定性构建与清单。
- `src/ci_workflow/renderers/portal/templates/b/`：共享壳、宏、目录页面和产品/试验档案模板。
- `src/ci_workflow/renderers/portal/assets/report-b.js`：筛选、图表、下钻和网址联动；只消费内嵌只读数据。
- `src/ci_workflow/renderers/portal/assets/report-b.css`：B 页面布局与响应式视觉层；共享品牌 token 继续来自项目设计合同。
- `tests/integration/reports/test_b_report_portal.py`、`tests/browser/test_b_portal.py`：确定性与真实浏览器验收。

## 页面装配

- 页面目录以 `src/ci_workflow/reports/common/page-catalogs/B.yaml` 为唯一静态路由来源。
- 首页提取常用主要终点、关键安全性、疗效—安全性矩阵、基线可比性和完成情况概览；不展示工作流状态或制作说明。
- 疗效、纵向、安全性、矩阵、基线与处置页面分别消费对应强类型视图；先图后表，并以稳定事实行标识联动数据依据。
- 产品/试验档案以稳定安全路径片段生成独立页面；所有档案均从目录页和相关数据点可达。
- 没有可绘制值时使用准确披露状态视图，不渲染空坐标轴。

## 响应式与视觉

- 采用 CSS Grid/Flex 和原生渐进增强；不引入新框架。
- 1440/1280 视口采用主内容与轻量筛选栏；1024 自动收纳筛选；768 使用可展开筛选和单列卡片，但主图仍完整适配容器。
- 安全性热图与其他矩阵按可见维度自动调整单元格、标签换行和小多图；默认不依赖整页横向滚动。
- 图表使用直接标签、轻网格线、单一主强调、对照中性灰和结论注释；完整数据留在下方语义表。
- 动效限定为 160–260ms 的淡入、位移和抽屉开合；`prefers-reduced-motion` 下关闭非必要动画。

## 失败关闭

- 页面目录、视图行、产品/试验关系、证据定位或清单绑定不闭合时拒绝构建。
- 任何模板占位符、工程标签、远程资源、重复稳定行或未知路线均阻断验收。
- 浏览器测试不仅检查路由可达，还检查实际图表尺寸、默认首屏、整页溢出、表格可读、筛选同步、数据依据、键盘和控制台。

## 外部调研转译

- 借鉴 McKinsey 公开年度图表的“一个图回答一个问题、直接标注重点、少装饰”方式；只转译信息设计原则。
- ECharts 采用现有离线包的 dataset、缩放、提示、ARIA 和响应式能力。
- 表格使用 W3C WAI 推荐的 `caption`、`thead`、`th scope`；图表紧邻文本说明与完整表。
- 跨页面动效仅作渐进增强，不作为导航或理解的必要条件。
