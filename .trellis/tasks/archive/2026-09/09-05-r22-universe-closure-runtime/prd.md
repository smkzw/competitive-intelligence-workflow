# R2.2 竞品宇宙闭包运行态

## Goal

把现有宇宙闭包模型接入自主研究提交与产品运行，建立逐路线/逐扩展回执、收敛与独立上下文门，禁止 Top-N 或网络错误伪装闭包。

## Requirements

- 现有 `UniverseClosureReceipt` 仅为历史实现输入；逐字段核对 v1.3 后再复用，不能因
  schema 能校验就视为真实闭包。
- 全球与中国必查路线、别名/靶点/企业/试验四类反向扩展必须分别记录类型化尝试、
  结果分类、发现实体集合、来源绑定和输入摘要；固定 Top-N 或单轮零新增不得闭包。
- `network_error`、`parser_error`、访问受限、真实未发现和不适用保持不同语义。
  网络/解析失败必须进入恢复路线，不能被 `closed=true` 或空集合覆盖。
- 候选、纳入、排除、待审实体必须可追溯；排除要有本体规则及证据，边界项目必须
  有独立审查回执，实体别名合并不能丢失原始名称和来源。
- 收敛必须基于至少两条独立扩展策略及最后连续零新增的版本化规则；拥挤适应症
  初搜少量、新增实体、异常数量和历史集合变化都触发复核。
- 独立闭包审阅者不得复用生产上下文、身份或会话；缺独立上下文时保持阻断。
- 闭包回执必须与提交的 research-package、项目、适应症、数据截止、来源策略版本
  和实际实体字节摘要绑定，不能跨项目、跨快照或篡改复用。
- 产品运行在 universe 节点消费上述回执；未闭包时不进入 gate/snapshot/render，
  但要生成可恢复工作状态和非技术中文说明。

## Acceptance Criteria

- [ ] 全球/中国路线与四类扩展任一缺失、重复、未绑定来源或输入摘要漂移均失败。
- [ ] 网络/解析失败不会被当作“真实无竞品”；恢复后只重排受影响闭包节点及下游。
- [ ] 空宇宙可保存审计事实，但不能进入报告门；不生成空报告或伪完整门户。
- [ ] 初搜少量但后续扩展新增实体时不得提前收敛；仅满足版本化连续零新增规则后
  才能申请独立复核。
- [ ] 同上下文、自审、错误项目/适应症/截止日、实体摘要漂移和手写闭包均失败。
- [ ] A/B/C 单报告和多报告使用同一竞品宇宙身份；报告专属筛选不能倒写或截断
  项目级全量宇宙。
- [ ] 聚焦、integration、strict mypy/Ruff、全仓 gate、bundle/fresh-install 均通过；
  独立 worker 审阅后由 Codex 写 checkpoint，不宣称真实八适应症闭包已完成。

## Notes

- 首版仍为 HTML-only；本任务不实现门户视觉、PDF/PPT、定时监测或真实药智登录。
- 不修改 sealed Task 10.3–10.5，不触碰其他工程，不清理科学证据或会话状态。
