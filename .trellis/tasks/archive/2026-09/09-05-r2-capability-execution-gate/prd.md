# R2 核心能力矩阵持久化与选择性执行门

## Goal

让每次项目运行都重新执行核心能力预检，保存一份可核验的当前能力矩阵，并在
缺少必需能力时仅阻断依赖它的研究或 HTML 交付；药智网可选登录路线失败不得
阻断核心研究。

## Requirements

- 项目运行不得复用历史 preflight 结论；每次新运行或恢复均按当前宿主能力重检。
- 当前矩阵保存到项目内固定相对位置，内容符合既有 capability-matrix v1.0 合同，
  使用原子替换，并拒绝软链接或非普通文件目标。
- 运行入口允许宿主或测试显式注入 `CapabilityProbe` 与宿主身份；生产默认使用
  `RuntimeCapabilityProbe`，不得通过隐式测试环境绕过预检。
- 任一报告的研究必需能力缺失时，不启动该报告的研究、分析、快照或交付节点。
- 仅 HTML 浏览器验收能力缺失时，研究仍可进行，但不得把受影响 HTML 交付标为完成。
- 仅药智可选 `login_browser` 缺失时，保留中文恢复指引并继续核心流程。
- 阻断必须是可恢复、可审计的明确运行结局，不得伪装成证据不足、技术失败或
  “正在采集”。
- 不新增状态数据库、后台监测、账号中心、Cookie 导出或浏览器自动续登。

## Acceptance Criteria

- [ ] 独立上下文、公共网络等研究能力缺失时，运行在 preflight 后停止，后续研究
  节点无完成事件，运行清单和中文状态准确说明能力阻断。
- [ ] `browser_validation` 单独缺失时，研究可继续；HTML 交付不能完成，且矩阵准确
  指向受影响的报告/格式。
- [ ] 药智登录能力单独缺失时，矩阵 `overall_state=ready`，核心研究不被阻断。
- [ ] `capabilities/preflight.json` 可解析、与当前运行所用矩阵逐字节语义一致；软链接
  与非普通文件目标失败关闭且不被替换。
- [ ] 同一项目恢复时 capability probe 会再次调用；能力恢复后只重启受影响的下游。
- [ ] 现有 capability、项目运行、宿主合同和全仓质量门保持通过。

## Notes

本任务只闭合运行门。真实药智登录检测、浏览器受限页诊断和 R2.2 竞品宇宙闭包
仍是后续切片。
