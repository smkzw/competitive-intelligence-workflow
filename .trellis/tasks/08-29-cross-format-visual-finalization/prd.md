# 跨格式定稿前视觉策划与审阅闭环

## 目标

让每份报告在成为正式 HTML、PDF、HTML-PPT 或 PPTX 前，先经历可追溯的视觉策划、真实渲染、美化修订和独立审阅，使资深医学经理无需学习系统即可快速看懂比较结论并顺畅下钻。

## 用户结果

- 用户看到的是中文临床试验工作语境中的标题、提示和交互，不看到提示词、程序状态、后端字段或中英混杂标签。
- 首屏先回答最重要的医学比较问题；详情页保持图在前、完整表在后，信息多但不拥挤。
- 字体、字号、字重、段落、间距、色彩、阴影、按钮、卡片、弹层、图表、表格和下钻行为在同一报告内一致。
- 交互动效帮助理解状态变化，不制造等待；减少动态效果偏好下仍完整可用。
- 文件存在、测试通过或没有横向溢出都不能单独代表视觉完成。

## 范围

- 四条格式轨各自建立视觉策划书、候选产物、真实渲染证据、最多三轮美化记录和独立审阅结论。
- 视觉策划只决定信息层级和表现形式，不修改锁定事实、口径、证据、分母或科学结论。
- 站点式 HTML 检查多视口、真实交互、键盘、弹层、下钻和图表—表格同步；PDF、HTML-PPT、PPTX 按各自项目设计轨检查。
- 本任务建立机制和合同；Phase 8 再用该机制生成并验收正式 PDF、HTML-PPT 和 PPTX。

## 完成标准

- [ ] 项目内新增明确的视觉策划 Skill，并与生成、视觉验收 Skill 分责。
- [ ] 格式节点在生成前必须取得与报告快照、格式和设计合同绑定的视觉策划书。
- [ ] 从候选产物到放行必须记录真实渲染、中文文案、信息层级、图表、表格、交互与格式专属检查。
- [ ] 美化回环最多三轮；仍失败时拆页、降低图形复杂度或阻断，不带已知缺陷交付。
- [ ] 独立审阅者不能与生成者相同，且不能复用旧截图或旧产物结论。
- [ ] 确定性负例能拒绝缺策划书、缺真实渲染、缺独立审阅、生成者自签和事实摘要漂移。
