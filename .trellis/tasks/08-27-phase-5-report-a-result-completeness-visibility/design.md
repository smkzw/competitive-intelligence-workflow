# 设计

## 根因链

当前 fresh 研究包由宿主研究步骤写入，`FreshAResearchContent` 只检查每个结果承载产品存在治疗组/对照组的任一疗效数值及 TEAE/SAE 任一数值。它不核对嵌入来源的结果模块是否被完整投影。因此“最小门槛通过”被误当成“来源结果完整”，登记中的其余终点和逐事件 AE 在进入渲染器前已经丢失。前端只能忠实展示这个不完整输入。

页面问题是独立根因：安全热图用“安全维度为行、产品为列”的无限横向网格，列宽下限与 38 个产品相乘，必然横向溢出；不是浏览器偶发现象。

## 修复结构

### 来源结果完整性

- 在研究包接收边界增加 ClinicalTrials.gov 结果模块覆盖审计。审计只解析包内已经捕获并锁定的 JSON，不联网，不改写来源。
- 为每个与报告试验绑定的登记来源建立可解析清单：结局指标的标题、时间窗、组别和数值；AE 组汇总；严重与其他 AE 的术语、组别、分子和分母。
- 报告事实以稳定复合键对齐来源清单。来源存在而报告缺失时失败关闭；解析不支持时单独标为“来源结构暂未支持”，不能降级成“未公开”。
- `otherNumAffected` 只代表达到登记展示口径的其他 AE 汇总，不命名为 TEAE。逐事件 `otherEvents` 进入“常见不良事件”；`seriousEvents` 进入“严重不良事件”。AESI 仅接收来源明确标注的 AESI 或预先指定术语集与来源依据。
- 详情疗效使用全量结局记录；首页通过明确摘要选择器选出常用主要终点，不删除全量数据。

### 热图可见性

- 热图转置为“产品一行 × 安全维度有限列”。第一列为产品名，后续列为当前选定的任何 TEAE、任何 SAE、AESI 与常见 AE。
- 详情页允许事件多选；列数过多时优先以事件分组/分页或纵向分面呈现，而不是恢复产品横向长表。
- 首页使用同一数据与同一转置组件，容器限定可用高度并提供纵向滚动；不做 Top N。
- 1280px 下第一列和数据列以 `minmax(0, ...)` 分配，矩阵自身 `scrollWidth <= clientWidth + 1`。

## 数据与验收边界

- 研究内容摘要、独立科学复核摘要、事实与声明引用随数据变更重算，不手工改摘要绕过校验。
- 既有 65 个锁定来源作为本次特应性皮炎纵切的真源；若这些来源仍不足覆盖某产品，保留真实未公开状态，不补猜测。
- Codex 负责最终源—行抽查和真实浏览器验收；执行者报告与既有截图不作为完成证据。
