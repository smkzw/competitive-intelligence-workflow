# Task 9.2 技术设计

## 真源与版本

刷新服务只读取已登记项目合同版本、已锁定快照、来源版本/回执、缺口与候选记录。扩大截止日通过现有项目合同追加新版本；不得更新父行。刷新结果用新的内容摘要和版本关系登记。

## 影响图

`graph/impact.py` 提供确定性反向依赖：来源/事实 → 声明 → 报告页面 → 选定格式。输入为稳定 ID 与依赖边，输出为排序稳定、去重的影响集合和复用集合。调用方不得自行扩大或缩小声明集合。

`graph/definitions/refresh.py` 只定义刷新节点和分支：读取父版本、筛选新适格候选、重评事实/声明、重算受影响门槛、局部重建、质控、建立新版本；重大合同变化进入“需要重新建立基线”，不得伪装成局部刷新。

## 刷新服务

`application/refresh_service.py`：

1. 验证新截止日晚于父截止日，追加子合同版本。
2. 按 `first_disclosed_at` 而不是获取时间筛选新适格候选。
3. 结合缺口与变化类型形成待重评对象，不重评仍不适格或已接受且未变化的来源。
4. 调用影响图得到受影响声明/页面/格式；HTML 为首版唯一必选格式。
5. 生成新的不可变快照与追加式重建回执，保留父版本可读。

## 门槛收紧

复用 `gates.coverage` 的覆盖偏序、变化单元和受影响报告计算，不复制门槛规则。调用方声明的影响报告集合必须与确定性计算一致；受影响报告进入 coverage/科学质控，其他报告与格式按摘要复用。

## 恢复与幂等

刷新计划和每个重建动作使用稳定幂等键。中断重放返回同一计划、同一子版本和同一回执；不同输入复用同一键失败关闭。未完成的局部重建不能把子版本登记为已接受。
