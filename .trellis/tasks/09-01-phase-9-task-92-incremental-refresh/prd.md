# Task 9.2 需求：增量刷新与影响传播

## 目标

用户扩大数据截止日或收紧项目门槛时，系统从最近已接受版本继续工作，不重新跑完整项目，也不改写历史。只核验新适格来源或受规则变化影响的对象，并只重建受影响声明、页面与站点式 HTML。

## 用户体验

- 用户只需提出“刷新到某个截止日”或确认更严格门槛，不需要理解依赖图。
- 未变化内容直接复用；用户看到的是新版本和实际变化，不展示内部重算日志。
- 截止日后候选只有在新截止日覆盖后才可进入重评；不能提前污染旧版。
- 任何关键证据仍未达门槛时继续阻断，不生成草稿。

## 范围

- 从最近已接受证据/声明/报告快照、来源回执、缺口和截止日后候选建立刷新计划。
- 新截止日建立新项目合同版本；父合同、父快照和父报告保持只读。
- 仅重评新适格候选；记录新增、变化、撤回、修订、取代和未变化对象。
- GateSpec 收紧时只重算受影响报告、声明、页面和选定站点格式。
- 未受影响对象按摘要复用；受影响对象形成可审计重建回执。

## 不在范围

- Task 9.3 自动监测与调度。
- Task 9.4 三宿主桥接。
- PDF、HTML-PPT、PPTX 生成或导出。
- 全量再基线迁移；重大 Schema/本体/证据合同变化只识别并明确要求再基线。

## 验收

1. 扩大截止日新建合同版本，仅晋级此前因截止日不适格、现在适格的候选。
2. 父合同、父证据/声明/报告快照和旧站点版本字节不变且仍可读取。
3. GateSpec 只允许收紧；受影响报告回到覆盖/科学质控，未影响报告和格式按摘要复用。
4. 影响集合至少能落到事实、声明、页面和格式；局部重建回执追加保存。
5. 重大 Schema/本体/证据合同变化不做局部刷新，明确返回“需要重新建立基线”。
6. 指定测试、共享历史截止日与门槛覆盖回归、Ruff、mypy 通过。
