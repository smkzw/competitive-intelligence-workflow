# Task 6.2 技术设计

## 数据流

`当前指南记录 + 锁定核心试验 + 原始疗效事实` → `Task 6.1 兼容结果` → `终点依据构建` → `疗效事实行` → `单时间点/纵向/效应量视图` → `默认顺序或用户主动排序`。

## 合同边界

1. `GuidanceEvidence` 保存监管依据完整谱系，不接收界面标签代替结构化状态。
2. `EndpointBasis` 同时保存监管依据与竞品共识；默认依据由当前、适用、未废止记录及锁定核心试验确定性派生。
3. `EfficacyFactRow` 绑定 Task 6.1 的兼容桶、治疗臂/对照臂、数值、分母、来源定位和稳定行标识。
4. `build_efficacy_views` 只按事实结构选择柱状、折线或森林视图，不计算跨试验合并效应。
5. `sort_efficacy_rows` 只接受一个兼容桶；默认顺序不读取疗效值，用户排序保留未知项的明确状态并支持重置。

## 关键决策

- 复用 Pydantic、Task 6.1 的兼容模型与现有标准库排序；不引入新依赖。
- 指南族只有在终点、定义、人群及研发语境均兼容时合并；否则输出独立依据组和中文分列理由。
- 效应量森林图只展示来源直接提供的效应量与区间，不汇总、不重算。
- 视图模型保留完整事实行标识，Task 6.9 的图、表、抽屉和网址状态共同消费，避免多套数据变换。
- 所有权威构建入口重新校验 Pydantic 实例，防止 `model_copy(update=...)` 绕过构造期校验。

## 错误与恢复

- 规则、试验集合或事实行身份冲突时失败关闭，不尝试猜测合并。
- 指南记录缺少精确定位或版本信息时不能驱动默认，可作为不完整候选留给上游补证。
- 当前筛选没有可绘制值时返回结构化空状态，不生成空坐标轴或零值。

## 兼容与回滚

- 新代码仅位于 `reports/b/efficacy.py` 和对应测试；Task 6.1 合同保持向后兼容。
- 失败时可删除新模块和测试，不迁移既有数据，不影响 A 类产物。
