# Phase 3 技术边界

## 控制分层

1. `GateSpec` 只描述每份报告的关键证据单元、对象粒度、适用性谓词、允许来源/披露状态、缺失/冲突策略和阈值；不负责搜索，也不生成用户报告。
2. 覆盖评估器读取不可变事实和当前项目合同，产生版本化 `GateResult`；项目覆盖先经“只收紧”校验，再作为新合同版本参与计算。
3. 双重穷尽把来源执行回执与独立遗漏复核分开。阻断时唯一用户产物是 `blockers/<report>/<version>/{audit.json,audit.md}`。
4. `manual-inbox` 用内容摘要、标识符、元数据和标题页匹配下载请求；原文件名留在元数据，规范文件名和归档由系统完成。
5. 类型化控制图只消费明确状态、事件和守卫证据。状态转移与业务能力解耦，所有副作用使用稳定幂等键。
6. 独立科学质控位于证据规则通过与快照锁定之间；验证者可接受或否决，不能改写事实。

## 关键不变量

- 任一适用关键单元失败、关键冲突未解决或科学质控否决，都不能出现报告快照、覆盖投影、渲染任务或正式/草稿/占位文件。
- 评估输入引用 Phase 2 已闭合宇宙和研究角色集合，保存适用对象 ID 全集、输入快照摘要和集合摘要；不能接收调用方过滤后的裸列表。
- 每个证据绑定明确的试验、比较、组别、终点和时间点作用域。组别规则只能由同组事实满足，多臂总体值不能跨组覆盖。
- 非阻断字段仍须保存准确的披露状态，不能以空白或零替代。
- A/B/C 共享证据版本，不共享证据规则结果；格式状态也按报告与格式分别保存。
- 技术失败不能写成“未公开”；只有满足既定恢复和穷尽条件后才可请求用户。
- 内部代码状态与用户中文说明分层；阻断说明只写医学对象、缺失内容、已尝试范围和用户下一步。

## 规则与结果模型

- `GateUnitSpec`：稳定 ID、报告类型、关键/扩展级别、对象类型、适用性谓词、上下文字段、来源角色、披露成熟度、事实状态、作用域、缺失/冲突策略和阈值。
- `ApplicableUniverseSnapshot`：项目/证据快照、产品/试验/比较/组别集合、角色与纳排审计、`enumeration_complete` 和集合摘要。
- `GateEvidenceBinding`：规则单元、对象引用、事实版本、作用域、数值/单位/分母、披露状态和精确来源定位。
- `GateUnitResult` 与 `ReportGateResult`：逐单元决定、中文用户说明、输入/规则/合同版本和结果摘要；报告结果是全部适用阻断单元的确定性合取。
- `GateOverride`：逐字段偏序校验、父子合同版本、变更摘要、依赖与受影响报告；覆盖和重算只追加新版本。
- `GateVocabulary`：封闭来源角色、披露成熟度、事实状态、冲突处置、A 开发成熟度、A 临床结果状态和 `observation_kind`；YAML 与 schema 共同拒绝未知值。
- `GateResultKey`：报告类型 + 证据快照 + 基础规则版本 + 项目合同版本 + 适用对象集合摘要的稳定摘要；父结果永不就地覆盖。

## 确定性比较

- `result_bearing` 只由目标适应症适格试验中已接受的观察性疗效/安全数值事实推导，计划字段不能触发，调用方不能直接传布尔值。
- 覆盖比较器执行集合包含/子集、成熟度序和阻断布尔的逐字段偏序，不以单元数量或一个总分代替。
- 受影响报告由规则依赖反向索引计算；调用方即使提供声明集合，也必须与计算结果完全一致。

## 复用与选型

继续使用已锁定的 Pydantic、JSON Schema、YAML、SQLite 事件/检查点和现有内容寻址库，不引入新编排框架。批准方案已经固定确定性控制图的职责；Task 3.1 不出现新的外部依赖或架构选择，因此不重复做无收益的工具选型。

## 回滚

Phase 3 的证据规则、结果、阻断包、下载请求、控制图事件和 fixture 均为新增版本对象。失败时删除本阶段生成的测试项目和未接受版本，保留 Phase 2 accepted 数据与提交历史。
