# Phase 3 证据规则、恢复与控制图

## Goal

把第二阶段已接受的科学真源变成可执行的 A/B/C 报告证据规则和可恢复工作流：关键证据不足时绝不生成草稿或占位报告；系统穷尽自动办法后，才用简洁中文告诉用户缺什么、为何阻断、需要把什么文件放到哪里。

## Requirements

- A/B/C 使用独立、版本化的证据规则；项目只能加严，不能删除关键单元或降低阈值。
- 规则评估必须从已闭合的完整产品/试验/组别集合开始，并绑定输入集合摘要；未知、重复、漏评或未证明为空时失败关闭。
- 证据值明确试验/比较/组别作用域；总体值不得冒充分组值，未报告、未公开、未找到、技术失败、低于阈值、不适用和冲突均不得写成数值零。
- B 的试验完成/处置信息全部建模但不阻断；C 的统计细节缺失不阻断。适格核心试验或产品不能通过删除来换取通过。
- A 的成熟度和已有临床数值结果状态由已接受事实推导，不能由调用方自由降级；临床前或早期无结果项目不得被误触发。
- 自动路线和独立遗漏复核均穷尽后，仍缺关键证据时只生成证据不足说明，不生成正式、草稿或占位报告，也不创建下游快照、覆盖集、渲染任务或产物记录。
- 用户辅助下载必须给出原文链接、唯一投递目录和最小操作；用户无需改名，系统负责识别、规范命名、归档、抽取和续跑。
- 项目、报告、格式、下载和修订状态使用确定性控制图；重放不得重复发布、移动、批准或删除。
- A/B/C 共享同一不可变证据，但各自证据状态、快照和格式互不污染；一个报告或格式阻断不撤销已完成对象。
- 独立科学质控可否决快照锁定；可修复问题回到恢复，已穷尽问题进入证据阻断，均不产生报告产物。
- 用户可见文字使用中文临床试验语境，不显示代码状态、日志术语、提示词或“门/信号”等程序员表达。
- 本阶段不实施报告门户或四格式视觉，不进行安全测试。

## Acceptance Criteria

- [x] Task 3.1：A/B/C 证据规则、覆盖评估和只收紧项目覆盖全部精确测试通过。
- [x] Task 3.2：每个非空关键缺口、关键冲突和科学质控否决均满足全链路“无草稿、无下游产物”，证据不足说明中文清楚可行动。
- [x] Task 3.3：下载请求、用户原文件自动匹配/改名/归档/续跑及重下载路径通过。
- [x] Task 3.4：九类状态与全部合法/非法迁移、节点合同和重放幂等通过。
- [x] Task 3.5：报告与格式部分交付、阻断和重新打开互相隔离。
- [x] Task 3.6：真实项目和登记 fixture 均由同一默认执行器运行，产物路径和摘要真实绑定。
- [x] Task 3.7：只有独立、有效且绑定当前候选快照的科学质控接受结论才能锁定快照。
- [x] Phase 3 正式确定性命令、真实阻断项目和独立科学/控制图验收全部通过。
