# A类报告数值覆盖与安全性矩阵适配修正

## Goal

纠正 A 类正式报告中“底层结果记录很多、首页和详情比较视图却大量缺数”的数据链路与呈现问题，并使首页和安全性详情页的默认矩阵在常见桌面视野内完整、清晰、无需横向拖动。

## Requirements

- 分开量化原始公开数值、可归一数值、可横向比较数值、默认可见数值，不得再用结果总行数代替产品级覆盖。
- 追溯数值缺失最早发生层：来源未取得、来源未抽取、术语/时间窗/组别未归一、报告投影遗漏或默认筛选遮蔽。
- 英文大小写与中英文同义安全事件应归入同一展示维度；定义或观察窗不同的项目不得强行合并。
- 对确实没有公开数值的产品保留“未公开”，不得用零值或由单项 AE 反推总体 TEAE。
- 首页和安全性详情页共享一套响应式矩阵合同；默认桌面视野内不得出现横向拖动、文字裁切或依靠极小字号硬塞。
- 默认比较先呈现对医学经理最有用且覆盖最高的安全性维度；全量事件与全部产品仍可筛选查看。
- 遵守项目内康哲设计规范：浅色站点、原生中文、数值读取面不使用毛玻璃或装饰性变形。
- 搜索、证据门槛与技术诊断留在任务记录，不进入受众正文。

## Acceptance Criteria

- [ ] 形成逐产品疗效/安全性覆盖审计，能解释每个缺数属于哪一层且总数机械对账。
- [ ] `Headache / HEADACHE / 头痛`、`Nasopharyngitis / NASOPHARYNGITIS / 鼻咽炎`等经批准同义项在比较图中合并，明细仍保留原始术语和来源。
- [ ] 首页主要疗效与安全性默认视图不因术语形式差异漏掉已有数值；真实未公开仍明确显示。
- [ ] 首页及安全性详情页在 1024、1280、1440、1920 px 的 Chromium 与 WebKit 中无需横向拖动，列标题、产品名、数值均可读。
- [ ] 窄于 1024 px 时采用明确的响应式降级，不以隐藏溢出冒充通过。
- [ ] 定向数据测试、浏览器交互测试、全量回归和静态检查通过；独立医学经理视觉复核通过后才替换正式入口。
- [ ] 新正式产物不可变；旧接受产物保留到新产物验收结束，再按项目清理规则处理可再生成副本。
