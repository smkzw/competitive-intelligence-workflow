# 技术设计

## 1. 诊断边界

按五层对账：来源取得 → 事实抽取 → 临床语义归一 → 报告数据投影 → 默认可见视图。每层输出产品数、试验数、数值数和缺口原因，禁止用总行数替代覆盖率。

## 2. 数据合同

- 事实层保留原始 endpoint/term、组别、时间点/观察窗和来源锚点。
- 展示层新增最小的规范化匹配函数，只合并明确同义、大小写或中英文别名；不同定义、合并剂量、不同观察窗保持分开。
- 图形与下方表格必须从同一筛选结果生成。
- “未公开”仅表示当前证据中无确定值；技术失败与尚未取得继续在日志中分开。

## 3. 默认安全性视图

- 默认列按医学优先级和产品数值覆盖共同选择：总体 TEAE、总体 SAE，再选覆盖最高的常见 AE；同义项先合并再计算覆盖。
- 产品全量保留，但默认视图应把“有可比较结果”和“尚无量化结果”视觉分组，避免灰格淹没有效模式。
- 首页采用紧凑摘要；详情页采用完整矩阵和明细表。二者共享归一与布局函数，不维护两套逻辑。

## 4. 响应式布局

- ≥1024 px：矩阵在内容宽度内完整显示，产品列固定合理下限，事件列等分且不产生横向滚动。
- 768–1023 px：改为分块矩阵，每块最多两个安全维度，重复产品列与列头。
- <768 px：改为逐产品纵向卡片/键值网格；不得压缩成不可读五列表。
- 测试同时检查文档、图表宿主、矩阵网格、文字墨迹框和截图，不再只检查 `scrollWidth`。

## 5. 研究补齐边界

本次先修复已经存在但未归一/未投影的数值。对来源层确实缺失的总体 TEAE、关键安全性或主终点数值，形成逐产品补研清单并走原有证据入库路径；不在 JavaScript 或模板中手填外部数值。

## 6. 回滚

新报告在独立不可变目录生成。验收失败时保留当前正式入口，不覆盖旧产物；代码回滚仅限本任务变更，不触碰用户其他工作。
