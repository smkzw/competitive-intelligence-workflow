# Phase 4 共用报告视图与康哲站点式门户

## Goal

把已锁定科学快照转换为稳定、可复现、可跨格式核对的共用报告视图，再建立符合康哲设计合同的中文原生多页面门户。图、表、筛选、网址状态与证据抽屉必须消费同一事实行集，不能在展示层补造或删减数据。

## Requirements

- 规范 `coverage_set` 固定快照、页面责任、产品、试验、关键声明、图、表、证据引用和附录；各格式只能生成带结构化例外的投影。
- 行标识稳定且由科学身份确定，不随排序、筛选或格式变化。
- 同一模块的图与完整表来自同一筛选后行集；不兼容数据拆分小多图，不补造值。
- 页面注册表以 Phase 0 已冻结 A/B/C 页面目录为真源，支持全部动态产品/试验详情页，不做固定示例或 Top-N。
- 门户使用项目内冻结康哲合同、正式 Logo、多物理页、原生中文临床试验语言；不得显示流程日志、后端状态或提示词。
- 从 Task 4.2 起，凡涉及用户可见页面、交互或导出物，除确定性浏览器检查外，须让 CodeBuddy CLI `kimi-k2.6`、Pi `cms-router/minimax-m3`、Grok Build `grok-4.6` 启用视觉并分别扮演真实资深医学经理完成端到端试用；不得仅以页面显示或流程跑通判定可用。
- 本阶段不实施 A/B/C 具体完整页面、不生成 PDF/HTML-PPT/PPTX、不做安全测试。
