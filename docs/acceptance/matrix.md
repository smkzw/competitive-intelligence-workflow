# Task 10.1 首版正负基准矩阵

**适用范围：** 首个可安装版本的 A、B、C 三类竞品调研报告。本文面向医学人员、医学经理和验收人员，说明每个场景要证明什么、何时执行，以及成功或阻断应如何解释。

## 先看结论

- 首版正式交付只有**多页面站点式 HTML**。A、B、C 仍分别有首页、真实详情页、全局导航、搜索、筛选、下钻和证据定位。
- PDF、HTML-PPT、可编辑 PPTX 和 PowerPoint 确认属于后续可选能力。首版不检查、不提示、也不因这些能力缺失而阻断站点式 HTML。
- A、B、C 可以共享已核验的科学资料，但每类报告仍独立判断资料是否足够。某一类报告被阻断，不会撤销其他已满足条件报告的站点式 HTML。
- `fixtures/acceptance/catalog.yaml` 是场景的唯一机器目录；本文是给人的说明。验收人员不需要临时补写场景、截止时间或成功条件。
- 所有正向输入均为仓库内已脱敏、已核验身份的合成或既有样本。旧版失败样本只用于确认“仍然拒绝”，不能作为模板、视觉参考或事实来源。

## 结果如何解释

| 人员看到的结果 | 医学含义 | 下一步 |
|---|---|---|
| **成功交付** | 关键证据、适用范围、数据截止和页面事实均已核对；允许生成对应的站点式 HTML。 | 保存本次验收记录，进入已批准的后续责任阶段。 |
| **关键证据不足，暂不生成草稿** | 不能支持关键临床结论，不能用猜测、零值或其他试验资料填补。 | 保留阻断原因；如有资料，提交可核验的补充文件。 |
| **资料未公开** | 来源确实没有公开该字段；这不等于系统失败。非关键字段可带着“未公开”状态交付，关键字段则按关键证据不足处理。 | 查看页面中的准确披露状态，不把“未公开”改写成 0。 |
| **技术问题，尚未完成** | 网络、限流、验证码、页面变化、解析或运行环境问题，不能解释成“未公开”或“未找到”。 | 恢复环境后重试；不能用技术问题掩盖证据缺口。 |
| **等待后续责任阶段** | 场景合同已经记录，但责任尚未到首版发布阶段，例如最终恢复演练或旧根处置。 | 不写成已通过，也不提前删除或迁移资料。 |
| **本次条件不适用** | 只有明确的可选能力未被当前项目合同选择时才使用。 | 保留适用条件和合同依据；不能用它绕过必做场景。 |

“关键证据不足”和“技术问题”必须分开记录。前者保护科学结论，后者保护恢复路径；两者都不能伪装成另一类结果。

## 执行时点

| 何时执行 | 需要核对的范围 | 通过的含义 |
|---|---|---|
| 每次首版候选包或科学快照冻结前 | `full-matrix-v1`、四个历史截止场景、当前可执行的 `required-v12` 场景 | 同一脱敏项目、同一物化截止和同一输入摘要能够稳定重现 A/B/C 站点式 HTML。 |
| 发生跨日恢复或重新取得历史资料时 | 历史截止四个场景 | 重新取得资料不会改变原来的披露归属和物化截止。 |
| 最终 RC 冻结前 | 18 个 `required-v12` 场景 | 规定的科学、交互、宿主和负向回归范围已经逐项留下证据；尚未到责任阶段的项目仍保持等待。 |
| 用户明确选择后续格式时 | 只执行被选择格式的独立验收 | 后续格式单独通过或单独阻断，不追溯改变已锁定的站点式 HTML。 |

## A. 首版核心基准

| 场景（目录定位标识） | 要证明什么 | 成功时看到 | 阻断或等待时怎么处理 | 责任阶段 |
|---|---|---|---|---|
| A/B/C 首版全量站点基准（`full-matrix-v1`） | 特应性皮炎同一脱敏项目的 A、B、C 是否共用同一物化数据截止、输入摘要和科学快照边界。 | 三类报告均有站点式 HTML 首页和真实详情页；页面事实、版本、截止和输入来源一致。 | 任一关键证据或摘要不一致时不锁定对应快照；PDF、HTML-PPT、PPTX 缺失不构成阻断。 | 首版矩阵冻结 |
| 获取晚于截止、首次披露在先（`historical-cutoff-acquired-after-disclosed-before`） | 获取日期与首次披露日期是否被分别保存；晚取得的资料若在截止前已披露，能否正确归入历史快照。 | 资料可以进入历史快照；页面保留首次披露时间和获取时间的区别。 | 不得因取得晚就排除截止前已披露资料，也不得把取得日期冒充披露日期。 | 首版矩阵冻结 |
| 首次披露晚于截止（`historical-cutoff-disclosed-after-cutoff`） | 截止后的首次披露是否与当前历史快照隔离。 | 当前历史快照不纳入该资料；资料只进入后续刷新候选。 | 不得把后续资料倒灌旧快照，也不得把刷新候选说成已锁定事实。 | 首版矩阵冻结 |
| 首次披露时间未知（`historical-cutoff-unknown-first-disclosure`） | 关键来源无法确认首次披露日期时是否失败关闭。 | 不生成依赖该关键资料的草稿；保留“首次披露时间未知”的原因。 | 不得用获取日期、默认日期、0 或其他来源猜出披露时间。 | 首版矩阵冻结 |
| 跨日恢复仍冻结原截止（`historical-cutoff-cross-day-resume`） | 恢复动作跨过自然日后，是否仍使用原物化截止和原时区。 | 恢复前后截止值和时区完全一致；截止前已披露资料不被重新分类。 | 不得把恢复时钟自动变成新的截止，也不得丢失原时区偏移。 | 首版矩阵冻结 |

## B. `required-v12` 18 个场景族

下表中的 18 个场景是批准矩阵的完整集合。每个场景都必须同时出现在共享目录和 `required-v12` 场景片段中；每个场景的批准子场景也必须在其脱敏输入的 `scenario.json` 中逐项声明。缺少、重复、额外未说明或输入摘要不一致，均按失败关闭处理。

| 场景（目录定位标识） | 要证明什么 | 成功时看到 | 阻断或等待时怎么处理 | 责任阶段 |
|---|---|---|---|---|
| 全球/中国成熟度范围（`landscape-global-china-maturity`） | 全球/中国、本地/境外范围，以及成熟有结果与早期无结果项目是否分开。 | 区域、开发阶段和结果承载证据各自可追溯；早期无结果保留真实状态。 | 不能用项目数量或项目存在代替结果证据；范围或结果锚点不全时保持待审。 | 最终 RC 冻结 |
| 本体与治疗方案边界（`ontology-regimen-boundaries`） | ADC、融合蛋白、创新药与传统背景治疗、纯传统治疗、改良/重定位/固定复方是否按规则区分。 | 每个项目有可追溯的身份和谱系判断。 | 身份或谱系不足时排除或待审；不得因名称相似或结果较好而改判为创新药。 | 最终 RC 冻结 |
| 研究角色边界（`study-role-boundaries`） | 默认排除研究、支持层、特殊早期核心，以及试验研究角色与出版物角色是否分开。 | 每个纳入或排除决定都有原因、语境和来源血统。 | 不得因标题相似、已有结果或论文角色把排除研究升格为核心。 | 最终 RC 冻结 |
| C 登记与 Protocol/SAP 路径（`c-protocol-registry-paths`） | C 类登记字段足够时能否通过；关键设计缺失时能否经 Protocol/SAP 补件恢复；多条设计路径是否并列。 | 统计细节缺失但临床设计核心完整时仍可交付；多条路径显示差异、前提和权衡，不给唯一推荐。 | 临床设计核心缺失先阻断；补件需核验身份、来源和版本后再恢复。 | 最终 RC 冻结 |
| 证据与指南冲突（`evidence-guidance-conflicts`） | 论文、登记、监管、指定行业来源和指南状态发生冲突时是否逐项保留。 | 来源角色、版本、成熟度和定位均可查看；合资格来源的规则有清楚边界。 | 未解决的关键冲突保持关键证据不足，不生成草稿；不得用来源数量或“多数”掩盖冲突。 | 最终 RC 冻结 |
| 补充证据必要性（`supplement-requiredness`） | 补充材料不可得但不必要，与确为关键证据而需要用户补件的情况是否区分。 | 非关键补充材料缺失不阻断；关键材料经核验后可从原阻断版本恢复。 | 不得把所有补充材料缺失一律阻断，也不得把关键材料缺失静默降级。 | 最终 RC 冻结 |
| B 基线与 D70 边界（`b-baseline-d70`） | B 类每个核心试验组的年龄、性别和严重程度等基线是否独立完整；不兼容统计形式是否拆开。 | 各试验、各组别和各时间点保留原始语义；必要时以小图/小表并列呈现。 | 任一关键组别基线缺失先阻断；不得借用总体值、其他试验或其他组别填补。 | 最终 RC 冻结 |
| B 试验完成与处置（`b-disposition`） | 完成、退出、失访、筛败、补救治疗、禁用药和疾病进展等字段是否保留各自分母与披露状态。 | 未公开但非关键的字段以明确状态展示，完成情况页面仍可交付。 | 不得把未公开写成 0，不得把人数、事件数和非互斥原因合并计算。 | 最终 RC 冻结 |
| B 交互与格式边界（`b-interaction-cross-format`） | B 基线/完成页的图、完整表、证据抽屉、筛选和网址恢复是否指向同一事实。 | 选择条件、图表、表格和证据定位可往返恢复；首版只验收站点式 HTML。 | 不得要求 PDF、HTML-PPT、PPTX 或 PowerPoint 确认；不得让展示组件各自维护另一套数据。 | 最终 RC 冻结 |
| 技术与人工恢复（`technical-and-manual-recovery`） | 网络、限流、验证码、页面变化、解析/工具故障，及用户原文件恢复是否各自可诊断。 | 技术问题与证据不足分开；人工文件按摘要、标题和试验身份核验后可恢复，重复恢复不重复产生副作用。 | 未匹配、未核验或跨项目文件不得进入事实；恢复失败不能覆盖原阻断原因。 | 最终 RC 冻结 |
| 多报告部分交付（`multi-report-partial-delivery`） | A、B、C 共享资料时，是否仍保持各自的关键证据判断和站点式 HTML 交付状态。 | 已满足条件的报告继续交付；一个报告阻断不撤销其他报告。 | 不得把 PDF、HTML-PPT、PPTX 缺失作为首版部分交付前提，也不得让一类报告替另一类报告背书。 | 最终 RC 冻结 |
| 状态重放与显式重开（`state-replay-and-reopen`） | 非法动作是否拒绝；重复恢复是否不重复产生副作用；终态阻断是否必须显式重开。 | 非法动作有明确拒绝记录；重复检查至多执行一次；重开后重新核对目标和版本。 | 不得跳过已声明步骤、从终态自动续跑或以重复动作伪造完成。 | 最终 RC 冻结 |
| 康哲大型项目站点运行（`kangzhe-and-large-project-runtime`） | Logo、导航、搜索、全量静态页、产品/试验详情、筛选和证据下钻在大型项目上是否完整可用。 | 验收覆盖全部页面和详情，不只首页；站点式 HTML 在目标桌面宽度可浏览。 | 只验首页或少量样例不能算通过；不把固定幻灯片页型、演讲者稿或逐页规则叠加到首版站点。 | 最终 RC 冻结 |
| 三宿主站点冒烟（`host-smoke-v1`） | Codex、Hermes、OMP 是否从各自安装入口执行同一 HTML 案例，并保持语义一致。 | 三个宿主的运行、会话、项目和验收记录彼此独立，失败分类和 HTML 结果一致。 | 不能用适配器自报、同进程替身或旧记录代替真实入口；可选格式缺失不阻断首版 HTML。 | 最终 RC 冻结 |
| 可选适配器恢复（`optional-adapter-recovery`） | 只有项目合同主动选择可选适配器时，才验证私有缓存删除后的恢复。 | 未选择时明确记为条件不适用；选择后只能由规范事件和检查点恢复。 | 不得用空泛“不适用”绕过合同依据，也不得让可选适配器接纳事实、改变门槛或覆盖默认执行器。 | 条件扩展 E1 |
| 最终恢复演练（`recovery-rehearsal`） | 最终版本恢复包能否在隔离位置安装、恢复、刷新并重建代表性站点式 HTML。 | 恢复完成前保持等待；通过时所有输入、快照和事件来源一致。 | 不得复用旧候选包、旧项目或旧记录冒充通过；不得在真实恢复记录产生前写成已完成。 | 后续恢复责任阶段 |
| 旧工程无残留（`legacy-absence`） | 获得明确授权后，旧入口、影子副本、链接、消费者引用、缓存和备份登记是否按精确清单全部核对。 | 完成最终恢复、迁移清单和独立核验后，清单逐项无残留。 | 授权或清单未闭合时保持等待；不得提前删除、扩大删除范围或写成无残留。 | 后续切换授权阶段 |
| 旧版六类负向回归（`legacy-negative-regressions`） | 旧版负向回归的六个批准子场景——旧 CSU A、旧 PNH B、旧 AD A、样式崩塌、伪截图、假通过质控——是否仍被确定性拒绝。 | 六个失败子案例都保留失败原因；没有一个成为正向模板或视觉参考。 | 文件存在、截图存在、项目数量或旧质控通过都不能覆盖科学、样式或来源锚定缺陷。 | 最终 RC 冻结 |

## 验收人员的最小检查顺序

1. 先确认场景来自首版目录，输入来自已脱敏且身份已核验的仓库样本；不要临时替换输入或截止时间。
2. 先看适应症、报告类型、时区、物化数据截止和场景责任阶段，再看页面事实。截止后的资料不能反向改写历史快照。
3. 对每个场景分别记录“成功交付”“关键证据不足”“技术问题”“资料未公开”或“等待后续责任阶段”。不要把这些词互换。
4. 若关键证据不足，确认没有生成草稿、空壳页面或看似完整的替代数字；若只是非关键字段未公开，确认页面保留了明确的未公开状态。
5. 对站点式 HTML 检查首页、真实详情页、搜索、筛选、网址恢复、图表/表格和证据定位；不要用文件存在或首页显示代替完整浏览。
6. 只有在对应后续责任阶段真正执行并留下独立记录后，才可关闭最终恢复、旧根处置或条件扩展场景。

## 后续格式的恢复边界

PDF、HTML-PPT 和 PPTX 的既有合同、实现和暂停检查点继续保留，但它们不属于首版站点式 HTML 的阻断条件。将来用户明确选择某一种格式时，应从该格式已有检查点继续，使用同一已锁定的科学快照和覆盖集合，单独记录该格式的成功或阻断；不得为了补齐后续格式而修改本矩阵的首版 HTML 结论。
