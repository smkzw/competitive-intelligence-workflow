# PPT Master 作业操作指引（Task 8.7）

本指引用于从同一份锁定报告快照启动、暂停、恢复和交接 A/B/C 可编辑 PPTX 作业。它约束的是作业控制，不是 PPTX 视觉终验；Task 8.7 通过不等于 PPTX 已生成或已被 PowerPoint 接受。

## 一、开始前确认

1. 只选择一个报告：A、B 或 C。
2. 指定本次报告的**当前锁定快照**，并保存快照清单中的 `snapshot_id`、`snapshot_sha256`、声明快照、证据快照和 `coverage_set_id`。
3. 确认 PPTX 设计合同和作业合同版本与当前运行一致。
4. 确认 PPT Master 可用；缺失时只阻断 PPTX，不得改用 HTML、PDF、网页截图或图片页 PPTX。
5. 确认没有其他 PPT Master 作业正在占用全局锁。A、B、C 即使快照不同，也必须严格串行。

作业身份必须能重算为：

```text
(project_id, report, snapshot_id) -> job_id
```

任何一个身份字段或快照摘要发生变化，都应创建新作业，而不是修改旧作业。

## 二、启动一份新作业

### 1. 创建作业

建立作业后，状态应为“已创建”。此时不能直接开始逐页生成；必须先锁定快照。

```json
{
  "job_id": "由运行器生成的唯一标识",
  "project_id": "项目标识",
  "report": "A 或 B 或 C",
  "report_version": "报告版本",
  "snapshot_id": "当前报告快照标识",
  "snapshot_sha256": "64 位小写 SHA-256",
  "contract_version": "8.7",
  "state": "created"
}
```

### 2. 锁定快照

锁定动作要同时记录报告身份、快照摘要、声明/证据快照和覆盖集合。锁定之后，不得改写这些字段，也不得用文件修改时间代替摘要。

锁定成功后才可进入第一阶段。锁定失败时不要产生 PPTX 中间文件；先修复输入或重新创建作业。

### 3. 按固定顺序执行

每次只运行一个阶段。每个成功阶段都必须先写入一份阶段收据，再把恢复指针推进到下一阶段：

| 顺序 | 阶段 | 通过后的下一步 |
|---:|---|---|
| 1 | 初始化 | 内容策略与设计锁定 |
| 2 | 内容策略与设计锁定 | 逐页 SVG |
| 3 | 逐页 SVG | 质量检查 |
| 4 | 质量检查 | 备注 |
| 5 | 备注 | 收尾处理 |
| 6 | 收尾处理 | 原生导出 |
| 7 | 原生导出 | 可编辑性核验 |
| 8 | 可编辑性核验 | 原分辨率逐页视觉检查 |
| 9 | 原分辨率逐页视觉检查 | 交给独立验收 |

收据至少要能回答：哪个作业、哪个报告、哪个快照、哪一阶段、哪一次尝试、输入摘要是什么、输出摘要是什么、前一份收据是什么、何时提交、结果是什么。没有收据的阶段不能被恢复，也不能被算作已完成。

## 三、暂停

只在阶段边界暂停。暂停前先提交当前已经完成的阶段收据，再将状态改为“已暂停”；不要在 PPT Master 正写文件时复制目录或手工标记进度。

暂停记录应保留：

- `job_id` 与锁定快照身份；
- 最后一份已提交收据及其摘要；
- `next_stage` 恢复指针；
- 未完成阶段；
- 失败原因（如有）；
- 作业租约的 `expires_at`。

暂停不是“可以并行继续”。暂停边界提交收据后，运行锁可按合同释放，但同一作业仍保留快照身份和恢复租约；任何新作业必须等运行锁释放后再启动，恢复时重新取得全局锁。不得让两个阶段同时运行。

## 四、恢复

恢复只接受“已暂停”或“阶段失败”的作业，并且必须使用原 `job_id` 和原锁定快照。恢复前按下列顺序检查：

1. 作业存在且没有进入终态；
2. 请求中的报告、版本、快照标识和快照摘要与锁定记录完全一致；
3. 合同版本一致；
4. 最新收据摘要与恢复指针一致；
5. 所有前置收据均为已提交状态；
6. 所有前置产物仍存在，且摘要与收据一致；
7. 作业租约存在且尚未过期；
8. 没有其他活动作业或阶段占用全局锁。

恢复从 `next_stage` 开始，不重放已经提交的阶段，也不根据目录排序、文件时间或“看起来已经有文件”推断进度。

## 五、失败、重试和拒绝

阶段失败时保留失败收据和原因。只有失败阶段可以以新的 `attempt` 重试；前置成功收据不可被覆盖。重试仍必须匹配同一作业和同一快照。

遇到下列情况，系统应在副作用前拒绝，并保留可审计原因：

| 情况 | 用户动作 |
|---|---|
| 快照摘要不一致 | 停止恢复；回到原快照，或创建新作业 |
| 报告 A/B/C 不一致 | 不要合并文件；按正确报告重新创建作业 |
| 收据过期 | 不强行续用旧收据；按系统允许的流程重新建立有效作业 |
| 阶段顺序跳跃 | 回到恢复指针；补齐缺失的前置阶段 |
| 前置产物缺失或摘要变化 | 不复制旧产物；重新执行受影响作业 |
| 全局锁冲突 | 等待当前作业在边界释放，或由运行器处理明确的过期锁 |
| 作业已接受、拒绝或取消 | 不重新打开终态作业；创建新作业并保留旧记录 |

禁止用“只改时间”“复用旧收据”“复制另一报告的产物”“把失败目录改名为通过”绕过拒绝。

## 六、交接与验收

九个阶段全部提交后，作业只能进入“待独立验收”，不能由生成器自行写成“已接受”。交给独立验收者的最小证据包包括：

- 当前作业清单和锁定快照摘要；
- 九阶段收据链；
- 每阶段输入/输出摘要；
- PPTX OOXML 可编辑性核验结果；
- 原生 PowerPoint 渲染结果；
- 原分辨率逐页视觉检查结果；
- 备注、目录和覆盖集合核对结果。

Task 8.7 只冻结并验证作业合同、恢复和拒绝语义。可编辑 PPTX 的完整生成属于后续 Task 8.8；OOXML、PowerPoint 和逐页视觉终验属于 Task 8.9；四格式覆盖属于 Task 8.10。

## 七、给报告使用者的简短说明

- **已创建**：已登记作业，尚未锁定报告快照。
- **已锁定**：输入固定，可以按顺序执行。
- **运行中**：当前只有一个阶段在执行。
- **已暂停**：已保存最后一份收据，可在有效期内从下一阶段继续。
- **阶段失败**：失败原因已保存，只能按合同重试该阶段。
- **待独立验收**：生成链已结束，尚未代表验收通过。
- **已接受/已拒绝/已取消**：终态不可原地重开。

看到“快照不一致、收据过期、阶段顺序错误或锁冲突”时，不要继续点击恢复；保留提示和作业标识，交给运行器或验收负责人处理。
