# ADR 0004：结构化医学内容与确定性报告渲染边界

- 状态：已采用
- 日期：2026-08-11
- 适用范围：A/B/C 门户、原生 PDF、HTML-PPT、PPT Master PPTX
- 不改变：v1.2 科学门槛、康哲设计合同、四格式独立验收和 PPT Master 必经流程

## 1. 决定

宿主 Agent 和内部医学能力只生成、修订并审查类型化医学内容，不直接自由编写最终 HTML、CSS、JavaScript、PDF 绘图指令或 PPTX 页面。

正式产物由应用持有的确定性投影和渲染器生成：

```text
证据与声明快照
  -> A/B/C 类型化 ReportViewModel
  -> 规范 coverage_set
  -> 各格式 coverage_projection
  -> 门户 / 原生 PDF / HTML-PPT / PPT Master 来源包
  -> 当前产物的确定性、内容覆盖和真实渲染验收
```

康哲 `design_specs` 是构建渲染组件、页面壳层、图表主题、幻灯片母版和验证器的设计权威，不是每次报告生成时交给模型自由解释的长提示词。实施者和独立视觉验证者可以按 `ROUTER -> core -> one track` 读取合同；日常报告节点只提交符合 schema 的内容、图表数据、筛选维度、证据锚点和结构化格式例外。

## 2. 职责边界

### 2.1 Agent 与医学能力负责

- 竞品、产品、试验、终点、时间点、人群、治疗组和对照组的身份解析；
- 原子事实、声明、冲突、缺失状态、证据定位和适用比较组；
- A/B/C 页面责任所需的结构化内容计划；
- 图表种类的语义意图和可选维度，不指定任意像素、颜色或 DOM；
- 中文原生标题、标签、提示和面向资深医学人员的简洁解释；
- 对科学或内容异常提出否决，不以补写空白页面掩盖门槛失败。

### 2.2 应用渲染层负责

- 站点页眉、Logo、导航、全局搜索、筛选器、证据抽屉和响应式布局；
- 柱状图、折线图、森林图、热图、气泡图、雷达图及其下方事实表的统一 row ID；
- 康哲颜色、字体、字号、留白、图表主题、页面母版、页码和可见层级；
- HTML-PPT 翻页、`#/N`、全屏、讲者窗口、逐字稿、计时和双窗同步；
- 原生 PDF 的段落、续表、页眉页脚、书签和分页；
- PPT Master 所需来源包、逐页内容计划、确认中断和阶段收据；
- 将同一 `coverage_set` 投影为四种格式，拒绝静默删值或引入快照外事实。

### 2.3 独立验证层负责

- 读取当前 run、当前不可变快照和逐产物摘要，不接受旧截图或旧收据；
- 对完整物理页面、交互、图表—表格同步、中文标签和真实用户视口逐项验收；
- 对 HTML-PPT 讲者功能、PPTX 可编辑性、PDF 原生结构分别验收；
- 只能接受或否决，不能在验收时静默改写最终产物。

## 3. 为什么不能让 Agent 自由生成最终页面

2026-08-11 对最新 `design_specs` 的 S1 实产物只读复核提供了直接反例：

1. 流式路线读完约 1,500 行设计规则和来源后，写文件工具连续四次参数序列化失败，目录仍为空；生成进程却以退出码 0 结束。仅检查进程成功会把“零产物”误判为完成。
2. HTML-PPT 的 8 张幻灯片可打开、无滚动、基本视觉可读，但源码没有讲者窗口；`S` 无效，`N` 被占作下一页，逐字稿只有 38–144 字，页面存在 10–12px 可见文字。它通过了生成者自述和基础截图，却不符合 v1.2 与康哲合同。
3. 同一 HTML-PPT 把运营主责分别写成“5/9”和“1/3/5/6/7/9 六个环节”；RACI 九行可重算得到六个运营 A。生成日志仍以 `EXIT:0` 自述完成，证明视觉通过和功能存在也不能替代跨页医学/业务语义一致性。
4. `design_specs/local_map.md` 仍保留已经废止的“双全文同步”说明，与当前单一 `design_specs` 架构冲突。即使结构测试为绿，也不能证明设计合同已闭合。

这些失败分别属于工具故障、功能合同遗漏和规范内部矛盾，不能归为“未找到内容”，也不能靠换模型或增加提示词作为长期方案。正确的系统边界是：模型形成结构化医学真值，确定性渲染器实现用户界面，真实运行验证器拥有完成判定。

## 4. 机器合同

Phase 0–4 必须冻结并逐步实现以下合同：

1. `ReportViewModel` 只能引用已锁定的声明、事实和证据 ID；模板和渲染器不能创建新医学数字或结论。
2. 页面注册表声明每个报告的全部物理页面、必需模块、图表、表格、筛选维度和下钻目标；缺任何责任即失败。
3. 每个图表数据点与表格行共享稳定 row ID，筛选、排序、证据抽屉和 URL 状态同步。
4. 所有可见数字、比例、计数、列表长度、排序标签和定量结论必须携带稳定 claim/fact/row ID，并从同一结构化事实集确定性计算；首页、详情页、图、表、逐字稿及四格式的重算结果必须一致。任一孤立数字、手写汇总或跨页不一致均禁止渲染和接受。
5. 渲染器输入必须通过 Pydantic/JSON Schema；缺字段、未知字段、错误状态或未解释 coverage 差异均不得生成正式产物。
6. 模板只消费 view model；测试扫描禁止检索网络、读取旧工程、调用科学分析或硬编码 fixture 数值。
7. 用户可见文案由版本化中文词汇表提供；程序状态、日志标签、提示词片段和无必要英文不得进入报告。
8. “进程退出 0”不是完成条件。必须同时存在当前产物、摘要匹配、责任覆盖、跨页语义一致性、真实渲染锚点和独立接受记录。
9. HTML-PPT 运行时由应用固定，不允许报告生成节点重新实现或删减讲者功能；PPTX 仍必须由 PPT Master 串行生成，不能由确定性渲染器伪造。

## 5. 对实施计划的影响

本决定不新增阶段，也不扩大安全测试：

- Task 0.4–0.5 冻结公共能力、页面/格式 schema 和唯一 CLI；
- Phase 4 建立公共 `ReportViewModel`、页面注册表、康哲站点壳层和交互组件；
- Phase 5–7 只建立 A/B/C 医学 view model 与页面责任，不允许各报告另写一套自由样式系统；
- Phase 8 使用独立 PDF、HTML-PPT、PPT Master 投影，但共享同一快照和 coverage 集；
- Phase 10 用当前 run 的 3×4 产物和真实浏览器/Office/PDF 锚点证明边界有效。

如果某格式需要新的视觉表达，先扩展类型化 view model、格式投影或公共组件并新增机械检查；不得把任意 HTML/CSS 生成重新塞回 Agent 提示词。

## 6. 回滚

本 ADR 只固化已批准架构的责任边界。若某个确定性组件无法覆盖真实医学表达，应在保持快照、coverage 和真实验收不变的前提下扩展组件；不能回滚到“模型自由生成最终页面并自我宣告完成”。
