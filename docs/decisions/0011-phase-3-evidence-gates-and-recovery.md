# Phase 3 证据规则与恢复边界

状态：批准设计 v1.2 与批准实施计划的无损摘要；若摘要与原规格冲突，以原规格为准。

## 报告关键证据

- A：所有项目需身份、创新纳排、靶点/机制、模态、开发者/原研方、适应症关系、中国与境外最高阶段/状态及日期。临床、申报/上市/终止、已有数值结果项目按成熟度增加试验、监管事件和最低疗效/安全摘要。已有数值结果项目缺可解释核心疗效或 TEAE/SAE 数值摘要即阻断，不能删除产品后继续。
- B：每项核心结果试验需身份/角色、人群与组别、治疗与对照、每个可比较组的基线样本量/年龄/性别/至少一个适应症严重程度锚点、至少一个核心疗效终点的完整语境与两组数值、至少一个 TEAE 或 SAE 数值及来源定位。多臂总体值不能冒充逐组覆盖。全部试验完成/处置字段强制建模但非阻断，缺失不得写零、不得单独请求用户。
- C：每项适格核心试验需试验身份/阶段/开发角色、目标人群和关键入排、分组/随机性/盲法、干预/对照/背景和救援治疗、剂量/给药/疗程/随访/延伸、主要与重要次要终点的定义和时间点、计划或实际样本量，以及适应症规则明确列为关键的地区/访视/操作特征。正式 Protocol/SAP 非必需；官方登记覆盖全部适用核心字段即可通过并标注仅有登记信息。分析人群、主要比较逻辑、统计模型/检验、效应量、多重性、样本量假设、估计目标/伴发事件、缺失数据和敏感性分析均建模但非阻断。
- 适用关键单元缺一个即使该报告失败；不能删除已识别的适格产品或试验换取通过。项目覆盖只能增加单元或提高阈值，必须形成新合同版本并只重算受影响报告。

## 机器合同

- 每个规则单元固定稳定 ID、报告类型、阻断级别、对象类型、父子对象范围、适用性谓词、必需上下文字段、允许来源角色、最低披露成熟度、接受的事实状态、缺失策略、冲突策略、阈值和用户说明字段。
- 评估输入必须绑定已闭合竞品宇宙和研究角色集合，保存 `project_id/product_id/trial_id/comparison_id/group_id/endpoint_id/timepoint_id` 中适用的稳定标识、输入快照摘要、适用对象集合摘要与 `enumeration_complete=true`。未知、重复、漏评或未证明为空的对象集合失败关闭；有证据证明无适用对象时才可产生明确的不适用结果。
- 事实绑定明确 `trial/comparison/group` 作用域，数值、单位、分母、来源定位和披露状态分开。`reported_zero` 必须有明确零值原文；未报告、未公开、穷尽后未找到、技术未解决、低于报告阈值、不适用和冲突均不能转成数值零。
- B 的基线按每个核心试验的每个可比较组评估。疗效同时绑定治疗组与适用对照组及比较对；安全最低记录按各适用组保存 TEAE 或 SAE 数值。单臂支持/特殊核心按原设计只评估其唯一组，不虚构对照；多臂试验的总体值或部分组值不能覆盖其余组。
- A 成熟度由已接受事实确定，不接受调用方手工降级。临床前数值不触发临床 `result_bearing`；临床数值结果一旦由官方登记、监管、主要试验报告、会议/公司数值披露或指定来源触发，就必须同时满足核心疗效记录与 TEAE/SAE 数值摘要。
- A 的中国/境外状态没有开发活动时，只有带适用性依据的“不适用”可满足；空白不能满足。C 的 Protocol/SAP 缺失本身不阻断或触发用户补件，前提是登记事实覆盖全部适用核心设计单元。
- 用户说明字段固定为中文医学对象、缺失内容、影响和下一步；内部 ID、枚举和状态值不得作为用户文字直接输出。

### 封闭枚举与 A 触发谓词

- 规则来源角色只取：官方试验登记、监管审评/说明书、主要试验同行评议报告、正式方案/SAP、学术会议数值披露、公司数值披露、指定权威行业来源。每个单元保存允许角色集合，不从自由文本推断。
- 披露成熟度按可比较序列保存：`可归属数值披露 < 学术会议完整数值 < 官方登记结果或主要试验报告 < 最终监管结论`；C 的官方登记设计事实通过来源角色集合判定，不借结果成熟度序列冒充。
- 事实披露状态复用 Phase 2 的封闭枚举；冲突可接受结果仅为“已解决并选择已接受事实”或非阻断单元的“保留开放冲突”。关键单元只接受前者。
- A 开发成熟度使用封闭集合：临床前、临床、申报、已批准、暂停/终止/撤回；成熟度不被当成单一线性排名，适用规则由状态集合确定。
- A 临床结果状态使用：无适格临床试验、适格试验尚无观察性数值结果、已有观察性临床数值结果。`result_bearing=true` 当且仅当已接受事实属于目标适应症适格试验、事实域为疗效或安全、`observation_kind=observed_result`、为数值结果且来源角色在允许集合；计划样本量、计划终点、计划时间点、目标值和方案假设均不得触发。

## 项目覆盖偏序

- 单元集合只能增加；阈值只能提高；适用对象集合不能缩小。
- 可接受来源角色集合只能收窄，最低披露成熟度只能提高。
- 非阻断缺失可改为阻断，阻断不得放松为非阻断；可接受冲突处置只能收窄，未解决冲突不得改为通过。
- 每次覆盖保存父/子项目合同版本、变更摘要、依赖单元与受影响报告集合。旧规则结果不可变；只让依赖变更单元的报告回到覆盖评估/科学质控，未受影响报告结果摘要保持不变。
- 偏序算法固定为：`new_applicable_set ⊇ old_applicable_set`、`new_source_roles ⊆ old_source_roles`、`new_maturity_floor ≥ old_maturity_floor`、`new_conflict_acceptance ⊆ old_conflict_acceptance`；`blocking=false -> true` 允许，反向拒绝。覆盖操作只允许增加单元、提高阈值、扩大适用对象或收窄可接受集合，其他操作失败关闭。
- 规则结果不可变键由报告类型、证据快照 ID、基础规则版本、项目合同版本和适用对象集合摘要共同确定。受影响报告由变更单元到报告的反向依赖计算；调用方声明如与计算集合不完全一致则拒绝。父合同不存在、已被错误替换或证据快照不一致时不得生成子结果。

## 阻断与用户恢复

- 自动检索执行与独立遗漏复核都通过双重穷尽后仍缺关键证据，只生成 `blockers/<report>/<version>/audit.json` 与中文 `audit.md`。
- 阻断时不得创建锁定报告快照、覆盖集/投影、格式任务、渲染队列、产物记录或正式/草稿/占位门户。
- 证据不足说明只告诉用户：哪个产品/试验的什么关键内容阻断、已经尝试到什么程度、是否需要用户、最小动作、原文/附件链接和唯一投递目录；搜索日志与程序状态不面向用户。
- 主文、登记结果或监管材料已覆盖关键字段时不请求 supplement。确需用户下载时，用户保留发布者文件名；系统负责内容识别、规范命名、归档、抽取和续跑。不完整、登录页、错误附件或歧义文件进入隔离区并给一句明确指引。

## 控制图与独立质控

- 项目、报告证据、格式产物、下载请求、修订审批及其他版本对象使用 v1.2 §10.2 的完整状态和显式守卫。所有迁移保存事件、执行者、守卫证据、幂等键与前后版本。
- A/B/C 共享证据但不共享规则结果、报告快照或格式状态。一个报告或格式失败不撤销已通过对象；`partially_delivered` 与穷尽后的 `partial_delivery_blocked` 分开。
- GateSpec 通过后仍需独立科学质控接受才能锁快照。验证者只读候选快照、规则与来源证据；可否决或接受，不改写事实。可修复否决回恢复，已穷尽否决进入证据阻断，两者均无报告产物。
