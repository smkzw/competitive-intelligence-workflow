# v1 工程 Review 与 v2 处置（2026-10-27）

对象：`main@3087943f`（v1，2026-10-12 最后提交），现冻结为标签 `archive/v1`。本文汇总阶段 1 讨论、阶段 2 缺陷与增删清单，以及对计划的调整。

## 1. 总判断

v1 的需求方向成立，CT.gov 原子抽取（缺失≠0、0/0 不出率、分母取最深作用域、逐值 JSON-path 回放）可以复用。真正的问题在三处：

1. **派生环节不在产品里。** 研究 → 事实 → 门户载荷靠 `packets/` 与 `tools/` 下的 PNH 专用脚本完成，CLI 的 `project run` 只做门禁和渲染，新适应症跑不出报告。
2. **信任链是自签的。** 研究包里写着 `scientific_review.status: accepted`，校验只比较字符串和摘要。项目自己 09-23 的 REVIEW F01 已经指出过，此后一直没有修。
3. **发布门结构上不可能通过。** 一次发布要过 24 门户 × 双浏览器 × 4 宽 × 4 状态 + 三宿主 + fresh-install + 多模型独立会商；每轮宽门约 300 s。10 月的全部工作，是把 4 条论文数值接进 A/B 消费者。

## 3. 增删清单

**保留并重写（思路复用，代码新写）**
- CT.gov v2 原子抽取：分母作用域、缺失≠0、JSON 定位。
- CAS 原件存储：sha256 寻址、获取时间、URL。
- 事实带来源与定位、内容哈希作为稳定 ID。

**新增**
- 适应症 YAML（检索词、概念字典、产品别名、本品）。
- `analyses` 解析与组间差投影。
- 异构模型交叉核对（`verify/crosscheck.py`）。
- 中国来源采集收件箱 + CDE/NMPA/公告/公众号解析。
- 工作台 `ciw_release` 适配器与门户托管路由。
- release JSON Schema。

**删除（不迁移）**
- PDF/PPTX/HTML-PPT 渲染、监测服务。
- 三宿主 smoke、fresh-install、Skill 安装包。
- 验收 runner、视觉验收签发、科学复核签发链。
- 用户事实编辑服务、修订/撤销事务、离线分享包、个人配置。
- 历史截止日回放、终点族 registry-v7、渲染层翻译器。
- Trellis 与各 Agent 工具镜像目录（.codex/.cursor/.grok/.omp/.kimi-code/.codebuddy/.agents）。
