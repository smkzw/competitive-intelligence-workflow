## 1. 产品结论与首版边界

### 1.1 产品形态

系统是面向医学经理和医学总监的、可审计的科学事实与证据产品，不是一次性搜索脚本、提示词串联器或通用 AI 仪表盘。产品由以下部分组成：

1. 一个可安装、可版本化的 Skill 包和一个公开入口 Skill；
2. 多个具有稳定输入、输出、错误和恢复语义的内部 Skill；
3. 一个由应用持有的类型化控制图和一个本地确定性执行器；
4. 每项目自包含的证据、事实、快照、运行记录和报告目录；
5. 三个独立的高密度多页面 HTML 门户：A、B、C；
6. 独立的科学、视觉、包和恢复验收。

A、B、C 不是三个主题页，也不是一个跨报告超级门户：

- **A 是景观控制台**：完整创新药宇宙、产品档案、开发和监管状态；
- **B 是证据比较室**：疗效、安全性、基线、人群和试验完成情况的可比事实；
- **C 是设计图谱**：逐试验设计事实、模式、差异、权衡和多条候选路径。

三者共享字体、无障碍、响应式、页底来源区和组件质量基础，但不得套用一个 dashboard 模板，也不得建立第二套事实库。证据抽屉可以作为原位下钻交互，但不能取代页底来源区，也不是三个门户必须采用同一布局的理由。

### 1.2 用户最小合同

用户可以用一句话发起，例如：

> 请做特应性皮炎的 A、B、C 竞品调研。

最小输入为适应症和报告类型（A/B/C，可多选）。若用户未明确报告类型，入口必须用宿主原生 Ask 以带简短解释的选择项说明：A 研究创新竞品、管线、机制和开发/监管状态，B 研究临床疗效、安全性、基线和结果差异，C 研究人群、终点、访视、入排和方案设计模式。站点式 HTML 默认交付，不需要用户先列举竞品、设计检索式、配置来源或编写研究方案。历史数据截止日是可选项；默认截止日是合同建立日所在声明时区的自然日。每个新项目还只询问一次用户是否具备药智网访问条件，缺少访问不阻断其他来源。来源发布日期、生效日期、获取时间和数据截止日必须分别保存。

公开入口 Skill 负责把这一句话转换为项目合同、适应症身份、研究任务和可验证的 `research-package`。用户也可以提供一个符合当前 schema 的、已版本化的 typed research-package；提供该包是可选输入，不是用户的必答工作台。宿主 Agent 负责自主检索、来源适用性判断、下载和初筛，然后以同一合同把结果交给确定性引擎；用户不负责手写内部证据状态。

### 1.3 v1 发布范围

首版发布范围是 **HTML-only**：

- 每个所选报告生成一个独立的、内容完整的、多页面站点式 HTML 门户；
- v1 不发布 PDF、HTML-PPT 或可编辑 PPTX 运行时；
- v1 不生成表格级 CSV/XLSX 导出文件；
- v1 不提供雷达图或证据成熟度视图；
- v1 不提供定时监测、后台自动轮询或无人触发的刷新；刷新由用户手动触发，触发后来源复核、差异识别、快照建立和受影响 HTML 重建必须自动完成；
- 既有非 HTML 代码、schema 或历史验收材料不得被当作 v1 运行时能力，也不得进入 v1 产物或验收集合。未来恢复某一格式、导出、雷达、成熟度或监测能力必须以新的版本合同和新的用户决策恢复，不能修改已冻结 RC。

HTML-only 不意味着内容缩减：结构化数据先图后表，表格是同一事实集的完整折叠表，A/B/C 页面责任不能用首页摘要、Top-N 或单页长文档替代。`formats` 只能由当次 artifact manifest 实际计算；v1 的闭合值为 1，而不是静态常量。

### 1.4 验收范围不是产品范围

真实来源验收固定覆盖八个适应症：

1. 特应性皮炎（atopic dermatitis）；
2. 重度哮喘（severe asthma）；
3. 类风湿关节炎（rheumatoid arthritis）；
4. 溃疡性结肠炎（ulcerative colitis）；
5. 慢性鼻窦炎伴鼻息肉（CRSwNP）；
6. 结节性痒疹（prurigo nodularis）；
7. IgA 肾病（IgAN）；
8. 阵发性睡眠性血红蛋白尿（PNH）。

每个适应症分别产生 A、B、C 三个门户，共 **24 个独立 HTML 门户**。这 24 个门户是新鲜来源、门槛、科学和视觉验收矩阵，不允许通过合并门户、复用旧 run、复用旧 receipt 或删除稀疏项目来降低数量。

## 2. 权威顺序与升版决策

### 2.1 权威顺序

出现冲突时按以下顺序处理：

1. 当前用户指令和后续明确修正；
2. 本 v1.3 与其配套的 release-scope、Task 10.6 合同；
3. 本文附录 C 明确纳入的既有合同；
4. 已打包且通过摘要核验的康哲 `design_share_v2.md`，以及经验证的本地增强合同；
5. 未被后续决策推翻的用户原始回答；
6. ZCode 审计、旧 PRD、旧设计、旧交接、旧 Skills、旧测试和旧报告，仅作为历史、差异、迁移或回归证据。

无法确认适用性时失败关闭，不能以“审计建议”“已有代码”或模型记忆取代用户批准的合同。

### 2.2 ZCode 迁移标签 D71–D78 的当前处置

`D71–D78` 在本节只是为了与 ZCode 交接材料逐项映射的迁移标签，不是这些材料自身已获批准的证明。下表的效力来自用户对 2026-09-04 重基线计划的明确批准；一旦与当前用户裁决冲突，以当前裁决为准。

| 决策 | v1.3 处置 |
|---|---|
| D71 药智网企业版 | 保留为可选商业数据库来源；浏览器会话辅助；不能作为唯一权威，凭据和令牌不入任何产物。 |
| D72 research-package | 保留为确定性引擎的唯一科学入口；公开入口仍提供一句话自主研究，宿主 Agent 将自主研究结果编成该包。 |
| D73 首版格式 | 采用 HTML-only；PDF/HTML-PPT/PPTX 不进入 v1 运行时和验收。 |
| D74 表格 CSV/XLSX | 不进入 v1；当前门户只提供完整折叠表，不提供导出文件。恢复需新版本决策。 |
| D75 雷达/成熟度等增强 | 不进入 v1；普通结构化图形、热图和完整表仍是规范要求。恢复需新版本决策。 |
| D76 分发 | 采用版本化 Skill 包和关键词触发的公开入口；用户触点使用产品说明书式中文。 |
| D77 监测 | 定时监测、后台轮询和无人触发刷新移出 v1；不建设、不分发、不进入验收。用户手动触发后，刷新、差异识别和报告重建全自动完成。 |
| D78 治理密度 | 由 Codex 按工程审计材料判断；证据完整性、独立审查和失败关闭不可因瘦身而放松。 |

### 2.3 永久禁止的旧需求

以下项目继续被 v1.2 附录 B 和本版本禁止：Top-N 截断、缺失填 0、把空安全解释为安全、任意权重综合评分、四象限裁决、研发速度排名、入排宽严指数、方案创新度指数、跨试验池化、Bucher/Meta/NMA/MAIC/STC、以相似度聚类替代临床语境，以及任何把观察事实伪装成头对头结论的图形。暗色主题没有进入当前 v1，但它是未来视觉范围选择，不是科学性永久禁项。

## 3. 公开入口、研究包与内部 Skill

### 3.1 公开入口 Skill

公开入口的用户触点只承担产品说明：触发词、最小输入示例、可得到的 HTML 交付物、能力边界、常见阻断和中文求助指引。`gate`、`snapshot`、`receipt`、`research-package` 等内部词不得出现在普通用户入口文案中；它们可以存在于机器合同和工程日志。

推荐且 v1 固定的中文触发词为“竞品调研”。安装包 manifest、入口 `SKILL.md` frontmatter 和安装说明必须使用同一触发词。触发后：

1. 建立项目合同和运行上下文；
2. 执行能力预检；
3. 自主完成适用的来源研究和初筛；
4. 将研究结果转换成严格校验的 typed research-package；
5. 调用确定性身份解析、证据门槛、快照和 HTML 渲染；
6. 只向用户汇报启动、里程碑、资料请求、阻断、部分完成或完成，不刷出查询日志和内部诊断。

用户可以直接给出一个 research-package 作为补充或恢复输入，但不会被要求自行填充 package 才能启动。

### 3.2 research-package 合同

`research-package` 是确定性引擎的唯一科学入口。至少包含：schema 版本、适应症和合同身份、数据截止日、实体候选、来源版本/原文引用、精确定位、路由回执、抽取候选、恢复轮次、缺口策略和脱敏元数据。包必须严格校验未知字段、缺失必填字段、身份歧义、非法状态和内部绝对路径。

宿主 Agent 的自主研究和用户提供的 typed package 走同一校验、身份、门槛和快照路径；不得因输入方式不同而放宽来源权重、缺失状态、冲突规则或独立审查。研究包中的候选值不是已接受事实，必须经过确定性规范化和科学 QC。

产品交接采用双层但单一信任边界：通用 v1.3 审计信封记录来源、路由、闭包、
恢复和独立复核，并以规范路径和 SHA-256 绑定每个所选 A/B/C 专属科学载荷；
确定性引擎只有在提交 manifest、信封和载荷当前字节全部复核通过后才能运行。
松散 `report-data.json`、未绑定的 A/B/C 载荷、聊天文本或手写完成状态不能成为
产品输入。该双层结构不是两个科学真源：信封负责跨报告审计闭包，专属载荷负责
保持各报告已批准的精细医学数据合同。

同一项目可在一次产品运行中选择多个报告类型。调度器必须分别消费所选报告的
专属载荷，生成彼此独立的 A/B/C 门户和报告状态，不生成融合首页；共享节点按
“节点键 + 实际输入摘要”复用，不能把某一报告载荷下的完成状态误用到另一载荷。
恢复时只重算未完成报告及其下游，已发布阻断决定和已接受门户均按原字节重开。

来源的 `publication_classification` 必须按类型解释：只有
`source_type=publication` 使用主要结果、延长期、关键安全/长期、综述、ad hoc
或探索性分类；登记、监管、附件、公司、会议和二级来源统一为
`not_applicable`。来源是否可访问由 `access_state` 独立表达，不得把“可访问”
误写成“主要结果论文”。

引擎不得把聊天记录、模型记忆、页面截图、旧报告或工作流状态反向当作科学事实。引擎不以任意互联网搜索作为科学兜底；允许的直接拉取器若存在，必须是明确白名单、可限速、可回放并写入完整回执的可选实现，不得成为宿主自主研究和离线恢复的必要条件。

药智项目回答与运行期访问状态必须分离。项目回答仅允许 `available`、
`unavailable`、`skipped` 三态并只记录一次；`available` 才把
`yaozh-optional-browser` 加入来源计划，且该路线始终 `required=false`。
`unavailable` / `skipped` 形成明确的 `not_applicable` 操作状态，不冒充来源已验收。
登录会话失效由绑定项目回答摘要的类型化可选路线访问回执表达，并由能力矩阵给出
非阻断中文提示；它提示用户自行登录，但不改写项目回答、不阻断公开来源核心研究
或 HTML 交付，也不等于科学无数据。宿主浏览器可启动不等于药智会话仍有效；后者
只能在实际访问该路线时判断。
`source-policy-v1` 1.1 明确将药智的临床数值降为 `lead_only`，其他适用声明域
最多为 `cross_check`；任何药智内容都不能成为关键临床数值、监管状态或科学结论
的唯一依据。上述任务、能力和来源回执均为封闭类型，不接收凭据、Cookie、token、
授权头或浏览器存储。

### 3.3 内部 Skill 边界

| Skill | 主要输入 | 主要输出 | 禁止行为 |
|---|---|---|---|
| 入口与预检 | 最小输入、宿主能力 | 项目合同、能力矩阵 | 擅自缩小竞品宇宙或静默降级 HTML |
| 自主研究与研究包 | 适应症、缺口、来源计划 | research-package、来源回执 | 把线索写成接受事实；记录凭据 |
| 本体与竞品宇宙 | 适应症、创新本体 | 全量分层集合、纳排回执 | Top-N、宣传语或名称相似度纳排 |
| 来源解析与摄取 | 已获取来源、研究包 | 不可变来源版本、片段 | 把技术失败记为无证据 |
| 抽取、规范化、实体解析 | 来源片段 | 原子事实、冲突集合 | 覆盖原文或强行合并不等价项 |
| 覆盖与门槛 | GateSpec、事实 | 缺口账本、通过/阻断 | 用总完成率掩盖关键字段 |
| A/B/C 分析 | 锁定快照 | 各自页面数据与声明 | 互相依赖或建立第二事实库 |
| HTML 渲染 | 已批准快照、页面计划 | 独立多页面门户 | 截图冒充内容、静默删减 |
| 科学/视觉/包/恢复质控 | 实际产物和回执 | 接受/否决 | 生产者自行宣布完成 |
| 手动刷新与修订 | 已接受快照、用户批准 | 差异、新快照、影响集 | 自动发布、自动监测或覆盖历史 |

HTML 渲染采用版本级未发布事务：渲染器只写当前运行的 staging 目录，完成后原子
换名为 `html/` 并原子写入 `html.manifest.json`。仅当版本根不存在产物清单、覆盖
投影、artifact store、当前运行清单或科学复核状态绑定时，下一次 resume 才能精确
清理由中断留下的站点、staging 和 manifest 临时文件；任何未知文件、软链接、
损坏绑定或已发布记录都失败关闭。原始站点渲染函数不是产品发布入口。

## 4. 控制图与项目状态

### 4.1 控制图原则

系统采用应用持有的类型化控制图，不把科学真源交给某个图框架、中心服务器或宿主私有 checkpoint。LangGraph 不是必需依赖，也不得成为科学真源、宿主一致性或离线恢复的前提；未来如增加适配器，只能消费同一类型化控制图并作为可替换运行层。每个节点定义类型化输入/输出、前置条件、完成谓词、读写范围、重试/超时、错误分类、幂等键和独立接受者。默认使用单 Agent 节点；只有真实并行、不同上下文或独立否决需要时才增加节点。

控制图必须表达：A/B/C 分支、来源并行、缺口恢复、一次用户资料中断、修订批准、部分 HTML 交付、快照锁定、独立 QC 和恢复重放。生产节点不得自行宣布接受；验证节点拥有接受或否决权。重放不能重复重命名、批准、发布或删除，也不能重复改变已经接收的用户补件。

### 4.2 分离状态机

不得使用一个含糊的 `status` 表达所有对象。v1 继承 v1.2 §10.2 的项目、报告证据、格式产物、下载请求和修订审批状态以及合法迁移守卫。HTML 是唯一进入 v1 `delivery_ready` 的格式；未来格式的代码或历史回执不能改变当前 HTML 状态。

项目、报告和证据状态必须至少区分 `running`、`awaiting_user`、`partially_delivered`、`partial_delivery_blocked`、`blocked`、`complete`，以及 `reported_zero`、`not_reported`、`not_publicly_disclosed`、`unresolved_due_to_route` 等事实状态。技术失败、访问阻断和科学上的未公开不能互相替代。

### 4.3 项目自包含与版本

每个项目必须保存可移动的相对路径和稳定身份：


## 5. 来源政策、研究穷尽与用户资料

### 5.1 分声明域的来源策略

来源权威按声明域、地域和披露阶段确定，不设置一个适用于所有字段的总排名。至少覆盖：官方试验登记及历史版本/结果、监管审评和说明书、主要同行评议论文、登记关联的公开附件、关键长期/安全性论文、适用会议和公司披露，以及五个指定公众号（医药魔方 info、药融圈、丁香园 Insight 数据库、米内网、中国药审）。每条证据保存来源角色、披露成熟度、发布日期、获取版本和精确定位。

- 药物身份、机制、创新纳排：监管、官方登记、同行评议机制资料、可归属公司资料；
- 试验身份、设计、状态：官方登记及历史/附件、监管材料、方案/SAP；
- 疗效和安全性：登记结果、监管材料、主要论文和必要附件，指定公众号只在其允许声明域内直接支持；
- 基线和受试者处置：登记结果、监管材料、主要论文和明确报告该字段的公开材料；
- 中国与全球监管：适用辖区官方监管机构和官方登记，分轨保存；
- 企业关系、交易、专利：公司/证券披露、交易文件、官方专利/独占记录及可核验法律材料。

### 5.2 必须关联的论文与手工资料门

对进入核心比较或设计分析的适格试验，研究包必须检查登记关联的主要论文、扩展/补充材料、关键长期随访和关键安全性发表物。B 的疗效、安全性和基线核心不能只凭新闻稿或模型总结；C 的设计事实以登记平台及其历史和附件为主，论文只作身份和高层方法交叉核验。

登记页面绑定的 publication 先由版本化规则和模型共同分类，边界或阻断案例再由独立干净上下文复核。主要结果论文、延长期主要结果论文以及关键安全性或长期暴露论文属于必需 publication；综述、普通 ad hoc 分析和与核心问题无关的探索性分析默认排除，并保留分类理由。

当必需论文或附件不可访问时，系统只建立 **一个** Markdown manual-supply gate，集中列出：产品/试验、PMID/DOI/登记号、精确标题、阻断字段、已尝试路径、原文/附件链接、唯一投递目录和最小用户动作，并暂停受影响报告。用户文件必须通过摘要、类型、标题页、嵌入元数据和试验/论文标识符内容核验。核验通过后在用户指定的投递目录中原地规范重命名，不复制、不归档、不移动到其他目录且不修改文件字节；操作前写入原文件名、SHA-256、DOI/登记号、目标文件名和碰撞检查结果。目标冲突或身份不一致时失败关闭。

用户对该请求只需响应一次。若一次响应后资料仍不可用，同一快照不得再次追问：

- 若官方登记/监管证据仍足以回答核心门槛，继续生成报告并明确标注限制；
- 若核心问题无法由官方证据回答，内部生成证据不足审计包，对用户只交付简洁证据不足页，不生成草稿、空门户或推断值。

“只有全文下载才允许人工中断”不是 v1 规则；人工中断只在自动安全路径穷尽且该资料对当前报告确实关键时发生。

### 5.2A 来源新鲜度与历史可知性（2026-09-05 用户裁决）

按来源性质处理新鲜度，不使用一个统一过期天数代替研究判断。已获取论文的有效结果可以复用；动态管线、试验与监管状态每次研究运行必须重新核查。缓存仅用于加速，不能作为本次已经完成核查的证明；遇网络或权限错误不得把旧缓存状态表述为当前已确认状态。

历史截止日报告回答“当时可以知道什么”：只使用截止日前已公开的证据与当时状态。事实生效日早于截止日、但截止日后才首次公开的证据不能倒填到历史结论。来源发布日期、事实生效日、获取时间和报告截止日分别保存；晚于截止日的获取时间本身不排除一份能证明在截止日前已公开的历史版本。无法证明历史版本或公开时间时，应列为待核验/缺口，不得默认以当前动态页面还原历史状态。

以上为批准的产品合同；工程实现和验收情况由当前接管检查点记录，本段不宣称相关运行门已经实现。

### 5.3 药智网企业版

药智网企业版（`vip.yaozh.com`）是可选商业数据库来源，不是 v1 的唯一或必需来源。它可支持药物身份/别名、中国注册或批准状态、全球管线阶段、企业关系/交易线索和适应症扩展轨迹；数值疗效和安全性不得直接采纳，只能用于定位线索。与官方登记、监管或主要论文冲突时进入冲突门，官方直接证据优先。

2026-09-05 用户裁决：药智登录观察允许在同一运行内短期复用，遇实际访问失败立即失效并重检；不得跨运行沿用旧“已登录”回执作为当前可用性证明。历史回执只供追溯。短期窗口应成为明确、可测试的运行策略，具体时长尚未裁决或实现，不得声称已有用户批准的数值。重检仍遵守用户自行登录与凭据零落盘边界，不要求用户重复回答项目访问条件。

每个项目只记录一次初始可用性回答：`available`、`unavailable` 或 `skipped`。
记录必须绑定项目身份并原子落盘；同值重放保持字节和修改时间不变，改答、损坏、
跨项目替换或软链接均失败关闭。该记录不含用户名、密码、token 或浏览器会话。
`session_expired` 是后续浏览器路线的访问回执，不是初始 Ask 的第四个回答。

Yaozh 访问可以使用用户自己的已登录浏览器会话辅助；每个新项目的入口只询问一次用户是否具备访问条件。用户没有账号时跳过；会话失效时只提示用户自行登录。用户名、密码、Cookie、会话令牌和授权头不得进入 research-package、项目文件、日志、回执、快照、bundle、审计或截图。缺少 Yaozh 访问只产生细粒度的来源回执，不得被写成“没有证据”，也不得阻断能够由其他适格来源完成的核心字段。

### 5.4 路由完成与信息增益饱和

每份首次报告都必须先完成竞品宇宙闭包：运行全球和中国必查来源，扩展产品别名、靶点/机制、企业和试验登记反向关系，并由独立干净上下文复核遗漏与纳排。固定数量、Top-N、单一路由或“看起来已足够”都不能替代完整性。刷新还必须复核新增变化、异常数量和与历史集合的差异。

v1.3 的规范写入路径是单一 `ResearchPackage`：每个别名、靶点、企业和试验反向
扩展必须形成类型化回执，绑定路线、尝试、输入实体、发现实体、来源、查询摘要、
结果类别和诊断；闭包内四类回执集合必须与实际对象逐项相等，不能接受任意字符串或
遗漏回执。候选与排除实体必须来自这些回执，并分别绑定 `included`/`excluded`
处置、版本化本体规则、原始名称/别名和身份来源。历史 `UniverseClosureReceipt`
不再作为第二个可写产品真源。

闭包收敛只由最后连续两轮零新增证明；网络、解析、限流、验证码、来源不可用、能力
缺口或内容截断均为未完成状态，不能改写成真实零发现。独立闭包复核必须同时满足
生产者与复核者身份不同、生产与复核上下文不同，并把 verdict 绑定到由项目合同、
截止日、来源政策版本、实体处置、路线、扩展回执和闭包候选材料确定性计算的
`reviewed_universe_sha256`。复核后任一候选字节漂移都使 package 失效。

产品运行从不可变审计包摘要生成唯一项目级 universe identity；A/B/C 只投影各自
报告事实，不得生成报告专属宇宙身份或倒写/截断全量集合。同一运行中相同节点键与
相同输入摘要仅完成一次，恢复时按既有事件摘要复用。

双重穷尽仍是用户中断前的必要条件，但在一句话自主研究和 typed package 两种模式下都必须落为机器可审计字段：

1. **路由完成**：每条必需路由在 package 中有 `completed`、`not_applicable` 或经细粒度诊断证明的 `access_blocked` 回执；缺口的策略矩阵已实例化；
2. **信息增益饱和**：两轮不同的缺口驱动恢复没有获得能够改变关键单元、减少关键冲突或改变适用性的新增证据，或者剩余信息已证明为私有、未公开或权限限定；
3. **独立遗漏检查**：独立科学 QC 和 blocker audit 逐适用单元检查，不能用“没有实质遗漏”一句话放行。

关键缺失或异常零值必须进行两条不同的替代恢复检索，并在恢复后进入干净上下文的最终独立审查。缺少独立审查能力即预检失败。重复相同查询、标识符和访问方式不算新策略或新一轮信息增益。

### 5.5 错误分类与证据状态

路由结果至少区分 `success_with_evidence`、`success_irrelevant_only`、`searched_no_evidence`、`not_publicly_disclosed`、`access_or_permission_blocked`、`transient_network_failure`、`rate_limited`、`anti_bot_or_captcha`、`source_unavailable`、`parser_or_schema_failure`、`tool_capability_gap` 和 `content_truncated`。事实值至少区分 `reported_value`、`reported_zero`、`not_reported`、`below_reporting_threshold`、`not_publicly_disclosed`、`not_applicable`、`conflicting` 和 `unresolved_due_to_route`。

`reported_zero` 必须有明确原文；`not_applicable` 必须由版本化适用性谓词确定；`unresolved_due_to_route` 必须关联未解决路由回执。技术失败绝不能成为科学上的“没有证据”，访问阻断也不能替代关键事实。

## 6. 证据门槛与审计包

每个报告使用包内版本化 `GateSpec`。规则必须包括规则/字段 ID、对象范围、适用性谓词、所需上下文、允许来源角色与披露成熟度、新鲜度、允许缺失策略、冲突策略、关键/扩展级别、失败代码和恢复路由。项目覆盖只能增加限制，不能删除系统关键规则。

报告版本的确定性通过条件是：

`宇宙关闭且非空要求满足 AND 每个适用关键单元 satisfied AND 无未决关键冲突 AND 独立科学质控 accepted`

关键单元只能在存在达到来源、成熟度和上下文要求的已接受事实，或适用性被确定为 `not_applicable` 时通过。覆盖百分比只是说明，不能替代逐对象逐字段结果。候选范围必须在求值前锁定；不能删除稀疏、结果不理想或门槛失败对象来获得通过。

门槛失败统一生成 `blockers/<report>/<version>/` 下的机器 JSON 和简洁 Markdown 审计包。审计包不是报告、草稿、首页或占位门户，不得进入渲染器。它至少包含：合同和报告版本、失败规则/对象/字段、事实与缺失状态、受影响对象、全部路由回执、两轮信息增益差异、独立遗漏结论、诊断、不确定性、是否需要用户、最小动作、原文/附件链接、唯一投递目录和可恢复节点。

可选字段缺失时可以省略或用一句话说明。关键模块空缺或异常零值必须经过两轮不同策略恢复和独立终审：若真实有限宇宙中的官方登记或监管证据仍足以回答报告核心问题，则带明确限制交付；若核心问题仍不可回答，则内部保存完整阻断审计包，并只向用户交付简洁的证据不足页。不得生成大面积固定空字段、空坐标轴、零值占位、草稿或伪完整门户。A 没有适格创新项目、B 没有达到最低门槛的结果试验或 C 没有达到设计核心门槛的试验时适用同一规则。A 只有临床前项目或 C 只有一项适格核心试验不自动失败。

## 7. A 类：适应症竞品景观控制台

A 是目标适应症下全部创新治疗项目的完整开发档案。核心门槛按成熟度逐项判断：

- 所有项目：规范身份/别名、创新纳排、靶点/机制、模态、当前开发者/原研方、适应症关系、中国与境外最高阶段/状态及日期；
- 临床项目：适用核心试验身份、开发角色和状态；
- 申报/上市/终止项目：适用申报、批准、撤回、终止或放弃事件及地域；
- 已公开结果项目：至少一个适格锚定试验、一个可解释核心疗效记录和一个 TEAE 或 SAE 数值摘要，均带组别、对照、时间、分析人群和分母。

`result_bearing` 由官方登记结果、监管材料、主要试验报告、会议/公司数值披露或获准指定来源的明确数值触发；触发后缺少最低记录必须恢复，不能删回无结果层。临床前项目、未合作项目和暂无结果的早期项目保留真实状态，不因没有试验或交易失败。

A 门户至少包含：全景首页、竞争格局、产品总览、逐产品档案、临床开发组合、疗效与安全性概览、中国与全球监管、企业与交易、专利与保护、历史与边缘观察、证据与局限。每个结构化数据域使用适当图形并紧跟同一事实集的完整折叠表；叙事和缺失解释不强行画图。首页不以排名、评分或单一综合指数裁决产品。

A 的主要图形至少覆盖与数据适配的管线全景、靶点—产品关系、阶段矩阵、地域状态时间线、疗效比较、安全性热图和多维气泡图；没有可绘制事实时省略图形并说明原因，不生成空坐标轴。任何默认视图都不得只展示明星产品或以排名截断竞品宇宙。

A 单独运行时必须自行完成 A 所需证据；A 与 B 同时运行时可以复用同一不可变事实快照，但 A 不依赖 B 页面才能打开或解释。每页只设置一个聚合的外部来源区，显示中文来源入口和简洁限制；面向用户的表格、图例和页脚不得泄露内部文件路径、run ID、receipt、gate 计算或提示词。

## 8. B 类：证据比较室

### 8.1 核心试验和最低事实

B 核心比较层纳入目标适应症中有结果的 II/III 期、关键或注册相关试验；特殊早期试验只有明确的罕见病、肿瘤或加速开发决策证据角色才可进入特殊核心。早期、延伸、亚组、事后和真实世界研究保留支持层及理由，默认排除研究不得被隐式混入。

每项核心结果试验至少覆盖：试验身份/阶段/角色；目标人群、队列/组别、治疗和对照；组别基线样本量、年龄、性别及适应症严重程度锚点；至少一个核心疗效终点原始定义、方向、单位、评估时间、分析人群、治疗组、对照组和分母；可直接支持或确定性复算的效应；至少一个 TEAE 或 SAE 数值记录及定义、时间窗、组别和分母；来源角色、披露成熟度和精确定位。

基线门槛按每个可比较研究组判断，多臂试验不能用合并总体值伪装组别覆盖。均值/中位数、年龄分箱、性别分类、疾病量表版本、方向、单位和基线时间不兼容时必须分面或拆成小多图，不得估算、补造类别或以总体值替代。试验完成/处置字段全部建模但非阻断；未公开、来源未列示、技术不可用、不适用和明确为 0 必须分开。

### 8.2 整体临床构念分组

B 的终点和时间窗分组采用“模型辅助的整体临床构念语义分组 + 确定性冲突守卫”：模型可以提出同一临床构念、方向和分析语境的候选组，但不能单独改变组。48 周与 50 周等接近时间窗，在兼容的构念、定义、方向、单位、估计目标、分母和分析集下可以共用一个比较框，并在图题或标记中明确实际时间差；它们不是无差别合并。

以下任一项不兼容时必须拆分为独立小多图/表：量表或仪器、定义、方向、单位、估计目标、分母、分析集、分析形式或实质不同的时间语境。没有版本化兼容规则时，不能由模型临场合并。治疗组、对照组、原始终点角色、原始值、差异标签和证据入口始终保留。

B 不执行 Bucher、MAIC、STC、Meta、NMA、跨试验池化或安全/疗效综合评分，不默认给产品排名，也不自动给研发建议。常规输出是事实汇总和中性的差异描述。用户主动排序也只能在当前兼容桶内对方向校正后的试验内信号进行可逆视图排序；无对照或不可比记录保持未知/分列，不按零值沉底。

### 8.3 疗效、安全和人群页面

B 至少包含：首页、疗效、纵向结果、安全性、基线与人群、试验完成情况、试验/暴露语境、亚组与支持证据、产品/试验档案、疗效—安全性矩阵、证据与局限。结构化的疗效、纵向、AE、基线和处置数据均先图后表；每张图后提供同一过滤 row set 的完整折叠表。

B 的气泡图使用版本化临床预设组，不能由模型临场发明坐标轴：①疗效信号 × 总体安全性，大小为治疗组样本量或暴露量；②疗效信号 × 严重风险，大小为有效分析集规模；③获益持续性 × 停药风险，大小为长期暴露量。只有人群、终点/事件、方向、时间窗、估计目标、分析集和分母构成的完整临床语义基本可比时才进入同一图；不兼容内容进入相邻小多图。原始数值、方向、实际时间窗、分析集和分母在同模块折叠表中完整保留。

安全性热图至少覆盖 TEAE、SAE、AESI、常见 TEAE 和发生率；有数据时加入死亡、3 级及以上 AE、导致停药 AE 和治疗相关 TEAE。颜色只在相同事件和可比语境内表达高低；数值印在单元格，缺失/未报告/低于阈值/技术不可用/明确为 0 用不同状态。图例、对照语境、分母和缺失状态说明必须可见；不得输出雷达图或证据成熟度矩阵。

基线页面独立覆盖人口学、疾病语境和基线严重程度。完成情况页面独立覆盖筛选/筛败、随机/治疗、完成治疗/完成研究、停止治疗/退出研究、失访、依从性、补救治疗、禁用药和 PD，保留正确分母角色、计量对象、原因互斥/穷尽状态。非阻断字段没有数值时也呈现准确披露状态，不显示空白或伪造零。

## 9. C 类：临床试验设计图谱

C 提供逐试验逐字段的设计事实比较，并在事实之上形成设计模式、差异、权衡、风险和多条可选路径。只输入适应症时不能输出唯一或“最佳”方案；产品特异性建议需要机制、模态、阶段、给药、地域和人群/标签意图等背景。

设计事实以官方登记平台及历史版本、附件和公开方案/SAP 为主。可获得的方案/SAP 必须获取和抽取；不可获得时，只要登记字段足以覆盖关键临床设计即可通过，并明确“仅有注册登记信息”。论文只交叉核验身份和高层方法，不能替代登记设计事实。

每项核心试验至少覆盖：身份、阶段、开发角色；目标人群和关键入排；分组、随机/非随机、盲法；干预、对照、背景/救援治疗；剂量、给药、疗程、随访、延伸；主要和重要次要终点、定义和时间点；计划/实际样本量；适应症规则规定的关键地区、访视或操作特征。完整摄取登记公开的全部入选/排除条目；量表、阈值、运算符和筛选/基线时间必须按适用性保存，未使用量表的标准明确为 `not_applicable`。

C 页面至少包含：设计首页、设计图谱、试验档案、人群与疾病定义、入选标准、排除标准、分组/干预/对照、终点—定义—时间点矩阵、访视/疗程/随访/延伸、样本量/分析集/公开统计设计、设计模式/异常点/权衡/多路径综合、证据版本与局限。只输入适应症的验收必须形成至少两条有来源依据的候选设计路径，或明确缺少产品特异背景而不作唯一建议。

C 的主要图形至少覆盖与数据适配的设计模式地图、试验时间轴、终点—时间窗矩阵、入排主题分布、组别结构和方案差异图；完整入排条目、终点定义和方案参数保留在同模块折叠表中。多路径是证据支持的选项空间，不是自动生成唯一“最佳方案”。

## 10. HTML 门户、表格和证据交互

### 10.1 站点式 HTML

A/B/C 使用原生 HTML、CSS 和 ES2020+ JavaScript，不依赖 React/Vue 构建、远程字体、远程图片、远程脚本或运行时 `fetch` 本地 JSON。`index.html` 在 `file://` 和静态服务器下都可打开；页面数据使用版本化 `data/*.js` 或等价的本地内嵌对象。正式 Logo 随包本地嵌入并通过摘要和 SVG `viewBox="0 0 121 25"` 核验。

每个门户必须是至少两个互通物理页面的完整多页面站点，带统一粘性页眉、当前页状态、全局实体搜索、跨页下钻、键盘可用的原位证据下钻和唯一全局页脚。宽窄屏下品牌区、导航、搜索和 Logo 不碰撞；站点白/浅色面积不少于 80%，橙黄合计不超过 12%，红色只表示风险或阻断。每个门户必须有自己的信息架构、视觉重点和图形语法，不得用首页卡片、无限滚动、同一模板换色或通用 dashboard 替代页面族。“高密度”指事实深、细、全且无冗余，不得靠压缩字号、拥挤布局或展示工程字段制造密度；默认首屏不得出现阶段、Gate、提示词、覆盖率诊断或内部字段名。

### 10.2 图先表后与完整折叠表

每个结构化数据集都必须选择与其统计形式、单位、方向和语境相符的图形，并在同一模块内提供默认收起、原位展开的完整折叠表。表格不是摘要，也不能只列 Top-N；表格、图、证据下钻和网址状态读取同一 filtered row set。叙事、来源限制和缺失解释使用文本/状态模块，不强迫进入图形。没有可绘制数据时不渲染空坐标轴；关键内容不足按证据不足规则收口，可选模块不足则省略或一句话说明。

HTML v1 不提供 CSV/XLSX 导出文件。用户需要复制表格时，复制的内容必须仍是当前页面显示的完整事实集；任何未来导出能力必须定义快照、筛选状态、元数据和 artifact 边界后单独升版。

### 10.3 筛选、证据下钻和来源区

页面级筛选包括适应症、产品、靶点/机制和试验；模块级筛选包括终点、时间点、效应形式、分析人群、AE、设计要素、量表，以及 B 的队列/组别、变量域/字段族、统计形式、原因、分母角色、计量对象、披露状态。页面和模块状态分别写入网址；无数据模块显示限制范围和准确空状态，不自行扩大筛选。

点击图、表格、时间线或矩阵单元格，可以在原页面打开证据下钻并保持筛选、滚动和焦点。下钻显示产品、试验、组别、终点/事件/设计要素、量表、时间、值/阈值/单位、分子/分母、来源版本和精确登记字段/页/表/段定位；对基线和处置事实显示统计形式、计量对象、分母角色、原因语义、互斥/穷尽和差异标签。下钻可显示原文和规范化说明，但原文永远保留；其存在不能替代完整折叠表和页底来源区。

每页底部仅设置一个聚合的外部来源区，面向用户显示可访问的来源标题、来源类型、发布日期、数据截止日、链接和简洁限制。用户可见表格不得出现仓库相对路径、绝对路径、内部 receipt、run/job/session ID、门槛计算、源文件定位字段或搜索重试日志。完整路由与诊断留在项目证据和日志。

### 10.4 确定性默认值与真实视觉检查

默认锚定试验、首页终点族、常见 AE、基线变量、处置字段和产品/靶点顺序必须由版本化规则和稳定 ID 决定，不能由模型临场偏好或结果优劣决定。所有默认选择写入视图清单，新快照可复现，旧快照保持原选择。

所有物理页面必须覆盖桌面、平板、手机和窄屏四类真实视口，基准至少为 1440×900、1024×1366、390×844 和 320×568，并覆盖 Chromium 与 WebKit 以及声明的实际操作系统；大型页面、长表、折叠表、筛选、证据下钻、键盘、控制台、链接、中文可读性、数据完整性、遮挡和溢出都必须实际检查。可以增加 1920 桌面扩展检查，但不能用桌面三种宽度代替四类设备。不能凭源码、文件存在、缩略图或 `ok=true` 代替渲染验收。

## 11. 安装包、宿主和安全

### 11.1 Skill 包

安装包采用一个 HTML-only 通用核心包和 Codex/Hermes/OMP 轻量适配层；安装后只暴露一个用户入口，内部 typed Skills 保持独立可测试、可替换。包包含公开入口、内部 Skills、schema、受控词表、本体和来源策略、A/B/C GateSpec、控制图、默认执行器、HTML 渲染器、康哲 HTML 合同、脱敏基准、清单、许可证和摘要。v1 包不包含 PDF/PPT 运行时或运行依赖、表格导出、雷达/证据成熟度视图、监测能力、凭据、缓存或原始运行证据。缺少内部 Skill、合同、Logo、schema 或摘要不匹配时预检失败，不混合版本继续运行。

### 11.2 三宿主一致性

Codex、Hermes、OMP 宿主适配器只负责工具调用、能力映射、中断恢复、文件路径和状态返回，不能改变来源权重、门槛、错误分类、快照内容或验收标准。三宿主必须通过同一能力发现、HTML 生成、失败关闭、恢复、幂等和安装入口合同。产品命令来自安装入口；治理 verifier 在 clean RC worktree 执行，并在回执中绑定同一 RC 身份，不把测试树塞进用户运行包。

### 11.3 能力预检与用户指引

v1 预检重点检查文件读写、网络/浏览器研究能力、PDF/网页摄取、必要 OCR、脚本运行、真实浏览器 HTML 验证和独立上下文；PDF/PPT/Office/Poppler 不是 v1 默认必需能力。用户选择未来格式时才触发相应版本的额外检查。每种失败都给非技术用户可执行的中文修复指引，不能只显示错误码。

每次首次运行和恢复运行都必须执行新的能力探测，不得复用历史 preflight 节点或探针缓存。当前矩阵以类型化、原子替换且拒绝软链接/非普通目标的方式写入项目 `capabilities/preflight.json`；读取缺失回执不得创建目录或其他状态。研究必需能力缺失时在来源研究开始前以 `capability_blocked` 安全停止；仅 HTML 浏览器验收能力缺失时允许已完成的研究事实保留，但 format 不得生成或标记为完成。药智登录浏览器始终是可选辅助能力，单独缺失不能阻断核心研究或 HTML。能力阻断必须与证据不足和普通技术失败分开记录，并提供从同一项目恢复的中文指引。

任何凭据、Cookie、令牌、授权头、绝对路径、远程字体/脚本、未许可资产和不受控供应链依赖都会使包级安全检查失败。用户浏览器中的登录动作由用户自己完成，系统不复制或记录会话材料。

### 11.4 独立科学复核信任根

A/B/C 报告采用同一两阶段状态机。门户完成 format 后先进入 `rendered_unreviewed`，运行时把生产上下文、候选快照、研究内容摘要、Gate/coverage/source lineage，以及 HTML manifest 和站点目录的真实字节摘要绑定到不可变 review request。研究包内的审阅字段只证明摄取前研究材料达到入口要求，不构成报告候选的最终科学授权。

正式晋级只能通过安装包内 `review issue` 入口：入口读取现有 request，启动独立宿主外部进程，绑定宿主可执行文件、进程、会话和正式 verdict 文件字节，同时写入 `scientific-review-v1` receipt 与同源 issuance record。晋级前必须重新核验 request、receipt、issuance record、verdict、生产上下文和门户字节，并在实际晋级时再次检查签发时间与 `valid_until`；任一缺失、替换、漂移、同身份/同会话、自审、未来时间或过期都失败关闭。等待回执可执行任意次纯复用 resume；验收沿 `run.node.reused` 来源边验证完整运行谱系，不用固定两次运行假设。

本地 v1 信任模型防止普通调用方绕过公开 API、手写自洽 JSON 或误用无关历史，不声称能抵抗拥有项目目录写权限的同一恶意操作系统用户。v1 不引入 PKI、中央签名服务、操作系统远程证明、nonce 注册中心或第二套回执体系；若未来需要跨组织不可抵赖，再通过单独版本扩展信任边界。

## 12. 手动刷新、修订和历史

HTML 中的事实、图点、矩阵单元和声明可以导出修订建议，但不能直接编辑科学真源。建议经过来源、身份、上下文、冲突和影响集核验，进入 `validated_pending_user_approval`；只有用户明确批准后才能建立新版本并局部重建。拒绝或证据不足追加记录，不改变当前快照。

刷新是用户手动触发、随后全自动完成的增量能力：从最近接受快照、来源回执和缺口账本重新核验可变事实，复核新增变化、异常数量和历史集合差异，生成新来源/事实/声明/HTML 版本，保存新增、变化、撤回、取代和未变化 diff，只重算受影响页面。v1 不建设定时监测 Skill、不在无人触发时轮询来源，也不自动发布未经门槛与独立复核接受的报告。移除监测能力不影响打开、恢复和用户触发的自动刷新链。

## 13. Task 10.6、发布信号与独立验收

### 13.1 Task 10.6 四阶段

Task 10.6 仍分为四阶段，且每阶段前一检查点必须通过：

- **10.6A**：clean-commit provenance、最终 bundle 内容合同、`recovery-package-v1` manifest/receipt 和临时目录负向测试；不得创建 RC commit；
- **10.6B**：显式 release source set、Phase 0–10 确定性回归、隔离 clean worktree 和唯一 RC commit/tag；不访问真实旧根；
- **10.6C**：从 RC commit 构建/核验/安装最终 bundle，在全新 release root 用安装入口执行八适应症 A/B/C HTML 矩阵和三宿主回执；拒绝旧 run/job/session/artifact/verdict；
- **10.6D**：恢复包隔离演练、刷新、代表性 HTML 重建、owner-stage receipts、科学/视觉/包/恢复独立验收和 freeze record。

代码、schema 或历史资料中的四格式字段可以为未来兼容保留，但首版 artifact closure 只允许 HTML；任何 PDF/PPT 产物都会使当前 v1 scope 失败。

### 13.2 必须满足的终验条件

执行/会议代理负责运行和报告；Codex 负责最终接受。P0/P1 必须为零。P2 必须修复，或形成有证据的明确 non-impact disposition；不能以未分类、延期或“已知”掩盖。每个结论必须绑定真实文件、命令输出、数据库查询、浏览器渲染或恢复演练锚点。

发布状态只允许 `DEVELOPMENT_CANDIDATE → RC_FROZEN → RELEASED`。`RC_FROZEN` 只在以下条件闭合后输出：

```text
RC_FROZEN reports=3 formats=1 hosts=3 recovery=passed pending_future=1
```

`formats=1` 必须由当次 A/B/C HTML artifact manifests 实际计算；`pending_future=1` 只能表示尚未授权的 `legacy-absence` future owner，不得提前执行或接受真实旧根 absence 检查。`RELEASED` 只能由已冻结 RC 的正式发布裁决产生，不另建试用/候选状态。Task 10.6 不读取、inventory、validate、apply 或 absence-check 真实旧根，也不得宣称 `legacy_absent=passed`。

### 13.3 验收层级

必须覆盖包完整性、schema/状态/稳定 ID、来源回执和研究包、宇宙关闭与两轮恢复、A/B/C 门槛、语义兼容和无池化、HTML 页面/搜索/导航/筛选/网址/表格/证据下钻/无障碍、三宿主、用户触发的自动刷新链/历史、恢复包、秘密/绝对路径/远程依赖和 24 门户真实来源矩阵。确定性检查和真实 Chromium/WebKit 渲染缺一不可。

关键负向矩阵至少覆盖：拥挤领域初搜只发现少数竞品；网络错误被误判为真实无数据；Yaozh 无账号或会话失效；必需论文无法下载且用户确认无法取得；48/50 周可近似归并但不同量表、方向、估计目标、分母或分析集不得误合并；无可绘制数据时不得出现空坐标轴；重名/错误/扫描 publication 或登记号不一致；刷新后的新增、修订和撤回事实/来源进入正确差异；宿主无法创建独立上下文时预检失败且不得主 Agent 自证。

## 14. 迁移、回滚和后续版本

新系统在独立项目根构建。发布 source set 只含当前批准代码、schema、合同、必要资产、测试、脱敏基准和治理记录；不含凭据、旧可运行流水线、旧全局事实库、缓存、绝对路径、未批准归档或外部旧根。

真实旧根在当前阶段保持零接触。只有新系统至少完成三个覆盖 A/B/C 的真实项目，且用户触发刷新、历史差异、恢复和三宿主运行通过、严重缺陷清零、可验证回滚成立后，才允许再次请求用户明确批准其退役；获得批准前仍不得读取、inventory、chmod、修改、删除或 absence-check。RC 冻结和旧根退役是两个不同裁决，不得用 `pending_future=1` 冒充旧根已验收。

每个失败阶段保留不可变 checkpoint、摘要、日志、部分回执和下一安全动作。运行回执写入 acceptance root，不回写 frozen source commit。可选能力移除或失败时，项目必须只凭规范事件、检查点、事实和快照由默认执行器打开、恢复和继续；不能依赖私有运行时缓存。

首版冻结后发现的 P0/P1 进入新的 RC 候选和版本流程，不解冻已冻结 RC。PDF/PPT、导出、雷达、证据成熟度和监测均只能在后续用户批准版本中恢复；恢复时必须补齐完整合同、实现、测试、视觉证据和跨宿主验收，而不是仅打开一个开关。
