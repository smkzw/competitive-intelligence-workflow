# 竞品调研多 Skill 工作流重构设计规格

状态：待用户书面复核
版本：1.2
日期：2026-08-10
适用范围：A 类适应症竞品 Profile、B 类竞品临床试验结果调研、C 类竞品临床试验方案设计调研
设计依据：用户批准的 D01–D70、工作区全量审计、康哲 `design_v2.md` 与 `design_share_v2.md`

## 1. 规格目的与结论

本规格定义一套可安装在 Codex、Hermes、OMP 及其他具备相应能力的 Agent 宿主上的竞品调研工作流。用户只需选择 A/B/C 中的一种或多种报告、提供适应症，并选择是否生成 PDF、HTML-PPT 和可编辑 PPTX；系统即可启动。

系统不是一次性搜索脚本，也不是把若干提示词串起来的线性流水线。其产品核心是可审计的科学事实与证据系统；A/B/C HTML、PDF 和 PPT 是同一已批准数据版本的受控投影。

最终架构采用：

- 一个可版本化安装包和一个公开入口 Skill；
- 多个内部、边界清晰且可独立测试的领域 Skill；
- 一个由应用持有的类型化控制图；
- 一个本地、确定性的默认执行器，以及可替换的宿主/图运行时适配器；
- 每项目完全自包含的证据、数据库、运行记录、快照和报告目录；
- 三个相互独立、各自完整的大型多页面报告门户；
- 原生站点式 HTML、原生 PDF、HTML-PPT 和 PPT Master 可编辑 PPTX 四条独立交付轨。

旧工程不原地改造。新系统在独立目录净重构；新系统完成全量验收和迁移后，删除旧运行工程。

## 2. 不可妥协的产品约束

1. 关键证据未达到对应报告门槛时，不生成正式报告，也不生成草稿或占位报告。
2. 仅纳入创新药，包括创新抗体、多抗、融合蛋白、ADC、创新小分子、PROTAC、分子胶、创新多肽、RNA 药物、基因/细胞治疗等；不纳入抗组胺药、csDMARDs、传统激素、仿制药、生物类似药及仅换剂型或新增适应症的传统活性成分。组合方案只有在至少一个组件独立通过创新本体时才进入竞品宇宙，且组件事实与方案级结果必须分开。
3. `缺失`、`明确为 0`、`不适用`、`未公开`、`检索后未找到`、`技术不可用`、`访问受限`和`证据冲突`必须是不同状态。
4. 技术失败不得被记作“没有证据”。在阻断前必须完成与失败类型匹配的多路径恢复和独立遗漏检查。
5. HTML 是每个所选报告的默认交付物。A、B、C 分别生成独立门户，不生成跨报告超级门户。
6. 每个门户都是内容完整的多页面站点，不能以首页、卡片摘要、Top-N 或单页长文档替代完整内容。
7. 报告正文只呈现医学和竞争情报，不呈现搜索日志、证据门槛计算、重试诊断、提示词或内部工作流状态。
8. 面向资深医学经理，报告文案采用简洁、专业、中文原生的表达；除行业通用缩写外，不使用中英混杂的系统术语或提示词式标签。
9. HTML、PDF、HTML-PPT、PPTX 均从同一不可变报告快照生成，但分别遵循格式原生的内容组织和验收门槛，不能相互冒充或静默降级。
10. 系统不得把模型记忆、聊天记录、工作流框架状态或可视化页面反向当作科学事实来源。

## 3. 用户合同

### 3.1 最小输入

入口只要求：

- 报告类型：A、B、C，可多选；
- 适应症；
- 输出选择：PDF、HTML-PPT、可编辑 PPTX，可独立多选。

站点式 HTML 默认启用，不需要单独选择。除非适应症名称确实存在无法安全消解的歧义，系统不得在启动前要求用户编写研究方案、列举竞品、配置来源或设定证据等级。

默认数据截止日为项目合同创建时在合同所声明时区内的自然日；用户可以在启动语句中可选指定历史截止日，但这不是必答问题。获取时间、来源发布日期/生效日期和数据截止日分别保存；截止日之后首次披露的信息进入后续刷新，不静默混入当前快照。

项目可以可选加载只提高、不降低系统科学底线的版本化门槛覆盖，例如更严格的新鲜度、来源类别或附加关键字段。覆盖不是启动前的必答配置；项目启动后新增或改变覆盖时，必须形成新合同版本并重算受影响门槛。

### 3.2 默认范围

- 地理范围：全球；中国与境外的开发、注册和监管状态分轨展示。
- 生命周期：上市、申报、临床、公开披露的临床前、暂停/终止/撤回/放弃项目均保留并分层。
- 核心竞品：所有在检索截止时间内公开可识别、与目标适应症明确相关的创新治疗项目；不得以 Top-N 截断。
- 邻近观察：机制相关但适应症关系未确立的项目可以独立观察，不进入核心比较。
- 试验角色：B/C 核心层以目标适应症 II 期、III 期、无缝 II/III 期及关键/注册相关干预性试验为主；罕见病、肿瘤或加速开发中实际承担决策证据的早期试验可有理由地进入核心层。
- 默认排除健康志愿者、纯 PK/生物等效性、无关适应症、一般观察性及 EAP/同情使用研究。只有为已命名的安全性、监管或特殊人群问题提供不可替代证据时，才可带理由进入支持层；C 中早期试验只有明确关联剂量、终点、适应性设计、人群、估计目标或注册开发逻辑时才进入设计分析。
- 传统药物可以作为背景治疗、救援治疗或对照出现在试验事实中，但不因此获得竞品档案或进入创新药排序、矩阵和宇宙计数。

### 3.3 用户可见状态

宿主 Agent 的主对话只呈现：已启动、重要里程碑、需要用户资料、部分报告完成、阻断和全部完成。搜索回执、覆盖计算、重试、诊断和渲染日志写入项目文件，不在对话中持续刷屏。

### 3.4 用户协助

只有在所有安全、适用的自动路径用尽后，系统才可请求用户协助。请求必须一次说明：

- 哪个产品、试验或字段阻断了哪个报告；
- 系统已经尝试了什么；
- 阻断属于无公开证据、权限/登录、技术故障还是工具能力缺失；
- 用户需要下载或提供什么；
- 原文和附件链接；
- 文件应放入的唯一目录。

用户不负责重命名、分类、解压或移动到内部资料库。Agent 依据内容和标识符匹配文件，完成校验、确定性重命名、归档和重新抽取。

## 4. 系统边界与分层架构

系统由六层组成：

| 层 | 职责 | 不得承担 |
|---|---|---|
| 项目包 | 保存项目配置、证据、数据库、事件、快照和产物 | 不依赖中心数据库或私有云会话 |
| 科学真源层 | 保存实体、证据片段、事实、声明、冲突和版本 | 不保存页面布局或宿主聊天状态 |
| 控制图层 | 决定节点、边、分支、重试、中断、停止和影响传播 | 不直接拥有临床事实 |
| Skill 能力层 | 提供检索、摄取、抽取、分析、渲染、质控等能力 | 不自行决定全局流程或绕过门槛 |
| 报告应用层 | 生成 A/B/C 独立信息架构和交互视图 | 不建立第二套事实库 |
| 交付验收层 | 生成并验收 HTML、PDF、HTML-PPT、PPTX | 不以“文件存在”代替内容和视觉验收 |

科学真源、执行状态和生成产物必须物理或逻辑分离。运行时重放只能改变执行状态；已锁定事实、已批准修订和已交付快照只能由明确的新版本取代，不能静默覆盖。

## 5. Graph Engineering 适用性与技术路线

### 5.1 采用判断

本系统适合控制图，而不适合固定线性 Skill 链，原因是它同时存在：

- A/B/C 报告分支和各自证据门槛；
- 多来源并行检索、按缺口回环和信息增益停止条件；
- 网络、权限、解析、工具能力等不同恢复路径；
- 用户文件中断和修订批准中断；
- 多格式独立生成、独立验收和部分交付；
- 增量刷新、影响分析、局部重建及历史版本保持；
- 科学、视觉和包验收的独立否决节点。

这里的 Graph Engineering 指控制图：谁执行、何时执行、看到什么、输出到哪里、谁能否决、什么条件停止；不是以实体关系做检索的知识图谱。

### 5.2 路线比较

| 方案 | 结论 | 原因 |
|---|---|---|
| 线性多 Skill 串联 | 否决 | 无法可靠表达门槛、回环、中断、部分交付和影响传播 |
| 强绑定某个图框架/中心服务器 | 否决 | 框架状态会侵入科学真源，削弱跨 Agent 与离线可移植性 |
| 应用持有类型图，运行时可替换 | 采用 | 科学状态稳定；默认执行器简单；需要时可接入成熟图运行时 |

默认交付一个本地确定性执行器。LangGraph 可作为可选适配器：其官方模型支持状态、节点、边、循环、检查点和中断，且代码采用 MIT 许可；但 LangGraph、LangSmith 或 Agent Server 均不得成为基础项目打开、恢复、验证和渲染的前提。任何被采用的运行时版本必须在安装包清单中固定，并通过同一适配器一致性测试。

### 5.3 图工程约束

- 默认使用单 Agent 节点；只有真实并行、不同工具/上下文或独立否决需要时才增加节点。
- 每个节点具有类型化输入/输出、前置条件、完成谓词、读写范围、重试与超时、错误分类、幂等键、成本和运行记录。
- 每个重要完成声明至少具有一个非模型锚点：真实文件、执行测试、数据库查询、浏览器渲染、Office 渲染或源文档交叉核对。
- 生产节点不能自行宣布完成；独立验证节点拥有接受或否决权。
- 检查点重放可能重新执行节点，因此文件移动、发布、交付、修订批准和删除等副作用必须幂等或位于结构化闸门之后。
- 已验证完成状态不可被并发中的猜测覆盖；任何修订形成新版本并保留前版。
- 应用定义并版本化唯一的规范检查点/事件格式。可选图适配器可以写入私有运行缓存，但该缓存不得成为打开、恢复、验证或渲染项目的必要条件；适配器一致性测试必须证明由可选适配器启动的项目能只凭应用规范状态由默认执行器继续。

## 6. 安装包与跨 Agent 适配

### 6.1 包形态

用户安装一个版本化工作流包，调用一个公开入口 Skill。包内包含：

- 内部领域 Skills；
- 类型定义、JSON Schema 和受控词表；
- 创新药本体与来源政策；
- A/B/C 版本化 `GateSpec`、字段适用性规则、终点/时间窗兼容表和来源策略；
- 控制图定义和默认执行器；
- Codex、Hermes、OMP 宿主适配器；
- HTML、PDF、HTML-PPT、PPTX 渲染器接口；
- `design_v2.md`、`design_share_v2.md`、正式 Logo 和可再分发资产；
- 数据库迁移、基准案例、测试和验收工具；
- 包清单、组件版本、摘要和兼容范围。

缺少内部 Skill、设计规范、必要资产或版本不兼容时，预检失败；不得以混合版本继续执行。

### 6.2 能力预检

最小输入后、检索和渲染前，入口按用户选择检查：文件读写、网络/HTTP、浏览器、PDF/文档摄取、必要 OCR、脚本运行、真实浏览器验证、原生 PDF、HTML-PPT、PPT Master、目标 Office 验证等能力。

能力缺失只阻断真正依赖它的报告阶段或输出。例如，PPT Master 缺失不得阻断已满足条件的 HTML，但可编辑 PPTX 必须保持阻断，不能替换成 HTML-PPT 或图片页 PPTX。环境修复后只重跑失败能力及其下游节点。

### 6.3 宿主适配器合同

宿主适配器只负责：调用工具、映射中断、发送必要状态、解析用户恢复信号、提供文件路径和返回产物。它不得改变来源权重、证据门槛、错误分类、快照内容和验收标准。Codex、Hermes、OMP 必须通过相同的能力发现、状态语义、恢复、幂等和失败一致性测试。

## 7. 每项目自包含工作区

建议逻辑结构如下，具体名称可在实施计划中保持等价但不能改变边界：

```text
project/

  state/project.sqlite
  state/checkpoints/
  events/events.jsonl
  evidence/
    raw/<sha256>/
    fragments/
    library/
    manual-inbox/
    quarantine/
  receipts/source_receipts.jsonl
  receipts/download_requests.jsonl
  coverage/A.json
  coverage/B.json
  coverage/C.json
  blockers/<report>/<version>/
  snapshots/evidence/
  snapshots/reports/A/
  snapshots/reports/B/
  snapshots/reports/C/
  reports/A/<version>/
  reports/B/<version>/
  reports/C/<version>/
  logs/status.md
  logs/run_summary.md
  logs/download_requests.md
  logs/diagnostics/
  manifests/artifact_manifest.json
```

工作区必须可移动，不在数据合同中保存机器绝对路径。项目不能隐式读取另一项目的证据、缓存或结论；跨项目材料只有经用户显式导入、保留来源并重新通过身份、时效和证据门槛后才能使用。

`state/checkpoints/` 和 `events/events.jsonl` 执行应用的规范恢复合同；任何宿主或图框架私有检查点均为可丢弃缓存。`corrections/inbox/` 使用 §17.1 的修订建议 schema；`monitoring/inbox/` 使用 §17.3 的变更候选 schema；两者都不能绕过核验和批准。

## 8. 科学真源与类型化数据合同

### 8.1 数据链

唯一允许的科学数据链为：

`实体 -> 来源版本 -> 证据片段 -> 原子事实 -> 声明 -> 可重建视图`

- **实体**：适应症、药物项目/别名、靶点/机制、剂型/模态、组织/关系、试验/队列/组别/干预、终点/时间点/结果、安全性事件、监管事件、交易、专利。
- **来源版本**：不可变的网页、登记记录、PDF、附件、演示、新闻稿或手工下载文件，保留获取时间、版本日期、访问路径、摘要和内容校验值。
- **证据片段**：可定位到登记字段、网页段落、PDF 页/段/表/图/单元格的最小可引用单位。
- **事实**：一个主体的一个字段值，保留原始值、规范化值、单位、人群、时间点、组别、分母、证据片段和状态。
- **声明**：报告可表达的陈述，标明直接证据、确定性计算或综合判断，并列出支持事实。
- **视图**：表格、图、矩阵、排序或文字段落；可随筛选重建，但不能反写事实。

### 8.2 稳定身份

至少定义并持久化 `project_id`、`run_id`、`graph_id`、`node_id`、`entity_id`、`source_id`、`source_version_id`、`fragment_id`、`fact_id`、`claim_id`、`snapshot_id`、`report_id` 和 `artifact_id`。外部药物名、公司名或 NCT 号是标识证据，不直接充当所有内部主键。

### 8.3 事实基本字段

每个事实至少包含：主体、字段、原始表达、规范化值、单位、上下文、组别/队列、人群、时间点或时间窗、分子与分母、来源片段、抽取方法、规范化方法、质量状态、披露成熟度、创建版本和有效/发布日期。任何规范化都不得覆盖原始表达。

### 8.4 证据与缺失状态

不同语义使用不同类型，不能把路由失败写进事实值，也不能把事实未报告写成搜索结果：

- **路由尝试结果**：`success_with_evidence`、`success_irrelevant_only`、`searched_no_evidence`、`not_publicly_disclosed`、`access_or_permission_blocked`、`transient_network_failure`、`rate_limited`、`anti_bot_or_captcha`、`source_unavailable`、`parser_or_schema_failure`、`tool_capability_gap`、`content_truncated`；
- **路由完成性**：`completed`、`not_applicable`、`access_blocked`；`access_blocked` 只能由细粒度诊断和穷尽记录映射而来；
- **事实披露/值状态**：`reported_value`、`reported_zero`、`not_reported`、`below_reporting_threshold`、`not_publicly_disclosed`、`not_applicable`、`conflicting`、`unresolved_due_to_route`；
- **事实审查状态**：`candidate`、`accepted`、`rejected`、`superseded`。

`reported_zero` 必须有明确原文证据；`not_applicable` 必须通过版本化适用性谓词；`unresolved_due_to_route` 必须链接到未解决的路由回执。前端、分析器和导出器读取类型化状态，不使用空字符串、数值 0 或统一的“缺失”代替。

### 8.5 冲突和版本

冲突来源并存，保留时间和适用范围；裁决形成新声明或新事实版本，不删除旧证据。更新信息可以取代、缩窄或反驳旧声明，但必须记录原因。页面只显示当前批准结论，证据抽屉可查看冲突链和历史版本。

### 8.6 本地持久化

不可变原文使用内容寻址文件；结构化实体、事实、声明和关系使用本地 SQLite；运行历史使用追加式 JSONL；证据与报告版本使用不可变清单。SQLite 是应用数据层，不是工作流框架的检查点数据库。

### 8.7 可执行证据门槛

每个报告的系统科学底线以包内版本化 `GateSpec` 表达，而不是由模型临场解释“关键”“足以支持”或“实质影响”。每条规则至少包含：规则/字段 ID、报告类型、对象范围、适用性谓词、必需上下文字段、允许的来源角色与披露成熟度、新鲜度、允许的缺失策略、冲突策略、关键/扩展级别、失败代码和恢复路由。项目覆盖只能增加限制，不能修改或删除系统关键规则。

对一个报告版本，确定性通过谓词为：

`宇宙关闭且非空要求满足 AND 每个范围内对象的每个适用关键单元均 satisfied AND 无未决关键冲突 AND 独立科学质控 accepted`

关键单元只有在以下情形才为 `satisfied`：存在达到规则所需来源、成熟度和上下文的已接受事实；或适用性谓词确定为 `not_applicable`。`not_reported`、`not_publicly_disclosed`、`searched_no_evidence`、访问/技术失败和总完成率均不能自行替代一个必需值；只有规则显式允许的非阻断缺失才可留在扩展层。未能确定适用性时失败关闭。模型可以提出分类或冲突裁决候选，但门槛由规则求值器计算并由隔离质控者接受或否决。

报告候选范围必须在求值前锁定；不得删除证据稀疏、结果不理想或门槛失败的产品/试验来获得通过。门槛输出逐对象、逐字段保存适用性、事实 ID、回执、结果和失败代码，覆盖百分比只作描述。A/B/C 的具体最低单元分别见 §12.2、§13.2 和 §14.2。

## 9. 内部 Skill 划分

| Skill 域 | 输入 | 主要输出 | 禁止行为 |
|---|---|---|---|
| 入口与预检 | 最小输入、宿主能力 | 项目合同、能力矩阵 | 擅自缩窄竞品或降级输出 |
| 本体与竞品宇宙 | 适应症、创新本体 | 全量分层竞品集合、组件/方案纳排回执 | 用 Top-N 或宣传用语判定创新性 |
| 来源路由与检索 | 缺口、实体、声明类型 | 来源计划、检索回执、候选来源 | 把技术失败记作无证据 |
| 文档摄取与身份 | 文件/网页/登记记录 | 不可变来源版本、身份关系 | 按文件名盲配试验 |
| 抽取与规范化 | 来源片段、字段合同 | 原子事实、术语映射、质量状态 | 覆盖原文或强行合并不等价项 |
| 实体解析与冲突 | 候选实体/事实 | 稳定身份、冲突集合、裁决候选 | 取第一值或按名称相似度下结论 |
| 证据覆盖与门槛 | 报告合同、事实集合 | 缺口账本、通过/阻断决定 | 用总完成率掩盖关键字段缺失 |
| A 分析 | 已锁定 A 快照 | 产品、管线、企业、监管、IP、疗效安全概览视图 | 依赖 B 报告才能完整 |
| B 分析 | 已锁定 B 快照 | 疗效、安全性、基线、亚组和矩阵视图 | 默认排名、Meta/NMA 或合成池化 |
| C 分析 | 已锁定 C 快照 | 精确设计事实和综合判断 | 从论文替代登记设计事实或输出唯一方案 |
| 科学/证据质控 | 事实、声明、视图 | 接受/否决和可审计缺陷 | 自行重写证据以便通过 |
| HTML/PDF/PPT 渲染 | 已批准快照、内容计划 | 独立格式产物和覆盖清单 | 格式间截图冒充或静默删减 |
| 视觉/包验收 | 实际渲染产物 | 验收记录 | 仅凭源码或“无溢出”通过 |
| 修订与刷新 | 修订/变更候选 | 差异、影响集、新快照 | 未经用户批准发布修订 |
| 可选监测 | 既有项目、可变来源 | 变更候选 | 自动改事实或发布报告 |

每个 Skill 通过稳定合同被控制图调用；内部实现可以替换，输入、输出、错误和恢复语义必须保持兼容。

本体输出必须保存每个组件的 `component_eligibility`、方案的 `regimen_eligibility`、本体规则/版本、证据片段、边界原因和审查回执。改良制剂、重定位、固定复方或其他边界项目没有匹配规则时进入审查，不能由自由文本直觉纳排。研究分类另存 `study_role` 和 `publication_role`：核心、特殊核心、支持、默认排除及理由均可审计；一篇事后分析论文不能改变其母试验角色。

## 10. 主控制图

### 10.1 新建报告图

1. 接收最小输入并建立项目合同。
2. 运行安装包和宿主能力预检。
3. 解析适应症身份，建立创新药本体和全球分层竞品宇宙。
4. 按实体、声明类型、地域和报告类型生成来源关系图。
5. 并行执行适用来源路由，保存回执和不可变来源版本。
6. 摄取、身份解析、结构化抽取、规范化和冲突登记。
7. 分别计算 A/B/C 关键字段覆盖与缺口。
8. 对失败报告执行缺口驱动恢复；已成功的共享证据保持锁定。
9. 通过双重穷尽测试后，若仍缺关键证据，生成 §10.5 证据不足审计包并按需中断用户；不得进入报告渲染。
10. 对通过门槛的报告建立候选事实/声明快照，并执行独立科学质控。
11. 锁定不可变报告快照，A/B/C 分别分析并建立页面数据。
12. 生成站点式 HTML；按用户选择并行生成 PDF、HTML-PPT、PPTX。
13. 每个格式独立完成确定性、内容覆盖和真实渲染验收。
14. 产物按通过顺序交付；所有选定产物均通过后项目才标记完成。

### 10.2 分离状态机

不得用一个含糊的 `status` 表达全部状态：

- 项目/运行：`running`、`awaiting_user`、`partially_delivered`、`partial_delivery_blocked`、`blocked`、`complete`；
- 报告证据：`queued`、`collecting`、`recovering`、`awaiting_user`、`scientific_qc`、`snapshot_locked`、`evidence_blocked`、`superseded`；
- 格式产物：`queued`、`generating`、`quality_check`、`passed`、`delivery_ready`、`blocked`、`superseded`；
- 下载请求：`awaiting_user`、`file_detected`、`matched`、`accepted`、`needs_re_download`、`not_required`；
- 修订审批：`submitted`、`needs_evidence`、`rejected`、`validated_pending_user_approval`、`approved`、`published`。

合法迁移至少遵循下表；任何未声明迁移均拒绝并写入事件日志：

| 对象 | 迁移 | 必要守卫 |
|---|---|---|
| 项目 | 新建 -> `running` | 项目合同和包/能力预检记录已建立 |
| 项目 | `running` -> `awaiting_user` | 适用的科学双重穷尽或技术恢复穷尽通过、关键缺口仍在、§10.5 审计包和精确请求已写入 |
| 项目 | `awaiting_user` -> `running` | 用户材料已接受或环境修复已确认；只重排失败节点及下游 |
| 项目 | `running` -> `partially_delivered` | 至少一个选定产物 `delivery_ready`，且仍有选定对象处于可继续的非终态 |
| 项目 | `partially_delivered` -> `partial_delivery_blocked` | 至少一个产物已交付、至少一个选定对象已穷尽并阻断，且没有仍运行的选定对象 |
| 项目 | 任一未完成态 -> `blocked` | 尚无产物可交付，至少一个选定报告/产物终态阻断，且没有仍运行的选定对象 |
| 项目 | 任一未完成态 -> `complete` | 每个选定报告的 HTML 及每个选定可选格式均 `delivery_ready` |
| 项目 | `blocked`/`partial_delivery_blocked` -> `running` | 显式用户材料、环境修复或新项目合同版本重新打开对应节点 |
| 报告证据 | `queued` -> `collecting` -> `recovering` | 已锁定候选范围；首次门槛失败才进入缺口恢复 |
| 报告证据 | `collecting`/`recovering` -> `scientific_qc` | `GateSpec` 确定性通过且候选快照已建立 |
| 报告证据 | `scientific_qc` -> `snapshot_locked` | 隔离质控接受；否决则回到可修复节点或 `evidence_blocked` |
| 报告证据 | `collecting`/`recovering` -> `awaiting_user` | 适用恢复已穷尽、§10.5 审计包和下载/材料请求已建立 |
| 报告证据 | `awaiting_user` -> `recovering` | 所需文件已 `accepted`、权限/环境已恢复或用户提供了可核验新线索 |
| 报告证据 | `collecting`/`recovering`/`scientific_qc` -> `evidence_blocked` | 关键单元仍失败、适用恢复及独立审查已穷尽，且当前没有可继续用户动作；科学质控否决若仍可修复则只能回 `recovering` |
| 格式产物 | `queued` -> `generating` -> `quality_check` -> `passed` -> `delivery_ready` | 依次具有锁定报告快照、构建产物、确定性/覆盖/真实渲染接受记录、原子发布及清单摘要 |
| 格式产物 | `generating`/`quality_check` -> `blocked` | 格式特定技术/内容/视觉恢复已穷尽并保存失败证据 |
| 格式产物 | `blocked` -> `queued` | 环境/生成器已修复或新合同版本明确重新打开；继续使用同一快照，除非报告快照已另行修订 |
| 下载请求 | `awaiting_user` -> `file_detected` | 唯一收件箱发现新文件或用户发出“已下载”信号并完成库存 |
| 下载请求 | `file_detected` -> `matched` | 摘要、元数据、标题页和标识符形成唯一高置信内容匹配 |
| 下载请求 | `file_detected`/`matched` -> `needs_re_download` | 文件不完整、为登录/错误页、身份歧义、错误附件或不可读；文件留在隔离区并记录原因 |
| 下载请求 | `matched` -> `accepted` | 类型、完整性、身份、摘要、父子关系和规范命名均通过，且原子归档完成 |
| 下载请求 | `needs_re_download` -> `awaiting_user` | 已生成去重的新请求或更精确下载说明 |
| 下载请求 | 任一未接受态 -> `not_required` | 其他已接受证据已关闭原缺口，保存取消理由；不能用来掩盖仍失败的关键单元 |
| 修订审批 | `submitted` -> `needs_evidence`/`rejected`/`validated_pending_user_approval` | Agent 完成来源身份、上下文、冲突和影响验证并保存处置理由 |
| 修订审批 | `needs_evidence` -> `submitted` | 新证据作为同一建议的新事件附加，原提交历史不覆盖 |
| 修订审批 | `validated_pending_user_approval` -> `approved`/`rejected`/`needs_evidence` | 报告所有者作出显式决定；验证本身不能批准 |
| 修订审批 | `approved` -> `published` | 新快照、受影响产物重建和独立质控全部通过；发布使用批准 ID 幂等 |
| 任一版本对象 | 已接受态 -> `superseded` | 新版本已明确取代；旧版本保持只读和可复现 |

`partially_delivered` 表示仍在继续，`partial_delivery_blocked` 表示已有交付但剩余选定对象已经穷尽阻断；两者不能混用。一个报告被阻断不自动阻断另一个已满足门槛的报告，一个格式失败不撤销已通过格式。修改原始输出选择属于新项目合同版本，不得把放弃的产物静默算作完成。所有迁移保存触发事件、守卫证据、执行者、幂等键和前后版本；重放同一事件不得重复发布、移动、批准或删除。

### 10.3 双重穷尽测试

用户中断前必须同时满足：

- **路由完成**：所有必需来源路由为完成、不适用或可证明的访问阻断；针对缺口完成别名、多语言、标识符链、前后向引用、替代访问、登记—论文—监管关联、文档/OCR 和实体解析路径。
- **信息增益饱和**：连续两轮不同的缺口驱动恢复都未获得可改变门槛的新证据，或剩余信息已被证明为私有、未公开或权限限定。

每个失败关键字段都实例化版本化策略矩阵；每个适用单元必须有 `completed`、`not_applicable` 或 `access_blocked` 回执。查询/标识符/访问方式摘要相同的重复尝试不形成新单元或新一轮。信息增益定义为新增证据片段/事实足以改变关键单元结果、减少关键冲突集或改变适用性；独立审查节点逐单元检查缺口，不能用一句“没有实质遗漏”放行。

每份 `source_receipt` 至少保存路由/策略单元 ID、实体/缺口/声明域、查询或标识符、语言、访问方式、尝试与时间戳、响应/错误类、完整性检查、替代路径、取得内容摘要、诊断置信度和父重试/恢复轮次；不得含凭据。每份 `evidence_gap` 保存 `GateSpec`/对象/字段、当前状态、所需上下文、候选来源、已完成策略、信息增益差异和下一个合法动作。

### 10.4 技术恢复

可重试故障至少进行三次有间隔或退避的同路径尝试，并执行至少两条适用替代路径。限流、验证码、权限、页面变更、解析失败、内容截断、代理/DNS/TLS/HTTP 和工具能力缺失分别进入不同诊断分支。持久技术阻断需要独立诊断；成功节点和已锁定证据不重跑。

### 10.5 证据不足审计包

所有报告门槛失败统一生成 `blockers/<report>/<version>/` 下的证据不足审计包，包含机器 JSON 和简洁 Markdown。它是恢复/审计产物，不是报告、草稿、报告首页或占位门户，不得进入报告渲染器。

审计包至少包含：报告和合同版本、失败的 `GateSpec`/对象/字段、事实和缺失状态、受影响产品/试验、全部适用路由与回执、两轮信息增益差异、独立遗漏审查结论、技术诊断、仍存不确定性、是否需要用户、最小用户动作、原文/附件链接、唯一投递目录和可恢复节点。若 A 没有任何适格创新项目、B 没有任何达到最低门槛的适格结果试验、或 C 没有任何达到临床设计核心门槛的适格试验，双重穷尽后也只交付该审计包，不生成空报告；A 只有临床前项目或 C 只有一项适格核心试验并不自动失败。

## 11. 来源与证据路由

### 11.1 基本原则

来源权威按声明类型、地域和披露阶段确定，不设一个适用于所有字段的简单总排名。每项证据保留来源身份、文档角色、披露成熟度、发布日期、获取版本和精确定位。

包内版本化声明—来源策略至少覆盖：

| 声明域 | 优先直接路线 | 补充/交叉路线 |
|---|---|---|
| 药物身份、机制、创新纳排 | 监管文件、官方登记、同行评议机制资料、可归属公司资料 | 指定行业来源及其他可核验专业资料 |
| 试验身份、设计、状态 | 官方登记及历史/附件、监管材料、试验方案/SAP | 论文高层方法和公司/会议资料只作对应字段交叉核验 |
| 数值疗效与安全性 | 登记结果、监管审评/说明书、主要试验论文及必要附件 | 会议、公司 Topline 和 §11.4 指定来源，保留披露成熟度 |
| 基线与受试者完成/处置 | 登记结果中的基线特征和受试者流转、监管审评/公开 CSR 类材料、主要试验论文及必要附件 | 会议或公司数值披露仅支持其明确报告的字段；不同分母、时间窗和定义不得静默合并 |
| 监管与开发状态 | 各适用司法辖区监管机构和官方登记 | 公司披露及 §11.4 允许的中国状态资料 |
| 企业关系与交易 | 公司公告、证券披露、交易文件 | §11.4 指定来源和可核验专业资料 |
| 专利与保护 | 官方专利/监管独占记录及可核验法律文件 | 公司披露和 §11.4 指定来源；不把推断写成法律结论 |

策略对每个声明域定义可直接采纳、仅交叉核验、仅线索和禁止替代的来源角色。直接采纳不等于自动胜出；关键冲突必须保留并按适用范围、直接性、版本和发布日期进入裁决。

### 11.2 境外与全球路线

- ClinicalTrials.gov 是境外竞品的必查路线，也必须检查中国来源产品；需读取登记设计、历史版本、已登记结果和关联论文。
- 当产品地域、监管事件或登记标识符表明其他司法辖区适用时，必须进入该辖区官方试验登记和监管路线；ClinicalTrials.gov 是全球基线而不是其他适用官方路线的替代品。
- 从试验标识符和登记页关联论文开始，再使用 NCT 号、其他登记号、药物别名在 PubMed 等学术路线扩展。
- 论文必须分类为主要 II/III 期或关键试验报告、亚组/事后分析、汇总分析、长期延伸、二次分析或综述；后者不能替代主要报告。
- 监管审评、说明书、学术会议、Topline 新闻稿和公司披露按对应声明类型进入证据链。

### 11.3 中国路线

必查 CDE、`chinadrugtrials.org.cn`、丁香园用药助手，并交叉检查 ClinicalTrials.gov、PubMed、监管材料、会议、公司披露及指定行业来源。NMPA/CDE 与登记资料的版本、审评/批准/撤回/暂停等事件必须分开。中国与境外的状态分别保存，不能以一地状态推断另一地状态。

### 11.4 指定权威微信公众号

`医药魔方info`、`药融圈`、`丁香园Insight数据库`、`米内网`、`中国药审`的文章可直接支持以下声明域：主要疗效和关键安全性、中国开发与监管状态、企业关系与交易、专利。

文章必须能定位到明确产品/试验/事件，保留账号、标题、日期、链接、内容快照和精确位置。该资格允许直接采纳，不以“必须先取得上游文件”为前提；但与更直接或更新的官方资料冲突时仍进入冲突门，不得静默覆盖。事实强制保存 `authoritative_secondary_disclosure`、`preliminary_result` 或其他准确来源角色/披露成熟度，不得误标成同行评议或监管审评证据。

### 11.5 论文、补充材料、试验方案与 SAP

- B 报告先使用登记结果、主要论文和监管材料覆盖关键疗效、安全性及 §13.6 的基线核心字段，并同步抽取登记结果或公开材料中的受试者流转与完成情况。
- 只有仍存在具体阻断字段且补充材料很可能包含该字段时，才把补充材料升级为必要获取或用户辅助下载；若既有材料已覆盖关键疗效、安全性和基线核心字段，不获取补充材料、不标记其缺失，也不降低完整性。
- §13.7 的试验完成情况字段全部为非阻断字段。开放可访问且预期信息增益明确时可以继续自动获取附件，但这些字段单独缺失不得触发用户辅助下载、阻断 B 或把技术未获得误写成科学上的零。
- C 报告的设计事实以官方登记平台及其历史和附件为主；论文仅作身份关联和高层方法交叉核验。
- 公开试验方案/SAP 有则获取并版本化；没有时，只要官方登记字段足够覆盖关键临床设计，C 可以通过并注明“仅有注册登记信息”。
- 统计细节不是 C 的阻断重点；缺失的分析集、模型、检验、效应量、多重性、估计目标、缺失数据和样本量假设按真实披露状态标注，不得推测。

### 11.6 指南与首页终点依据

CDE 与 FDA 使用平行监管轨，不设普遍优先级。每条指南依据保存司法辖区、发布机构、文档标题、最终/草案状态、版本或发布日期、适用人群与研发语境、精确章节/页码、捕获版本和是否已废止；已废止文件只保留历史，不驱动当前默认。草案可以带明确标签展示，不能伪装成最终指南。

竞品共识以锁定的适格核心试验集合为分母；同一试验的共同主要终点可以分别计入。一个终点族在至少两项试验的集合中由严格多数试验作为主要终点时标为“多数竞品采用”；若不存在严格多数，可显示命中数最高且至少命中两项试验的“最常采用”族，但不得标成多数。分母、命中试验 ID、终点原始角色和合并理由写入 `endpoint_basis`。CDE/FDA 对齐的族合并展示并携带全部标签；适用人群、定义或研发语境实质不同的族分列。跨产品提取可以包含次要/探索终点，但不改变其原始角色，也不反向增加“主要终点采用”计数。

### 11.7 用户辅助下载与自动摄取

自动路线穷尽后，每个下载请求保存稳定请求 ID、阻断/非阻断优先级、产品和试验 ID、NCT/其他登记号、PMID/DOI（如有）、文档角色、精确标题、发布者/来源、原始落地页和附件链接、所缺字段/门槛、请求原因、唯一 `manual-inbox` 目录及 §10.2 生命周期。多个请求合并为一份简洁下载列表，用户只按发布者原文件名下载并放入该目录。

Agent 计算摘要、检查类型/完整性、读取嵌入元数据和标题页，以标识符与内容匹配请求；重复、部分下载、登录跳转、HTML 错误页和不确定匹配留在隔离区。接受后，规范文件名由稳定试验/文档标识、文档角色、版本/日期和摘要确定，原文件名保留在元数据；附件具有独立文档 ID 和父文档链接。移动、解压、重命名、归档和重抽取使用幂等/原子操作，用户不承担这些步骤。

## 12. A 类报告：适应症竞品 Profile

### 12.1 产品目标

A 是目标适应症下全部创新治疗项目的完整开发档案，不是若干明星产品卡片，也不是销售预测或市场模型。它覆盖身份、机制、模态、开发阶段、试验组合、关键疗效和安全性、监管、企业关系、交易及可公开核验的专利信息。

销售、价格、医保/支付、市场份额、收入预测、流行病学商业预测和专有商业策略不属于 A 的完成门槛；公开资料中的相关事实只能作为可选背景，不能改变产品性质。

### 12.2 证据门槛

A 的门槛按产品成熟度逐项判断，不能用一个总完成率掩盖关键字段缺失：

| 成熟度 | 关键字段 |
|---|---|
| 所有项目 | 规范身份与别名、创新本体纳排、靶点/机制、模态、当前开发者/原研方、适应症关系、中国和境外最高阶段/状态及日期 |
| 临床项目 | 上述字段，加适用的核心试验身份、开发角色和状态 |
| 申报/上市/终止项目 | 上述字段，加适用的申报、批准、撤回、终止或放弃事件及地域 |
| 已公开结果的成熟项目 | 上述字段，加 A 概览最低疗效记录、安全性摘要记录及其组别、对照、时间点/窗口和分母 |

`result_bearing` 的确定性触发为：官方登记已发布结果，或监管材料、主要试验报告、会议/公司数值披露、§11.4 指定来源出现可归属该适应症试验的数值结果。触发后，每个成熟项目至少需要一项适格锚定试验、一个可解释的核心疗效终点记录和一个 TEAE 或 SAE 数值摘要记录。疗效记录必须含原始定义、方向、单位、时间点、分析人群、治疗组、适用时的对照组和分母；安全性记录必须含事件定义、时间窗、治疗组、适用时的对照组和分母。默认安全性摘要各行还必须有报告值/零或准确的未报告/阈值状态，不能以空白代替。

临床前项目不因没有试验而失败，未合作项目不因没有交易而失败。早期项目可以显示“暂无公开结果”。如果 `result_bearing` 项目未达到上述最低记录，A 门槛失败；不得把该产品删除后继续生成。一个只有“Results posted”标志但值不完整的项目仍进入恢复，而不是退回无结果层。

分子参数、详细制剂、交易金额、完整专利族、推断性开发策略等是非阻断扩展字段，但任何正面陈述仍须达到自身证据门槛。非阻断缺口在详情和证据页保留真实状态。

### 12.3 门户信息架构

A 至少包含以下页面族；数据量增加时允许分拆更多页，不允许删除页面责任：

1. **首页**：创新药全景、靶点/模态/阶段结构、中国与境外状态、关键变化、图在前的疗效比较、安全性热图及疗效—安全性气泡矩阵。
2. **竞争格局**：全部项目的目标、模态、阶段、地域、生命周期和开发状态，可切换管线图、时间线、矩阵和完整表。
3. **产品总览**：所有项目的可筛选事实表与比较视图，不以 Top-N 截断。
4. **产品档案**：每个产品独立详情，覆盖别名、机制、模态、分子/给药、组织关系、开发时间线、试验组合、关键结果与风险、监管、交易及专利。
5. **临床开发组合**：产品—试验—地区—阶段—状态关系及核心试验下钻。
6. **疗效与安全性概览**：关键终点和安全性维度的独立分析页，支持 D53–D56 的筛选、图表—表格同步和证据抽屉；不复制 B 的全部终点和 AE 库。
7. **中国与全球监管**：申报、批准、审评、撤回、暂停/终止及差异化状态时间线。
8. **企业与交易**：原研、开发者、许可方/被许可方、合作、并购、地域权益和公开交易条款。
9. **专利与保护**：可核验专利族、范围、到期或独占信息；专利和监管独占分开表达。
10. **历史与边缘观察**：暂停、终止、撤回、放弃项目及邻近机制观察层。
11. **证据与局限**：仅保留影响医学解释的简洁限制、来源分类和报告方法；完整搜索/重试日志仍在项目日志中。

### 12.4 疗效与安全性概览

默认按靶点分组，每个产品锚定一项最成熟、符合研究角色的核心试验。疗效图显示所选常用核心终点的治疗组与安慰剂/对照组结果；安全性使用多维热图；气泡图使用一个当前选中的核心疗效终点、原始 TEAE 发生率和治疗组样本量。TEAE 轴倒序映射并明确标注“向上 = 发生率更低 = 观察到的安全性位置更有利”。用户可以切换锚定试验和维度，但系统不跨试验自动池化，也不生成默认名次或综合分数。

A 单独运行时必须自行取得该概览所需证据；A+B 同时运行时复用同一不可变事实快照，但 A 不依赖 B 页面才能理解或打开。

## 13. B 类报告：竞品临床试验结果调研

### 13.1 产品目标与试验范围

B 用于快速判断不同创新药的潜在疗效信号和安全性风险。核心比较层纳入目标适应症中有结果的 II/III 期、关键或注册相关试验；早期、延伸、亚组、事后、真实世界等进入支持层并明确角色，不能与核心证据等权呈现。

健康志愿者、纯 PK/生物等效性、无关适应症、一般观察性及 EAP/同情使用研究默认排除。它们只有为一个已命名的安全性、监管或特殊人群问题提供必要证据时，才带 `inclusion_rationale` 进入支持层。罕见病、肿瘤或加速开发的早期特殊核心必须保存其批准/决策证据角色；试验角色与论文角色分别保存。

B 不执行 Bucher、MAIC、STC、Meta 或 NMA，不生成安全性排名或疗效—安全性综合分数，也不默认排列疗效名次。用户可在明确的终点/时间窗桶内主动按方向正确的疗效信号排序；该顺序只是可逆视图状态。

### 13.2 关键证据门槛

每项进入核心比较的结果试验至少满足：

- 试验身份、阶段和研究角色；
- 目标人群、队列/组别、治疗和对照身份；
- §13.6 定义的组别基线样本量、年龄、性别及至少一个适应症特异疾病严重程度锚点；
- 至少一个适应症核心疗效终点的原始定义、方向、单位、评估时间、分析人群、治疗组结果、对照组结果（适用时）及分母；
- 任何展示的组间差值、相对效应或置信区间均可由来源直接支持或确定性复算；
- 安全性最低记录：至少一个 TEAE 或 SAE 数值记录，含定义、时间窗、治疗组、适用时的对照组发生率及分母；
- 结果来源角色、披露成熟度和精确定位。

TEAE、SAE、AESI、死亡、3 级及以上 AE、导致停药 AE 和常见 AE 的默认单元均须保存报告值/零或准确的未报告、低于报告阈值、不适用状态；只有上述最低数值记录和适用的项目 `GateSpec` 单元是阻断项。适应症/靶点/模态特异 AESI 由版本化项目适配器定义，并与来源自定义 AESI、SMQ 聚合分别保存来源、范围、版本和映射方法。

基线核心门槛按每项核心试验的每个可比较研究组判断，明确包括治疗组与安慰剂/阳性对照组；单臂试验按其唯一研究组判断。年龄允许来源报告的均值、中位数或有明确分母的年龄分层形式，性别保留来源分类，疾病严重程度锚点由适应症 `GateSpec` 版本化定义。每个单元必须携带基线分析人群/分母、统计形式、单位、基线时间定义和精确证据位置；多臂试验只报告合并总体而无组别值时不能伪装为组别覆盖。适用字段穷尽后仍未公开即阻断 B，不能以总体值、估算值或其他试验值替代。

§13.7 预定义的全部试验完成/处置字段，包括筛选、筛败、随机、接受治疗、完成治疗、完成研究、停止治疗、退出研究、失访、上述主要原因、依从性、补救治疗、禁用药，以及 PD 的受试者数/事件数，均为强制建模但非阻断字段。每个预定义字段必须保存数值或 §8.4 对应的准确缺失/披露状态；任一或全部字段单独未公开均不使 B 失败，不得写空白、不得记为 0，也不得单独触发用户辅助下载。

无对照试验可以按原设计进入支持或特殊核心层，但不能虚构对照。一个已识别的适格核心结果试验若有任一适用关键 `GateSpec` 单元未满足，必须进入恢复；穷尽后仍缺失则 B 阻断，不能删除该试验或产品以获得通过。若目标适应症在截止时间内没有任何达到最低结果门槛的适格试验，交付 §10.5 证据不足审计包，不生成空 B 报告。

### 13.3 疗效比较

- 首页同时展示 CDE/FDA 适用指导原则推荐以及多数核心竞品广泛采用的一个或多个主要终点族。
- 相同或充分接近的终点和约略时间窗只有命中版本化终点/时间窗兼容规则时才进入模糊匹配族。规则固定临床构念、方向、可换算单位、分析形式以及时间窗最小/最大值；每条记录保留原始终点、单位、实际时间点、分析形式、规则 ID 和差异标签。无规则或越界时自动拆分小多图，不能由模型临场合并。
- 某竞品未把该终点列为主要终点，但公开了对应指标时，仍提取并展示，同时保留其原始终点角色。
- 单一时间点默认使用分组柱状图；纵向时间序列使用折线图；有来源效应量与不确定区间时可用不合并效应的森林图。图下紧跟完整数值表。
- 治疗组与安慰剂/对照组始终并列；组间校正信号可作为默认比较量，但不得隐藏原始两组数值。
- 具体疗效页提供全部已抽取终点，用户可按产品、靶点、试验、组别、终点、时间点、分析人群和效应形式多选。

用户主动排序时，只在当前兼容终点/时间窗桶内使用方向校正后的试验内治疗—对照信号作为主键；无对照或不可比记录保持未知/分列，不按零值沉底。原始治疗组、对照组和差异标记始终保留，排序只是可逆视图状态。

如果仪器、单位、定义或效应表达不兼容，自动拆成可比较的小多图，不使用未披露的统一评分或误导性多轴图。

### 13.4 安全性比较

安全性首页和详情页均先图后表。默认多维热图至少覆盖 TEAE、SAE、AESI、常见 TEAE 和发生率；有数据时加入死亡、3 级及以上 AE、导致停药 AE、治疗相关 TEAE。

常见 AE 行取以下并集后，按比较信息量选择约 10–15 行作为默认视图：来源高频事件、任一治疗组发生率至少 5%、任一治疗—对照绝对差至少 5 个百分点，以及适应症/靶点/模态临床上重要事件。完整事件集始终可搜索和展开。

颜色只在相同事件和可比语境内表示发生率高低；数值必须印在单元格中。缺失、未报告、低于来源列示阈值、技术不可用和明确为 0 使用不同的非误导状态。每个产品列默认锚定一项核心试验，允许切换或展开试验子列；系统不合并多项试验，除非权威来源本身报告了综合安全性分析。

术语在许可与字典可用时映射到 MedDRA 首选术语，同时保留原文、语言、版本、映射方法和置信度。MedDRA 不可用或映射不确定时，保守保留来源术语并分开显示，不能用自由翻译强行合并。

### 13.5 疗效—安全性气泡图

默认：横轴为当前选中的常用主要疗效终点且方向统一为越右疗效信号越强；纵轴为原始 TEAE 发生率并倒序映射，明确标注“向上 = 发生率更低 = 观察到的安全性位置更有利”；气泡面积正比于治疗组样本量，半径按 `r = k × sqrt(N/pi)` 计算。

用户可改变疗效终点、效应形式、时间点、分析人群、安全性维度/事件/窗口/分母、气泡大小、产品、试验和靶点。每次变化同步更新坐标、尺度、图例、气泡、表格、提示、证据链接和网址状态。气泡图是二维观察工具，不是综合评分、头对头结论或排名。

### 13.6 基线与人群比较

B 必须提供独立的“基线与人群”页面族，而不是把几行人口学信息塞入试验档案。每个 `baseline_observation` 至少保存：试验、队列、组别、基线分析人群、变量域、来源原名、规范概念、量表/仪器及版本、方向和理论范围、数据类型、统计形式、值、单位、离散度或区间、分类水平/分箱边界、分子/分母、基线时间定义、来源版本与定位、缺失状态、兼容规则和差异标签。

页面族至少覆盖：

- **人口学**：组别基线样本量、年龄、性别；公开时继续纳入种族/民族、地区、体重/BMI 及其他人口学变量；
- **疾病语境**：病程、既往/背景治疗、表型/亚型、既往加重或事件史、相关合并症和生物标志物；
- **基线疾病严重程度**：适应症 `GateSpec` 规定的一个或多个严重度/活动度量表、实验室或临床锚点，以及竞品公开的其他基线严重度指标。

连续变量的均值/标准差、中位数/四分位距、范围或其他统计形式分别保存；不得把均值和中位数混画成同一种估计，也不得凭空生成误差线。分类变量只有在分母明确时计算比例；来源类别不穷尽时不得使用暗示总和为 100% 的堆叠图。年龄分箱边界、性别类别或种族/民族分类不一致时不得自动重分箱、强制二元化或以 100% 减法补造未报告类别。疾病严重程度只有在量表/版本、方向、单位、基线时间和统计形式兼容时进入同一比较图，否则拆成小多图并保留差异标记。

图在前、表在后。连续变量优先使用分组点图/区间图，只有中心值时使用带数值标签的点图或柱状图；分类变量使用分组比例柱状图；严重程度使用兼容量表的小多图。表格保留全部来源值、统计形式、分母和缺失状态。筛选维度以 §15.4 为规范性全集；当前数据域不适用的维度按适用性规则隐藏或禁用，不能误标成数据缺失。基线页至少支持产品、靶点、试验、队列、组别、地区、基线分析人群、变量域、变量、统计形式、量表/单位和披露状态多选；图、表、证据抽屉和网址状态同步。

基线比较只描述试验人群和组别构成，不以跨试验显著性检验、标准化总分或“更容易入组/病情更重”的自由评分替代原始事实。

### 13.7 试验完成情况与受试者处置

B 必须提供独立的“试验完成情况”页面族。预定义字段族至少包括：

- 受试者流转：筛选、筛败、随机、接受治疗、完成治疗、完成研究、停止治疗、退出研究、失访；
- 原因明细：筛败原因、停止治疗原因、退出研究原因及其人数和比例；
- 试验实施：依从性、使用补救治疗、使用禁用药、方案偏离（PD）的人数/事件数和比例；公开时继续保留重大 PD、导致排除的 PD 或来源定义的其他层级。

每条 `trial_disposition_observation` 至少保存：试验、阶段/期间、队列、组别或总体层级、分析人群、规范字段族、来源原名与定义、计量对象（受试者或事件）、统计形式、分子、分母、来源报告比例、可复算比例、分母角色（如筛选、随机、治疗、安全性人群）、时间窗、原因原文与规范原因、原因是否互斥/穷尽、来源版本与定位、缺失状态和差异标签。

“完成治疗”与“完成研究”、“停止治疗”与“退出研究”必须分开；筛败率以筛选人群为语境，不能强行分配到随机组；PD 的受试者数和事件数不能互换；依从性保留来源阈值或计算定义。只有分子、分母和语境明确时才确定性复算比例。原因非互斥或非穷尽时不得绘制暗示整体构成的 100% 堆叠图，也不得把原因比例相加为总退出率。

跨试验默认使用按统一分母角色分面的小多图、分组比例柱状图或点图；单项试验下钻可使用 CONSORT 式流转图。原因构成只有满足互斥且穷尽条件时才使用堆叠图，否则使用独立原因点图/条形图。若当前筛选范围没有任何可绘制数值，图形区改为试验 × 预定义字段的披露状态矩阵，清楚区分未公开、来源未列示、技术不可用、不适用和明确为 0，而不是显示空坐标轴。每个图或状态矩阵下紧跟完整表格，并允许按产品、靶点、试验、阶段/期间、组别、分析人群、字段族、原因、分母角色、时间窗、计量对象和披露状态多选。

本页面族本身为强制产物，但其全部数值字段为非阻断字段。自动路线穷尽后，未公开、来源未列示、技术不可用、不适用和明确为 0 分开呈现；这些中文界面状态必须确定性映射到 §8.4 的既有类型，不得另建相互冲突的缺失枚举。没有数值时仍显示结构化状态，不生成空白单元格、零值或推断性比例。报告主页面只呈现医学解释所需的披露状态；完整搜索路由、尝试和穷尽证据仍留在项目证据/日志包。

### 13.8 门户信息架构

至少包括：首页、疗效、纵向结果、安全性、基线与人群（人口学、疾病语境、严重程度）、试验完成情况（流转、依从性、失访/退出、筛败、补救治疗、禁用药、PD）、试验/暴露语境、亚组与支持证据、产品/试验档案、疗效—安全性矩阵、证据与局限。详情页保留所有终点、安全性事件、基线变量和完成情况字段，不因首页密度而删除。

## 14. C 类报告：竞品临床试验方案设计调研

### 14.1 产品目标

C 提供逐试验、逐字段的设计事实比较，并在事实之上形成设计模式、差异、权衡、风险和多条可选设计路径。只输入适应症时，系统不能输出一个唯一或“最佳”方案；产品特异性建议需要额外的机制、模态、阶段、给药、目标地域和人群/标签意图等背景。

C 以核心研究为中心。默认排除层和支持层再纳入执行 §3.2；早期研究只有保存其对剂量、终点、适应性设计、人群、估计目标或注册开发逻辑的具体依赖和理由时才进入设计分析。

### 14.2 来源与门槛

官方登记平台及其历史版本和附件是设计事实的主要来源。可获得的试验方案/SAP 必须获取和抽取；不可获得时，登记字段足够即可通过，并明确标注“仅有注册登记信息”。论文只能交叉核验身份和公开的高层方法，不替代登记、试验方案或 SAP。

每个核心试验的关键临床设计至少覆盖：

- 试验身份、阶段和开发角色；
- 目标人群和关键入排标准；
- 分组、随机/非随机、盲法；
- 干预、对照、背景治疗、救援治疗；
- 剂量、给药、疗程、随访和延伸设计；
- 主要和重要次要终点、定义及评估时间点；
- 计划或实际样本量；
- 适应症 `GateSpec` 明确列为关键的地区、访视或操作特征。

“关键入排”在规则中展开为可测试字段族，而不是自由判断：完整摄取所选官方登记版本公开的全部入选/排除条目，并对适用的疾病定义/诊断、病程、严重度或活动度量表、既往/背景/救援治疗、洗脱、年龄、实验室/生物标志物及重要合并症规则建立原文和结构化单元。项目适配器可以增加字段族但不能删除系统的完整原文摄取责任；未公开与不适用分开。

分析人群、主要比较逻辑、统计模型/检验、效应量、多重性、样本量假设、估计目标/伴发事件、缺失数据或敏感性分析均为“公开则提取”的非阻断字段；缺失时按真实披露状态标注，不能从常规做法推断。地区、访视或操作特征没有命中版本化关键规则时也属于扩展层，不能由模型临场升级为阻断项。

### 14.3 精确下钻合同

任一设计事实都能按以下路径定位：

`适应症 -> 产品 -> 试验 -> 队列/组别 -> 设计要素 -> 原始字段 -> 量表/评分 -> 筛选或评估时间 -> 运算符/阈值/值/单位 -> 证据位置`

例如，入选标准必须显示某药某试验使用了什么量表、在筛选期还是基线的哪个时间点、采用什么阈值；并能与用户所选竞品的对应量表、时间点和阈值并列比较。

当原始标准确实使用命名量表/评分时，量表、阈值、运算符和时间引用为关键子字段；未使用量表的标准按原文逻辑、时间、值和单位保存，量表字段由适用性规则判为 `not_applicable`，不能伪造评分。只输入适应症的验收样例必须产生至少两条有证据依据的候选设计路径，或明确说明缺少产品特异性背景而不作唯一建议；不得出现单一“推荐方案/最佳方案”结论。

### 14.4 门户信息架构

C 至少提供十二类页面责任，可按实际内容合并导航但不能删除字段能力：

1. 首页：核心设计格局、关键模式和差异；
2. 设计图谱：试验角色、阶段、地区、随机/盲法、组别和疗程全景；
3. 试验档案：逐试验精确事实；
4. 人群与疾病定义；
5. 入选标准；
6. 排除标准；
7. 分组、干预、对照与背景/救援治疗；
8. 终点—定义—时间点矩阵；
9. 访视、疗程、随访与延伸；
10. 样本量、分析集和公开统计设计；
11. 设计模式、异常点、权衡和多路径综合判断；
12. 证据版本与局限。

时间轴、终点矩阵、人群范围图、雷达或其他兼容图形均先呈现图，再提供逐字段事实表。空白不能解释成无随访，未登记不能解释成未实施。

## 15. 跨报告页面与交互合同

### 15.1 康哲站点式 HTML

A/B/C 均执行康哲设计规范的站点式 HTML 轨，不是 1280×720 HTML-PPT，也不是一个无限滚动长页面。每个门户必须实现本报告章节定义的全部页面责任，并至少具有两个互通物理页面、统一粘性站点页眉、当前页状态、全局实体搜索、跨页下钻和每页唯一全局页脚。首页左上及每个内容页的响应式品牌区必须显示经核验的正式 CMS Logo；站点名/标题、导航、搜索和 Logo 分区不得串行、重叠或折行碰撞，窄屏按合同折叠。

运行时为原生 HTML、CSS 和 ES2020+ JavaScript，无 React/Vue 构建依赖；`index.html` 在 `file://` 和静态服务器下均可运行。不得依赖远程字体、远程图片或远程脚本，也不得通过本地 JSON `fetch` 才能显示数据；页面数据使用版本化 `data/*.js` 和 `window.DATA_*` 对象。正式 Logo 随包本地嵌入。

所选包内康哲合同的适用章节、全部 `MUST`/`NEVER`、固定组件/命名、静态与动效冻结、`prefers-reduced-motion`、资源、可访问性和机器验收条款均具有规范效力；本规格的摘要不能放松它们。每次构建清单记录合同角色、摘要、适用章节和逐项闸门结果。

### 15.2 报告文案

标题、模块和结论直接表达适应症、竞品、试验和结果。页眉只保留适应症、报告主题、数据截止/版本和必要控制。`A/B/C`、内部阶段、证据门槛、检索次数、覆盖率、技术诊断和提示词不是报告首页内容。

直接证据、确定性计算和综合判断仍在数据层严格分类；报告中使用“研究结果”“计算结果”“综合判断”等自然中文和紧凑来源入口。`registry-only`、`publication`、`protocol`、`evidence synthesis` 等不作为直白的中英混合标题。

跨试验结论统一使用“潜在疗效信号”“潜在安全性风险”等观察性措辞，并把关键人群、终点、时间窗、对照和暴露差异放在图题、标记或简洁提示中；不能把模糊匹配升级为头对头优效或因果结论。

### 15.3 图形选择和小多图

系统根据数据合同推荐图形：单时间点分类比较用柱状图，纵向数据用折线图，来源给出效应量与区间时用不合并的森林图，多维位置用气泡图或明确归一化的雷达图，精确字段比较使用同步表格。

B 的基线连续变量使用点图/区间图或柱状图，分类变量使用比例柱状图，兼容严重度量表使用小多图；试验完成情况跨试验使用按分母角色分面的小多图、比例柱状图或点图，单试验可使用 CONSORT 式流转图。只有原因互斥且穷尽时才允许 100% 堆叠图。站点式 HTML 和原生 PDF 中所有图形都必须下接同一事实集的完整表格；HTML-PPT/PPTX 执行 §16 的视觉优先合同，只有图形已经完整表达同一数值时才可省略冗余表，并必须在 `coverage_projection` 登记等价覆盖，不能静默丢值。

用户只能切换到当前事实集满足输入合同的图形。不兼容图形禁用，并用简洁中文说明缺少的字段、单位或区间；不能为了启用图形而估算或补造数值。不同仪器、单位、定义或效应表示自动拆分为可比较小多图。任何归一化视图都必须可逆并同时提供原始值表。

### 15.4 分层筛选和联动

- 页面级筛选：适应症、产品、靶点/机制、试验等共享范围，影响页面全部模块。
- 模块级筛选：终点、时间点、效应形式、分析人群、AE 术语/等级、设计要素、量表等，只影响相关模块。
- B 基线与完成情况模块还必须支持队列/组别、基线或处置人群、变量域/字段族、统计形式、原因、分母角色、计量对象、时间窗和披露状态；分母语境改变时图表必须重新分面而不是直接混排。
- 图和表使用同一事实集；悬停、聚焦或选择在两者之间同步。
- 页面重置和模块重置分离；无数据模块显示限制范围和空状态，不自行扩大筛选。
- 页面和模块状态分别序列化到网址；较大的命名视图使用本地清单，不能截断状态。

### 15.5 同页证据抽屉

点击图形标记、时间线、矩阵或表格单元格，在原页面右侧打开证据抽屉，保持当前筛选、滚动和焦点。抽屉显示精确的产品、试验、组别、终点/事件/设计要素、量表、时间点、值/阈值/单位、分子/分母、来源版本及登记字段/页/表/段定位。

在法律和技术允许时，抽屉提供简短原文和规范化说明；原文始终保留。用户可固定多条证据并列核对定义、时间点、分母和冲突。所有抽屉和筛选支持键盘、焦点返回和减少动态效果。

对 `baseline_observation` 和 `trial_disposition_observation`，证据抽屉还必须显示规范变量/字段族、来源原名与定义、统计形式或计量对象、量表/版本/方向、分母角色及分子/分母、时间窗或基线时间定义、原因原文/规范原因及互斥穷尽标记、兼容规则/差异标签、缺失/披露状态和精确定位；不适用字段以准确状态呈现而不是留空。

### 15.6 视觉语言

站点白色/浅色面积不少于 80%，橙黄合计不超过 12%，红色仅用于风险或阻断；颜色来自康哲令牌，不能只靠颜色传达含义。使用康哲字体栈、表格数字等宽特性、克制阴影和动效；禁止暗色霓虹、玻璃拟态、WebGL、整页渐变、无限滚动和通用 AI 仪表盘风格。

所有门户及详情页在 1280、1440、1920 宽度进行真实浏览器检查，并覆盖 Chromium、WebKit 和所声明的实际操作系统；不能以伴随原型截图代替生产报告验收。

### 15.7 确定性默认选择

默认视图不能由模型临场偏好决定。所有选择规则版本化并写入视图清单：

- **锚定试验**：仅从已通过当前报告关键字段门槛的适格核心试验中选择；依次按注册/关键研究角色、阶段、主要结果披露成熟度排序，仍并列时以稳定试验 ID 决定。该规则不使用疗效数值或安全性发生率，因此不会暗中偏好结果更好的试验。
- **首页终点族**：按 §11.6 生成 CDE、FDA 与竞品采用依据，平行轨及全部适用核心终点族均可见。气泡图或单图需要一个初始终点时，选择具有最多适格产品、对照和兼容结果记录的终点族；并列时按稳定终点族 ID。用户切换不改变事实。
- **常见 AE**：强制摘要行优先；其余依次按预定义 AESI/临床重要性、具有可比已报告值的产品数、最大绝对治疗—对照差、最高报告发生率和稳定术语 ID 选择。该顺序只决定默认显示行，不形成产品安全排名。
- **基线变量**：先显示组别基线样本量、年龄、性别和适应症 `GateSpec` 定义的全部严重程度锚点，再按人口学、疾病语境和其他严重度域的稳定变量 ID 展开；统计形式或量表不兼容时固定拆分小多图，不能为增加覆盖而混合。
- **试验完成情况**：固定先显示筛选/筛败、随机/治疗、完成治疗/研究、停止治疗/退出研究和失访，再显示依从性、补救治疗、禁用药及 PD。所有预定义字段保留未公开状态；原因按规范原因族和稳定 ID 展开，不以 Top-N 截断。
- **产品和靶点**：默认按靶点分组，组内使用稳定产品 ID 或规范名称，不按疗效、安全性或综合分数排列。

任何默认选择若因数据变化而改变，必须在新快照中可复现；旧报告保持原选择和原清单。

## 16. 多格式交付合同

### 16.1 共同规则

每个格式读取同一已锁定报告快照、声明集和证据清单。锁定时建立规范 `coverage_set`，逐项列出章节、页面责任、产品、试验、关键声明、表、图、证据引用和附录。每个格式生成 `coverage_projection` 并计算集合差异；格式可以重新组织内容，但不得引入新事实或混用快照。未覆盖项只有命中版本化格式例外并保存替代表达/理由时才允许，例如 PPT 中一张图已完整覆盖同一页的冗余表；任何未解释差异均使该格式失败。

正式全量报告与当前筛选视图导出是两种不同产物，使用不同类型、文件名和清单。自定义导出直接呈现筛选后的结果，不增加“筛选范围说明”页；完整筛选状态和快照身份保存在清单、元数据或备注中。

### 16.2 站点式 HTML

HTML 是交互真值表现层：完整多页面、全局搜索、分层筛选、可复现网址状态、证据抽屉、跨页下钻和本地离线运行。生成后必须执行链接、控制台、数据完整性、筛选联动、溢出、键盘和真实视觉检查。

### 16.3 原生 PDF

PDF 是可打印、可归档、文字可选择/检索、图形优先保持矢量的完整文档，不是网页截图或幻灯片 PDF。默认 A4 纵向；宽表、森林图、纵向多系列、设计时间线和终点矩阵自动使用 A4 横向。横竖切换只能发生在分页边界，并保持书签、页码、页眉/页脚和章节顺序。

PDF 使用克制、段落逻辑清楚、高信息密度的编辑语法。表格允许跨页并重复表头；图表和表格在两者都提高完整性时可同时保留。验收必须确认标准阅读器可打开、文字可检索、书签正确、无裁切重叠且 100% 打印可读。

### 16.4 HTML-PPT

HTML-PPT 使用独立的固定 1280×720、16:9 康哲幻灯片运行时，具备键盘导航、深链及按 `S` 打开的当前页/下一页/逐字稿/计时器演讲者视图。每张幻灯片包含合同要求的 150–300 字口语逐字稿；封面/章节等合同允许的页型例外按原合同执行。它把完整报告内容重组为不限页数的视觉叙事，不是站点页面截图。所有页使用康哲幻灯片母版、正式 Logo 和字体；页码按合同页型规则显示，不能误加在封面、目录、章节首页或结束页。逐页视觉验收覆盖 1280×720、1920×1080、2048×1024 及用户实际最大化窗口，不能用缩略总览替代原图。

### 16.5 可编辑 PPTX

可编辑 PPTX 必须真实调用 PPT Master 完整串行流程：初始化、内容策略与锁定设计、逐页 SVG、质量门、备注、收尾处理、原生导出、OOXML 可编辑性核验和原分辨率逐页视觉检查。图片页、HTML 截图、仅生成 SVG 或绕过 PPT Master 的脚本均不合格。

PPT 以视觉反馈为主，一页一个核心比较或结论；图已经完整表达时不重复表格。复杂内容通过增页解决，不缩小到不可读，也不删除记录。文本、形状和支持的图表应保持可编辑，并在目标 PowerPoint/Office 中检查字体、折行和裁切。

### 16.6 设计合同包装

- 跨 Agent 默认合同：`design_share_v2.md`，SHA-256 `113cc55f39d469ae91760da10c0cc3e28071573d35f4095b05b1d96d8cfb5c46`。
- 本地增强合同：`design_v2.md`，SHA-256 `8d8dc9f67478caefda0fde8c3555863b49db5055739e6db8d3192e15622f4def`。
- 两者共同正文摘要：`49c39fc209445a8bc679993483bf50d7b4a7566cbb55688b3448bb53f1f09ce7`。

两份文件原样保存为包内 `contracts/kangzhe/design_share_v2.md` 和 `contracts/kangzhe/design_v2.md`；清单中的逻辑入口 `design.md` 固定解析到 share 版，不复制出第三份可漂移合同。本地增强入口只能显式解析到 v2 本地版。角色、版本、来源、摘要、兼容范围和更新时间写入清单。跨 Agent 基线只依赖 share 版；本地增强版只有在其引用资产和工具摘要全部验证后才能启用。任何缺失或摘要不匹配在内容生成前失败关闭。

正式 Logo 从康哲设计合同指定的官网源获取并核验 SVG 类型、`viewBox="0 0 121 25"`、非空内容和摘要后随包嵌入；观众运行时不得访问远程 Logo。旧仓库中的 Logo 只能作为待核验迁移候选。当前已安装 `kangzhe-ppt-design` 缺少其入口声明的设计文件，新包必须以本节两份 v2 合同修复该缺陷，不能继承损坏引用。

## 17. 修订、刷新与可选监测

### 17.1 来源关联修订

HTML 中的事实、图点、矩阵单元和声明可以发起修订建议，但不能直接编辑科学真源。建议包含目标稳定 ID、当前报告/快照、可见值、建议值、理由和新来源。

修订建议 schema 至少保存建议 ID、提交时间、目标事实/声明/图点 ID、报告与快照、旧值、建议值/解释、用户理由、附件/链接、验证状态、证据、冲突、影响集、批准者/决定和发布幂等键。

宿主提供本地项目桥时，建议直接进入项目修订收件箱；纯 `file://` 报告必须能够导出自包含修订包供 Agent 摄取，不能依赖中心服务。

Agent 核验来源身份、上下文和定位，生成旧值—新值、证据和下游影响范围。有效修订进入 `validated_pending_user_approval`；只有用户明确批准后才能建立新证据/声明快照并局部重建。拒绝或证据不足均保留追加式记录，不改变现行版本。

### 17.2 增量刷新

刷新从最近已接受快照、来源回执和缺口账本开始，对开发/招募/结果/监管/试验变更/论文/会议/公司事件等可变事实重新核验，并进行缺口和变化驱动检索。每次接受的刷新建立新的不可变证据、声明和报告版本，记录新增、变化、撤回、修订、取代和未变化对象。

只重算受影响声明、视图和产物；未受影响对象按摘要复用。重大 schema、本体或证据合同变化触发显式再基线和迁移，历史版本保持可读。

### 17.3 可选监测

支持调度的宿主可以安装独立监测 Skill。监测只写入去重后的变更候选，不能自动接纳事实、生成正式快照或发布报告。用户决定是否启动正常刷新。移除监测能力不影响新建、打开、恢复或手动刷新项目。

变更候选 schema 至少保存候选 ID、来源/版本/定位、发现时间、涉及实体和声明域、变化类型、当前值与候选值、去重摘要、可能影响的报告/页面、获取/诊断状态和用户处置；候选不能直接成为事实。

## 18. Agent 交互、日志、安全与隐私

### 18.1 无强制工作台

Codex、Hermes、OMP 等宿主的原生任务/对话就是运行交互面。基线包不包含强制 Web 工作台、服务器或中心仪表盘。可选观察器可以读取持久日志做状态展示，但不能持有科学真源。

### 18.2 持久日志

项目至少保存简洁 `status.md`、每次运行摘要、`events.jsonl`、来源回执、A/B/C 覆盖记录、下载请求、必要诊断和产物清单。日志足以支持 Agent 重启、上下文压缩、跨宿主交接和审计，不依赖模型记忆。

### 18.3 凭据和用户登录

用户可以在自己的浏览器完成登录、机构访问、验证码或同意。系统不得请求、复制、记录或打包密码、Cookie、会话令牌和授权头。用户辅助获取改变访问来源，不改变科学权威。

手工文件先进入隔离目录，按摘要、嵌入元数据、标题页和试验/论文标识符匹配。重复、下载不完整、登录跳转页、HTML 错误页和身份不清文件不能进入证据库。

### 18.4 分发安全

安装包和迁移清单必须执行秘密扫描、绝对路径扫描、许可证/资产来源检查和远程依赖检查。旧交接文档中的明文登录材料不得迁移，相关凭据应在切换前轮换。任何外部依赖必须具有明确允许预期使用的开源许可证，并固定版本和摘要。

### 19.1 测试层级

| 层级 | 必测内容 |
|---|---|
| 包完整性 | 组件、Skill、schema、设计合同、资产、版本、摘要、许可证、迁移 |
| 数据合同 | 稳定身份、原文/规范值、基线统计形式、处置分子/分母/分母角色、缺失/零/冲突、版本和 locator |
| 来源与门槛 | `GateSpec` 通过/阻断/空宇宙、技术失败分类、策略矩阵、双重穷尽、审计包、用户下载恢复 |
| 控制图 | 合法/非法迁移、分支、并行、回环、中断、恢复、幂等、部分交付、`partial_delivery_blocked`、停止条件 |
| 科学分析 | 终点方向、组间计算、单位兼容、AE 术语、基线统计形式兼容、处置分母/原因语义、无池化和无隐式排名 |
| HTML | 页面、搜索、导航、筛选、网址状态、图表/表格、证据抽屉、可访问性 |

| 安全 | 凭据、绝对路径、远程依赖、非法资产和供应链检查 |

### 19.2 基准场景

正式验收至少覆盖：

- 全球成熟竞品和中国本土竞品；
- 公开结果成熟项目和早期无结果项目；
- ADC/融合蛋白、创新药+传统背景治疗组合、纯传统组合和边界本体审查；
- 默认排除研究、带理由的支持层再纳入及特殊早期核心；
- 有完整试验方案/SAP 的 C，以及仅登记字段已足够的 C；
- 仅登记且缺少分析人群/统计模型但临床设计核心通过的 C，以及缺少人群/分组/终点/时间点而阻断的 C；
- indication-only C 输出多条候选设计路径且不产生唯一推荐；
- 主要论文、登记结果、监管或指定行业来源之间的冲突；
- 最终/草案/废止指南、CDE/FDA 对齐与分歧、严格多数和“最常采用”终点族；
- 补充材料无法获取但并非必要，以及补充材料确为关键阻断；
- B 核心试验疗效/安全性已齐全但缺少组别年龄、性别或适应症严重程度锚点而阻断，以及通过登记结果/补充材料补齐基线后恢复；
- B 多臂试验的均值/中位数、年龄分箱/人口学类别、不同严重度量表版本/方向或基线时间不兼容而自动拆分小多图且不补造类别；
- B 的随机/治疗/完成/退出、依从性、失访、筛败、补救治疗、禁用药和 PD 全部或部分未公开，但以准确缺失状态生成完整完成情况页面且不阻断；
- B 关键疗效、安全性和基线核心已满足而仅完成/处置字段缺失或部分缺失时，完整完成情况页照常交付、不阻断 B、不单独触发用户辅助下载；开放附件可自动跟进但不升级为必要下载；
- 筛选/随机/治疗等不同分母、完成治疗/完成研究、停止治疗/退出研究、PD 受试者数/事件数和非互斥原因不得错误合并或复算；
- B 基线与完成情况页面的图表—表格—证据抽屉、多维筛选、网址恢复及跨格式覆盖；
- 网络、限流、验证码、页面变更、解析失败和工具能力缺失；
- 用户按原文件名下载后的自动匹配、重命名、归档和恢复；
- 同时选择 A/B/C 和多种格式时的共享证据、独立门槛及部分交付；
- 非法状态迁移、重放幂等、部分交付后剩余对象终态阻断及显式重新打开；
- 康哲站点页眉 Logo/导航/搜索无碰撞、HTML-PPT 演讲者运行时/逐字稿/页码页型及跨格式覆盖集合；
- 可选图适配器缓存移除后由规范事件/检查点恢复；
- 新版本恢复包在隔离目录完成安装/恢复/代表性重建，旧根删除后对影子副本、符号链接、启动器、消费者引用和缓存/备份登记执行主动无残留扫描；
- 大型项目的完整页面、筛选和证据下钻，不能仅测首页。

旧工程的慢性自发性荨麻疹 A、PNH B、特应性皮炎 A、样式崩塌报告、伪截图和 false-green QC 作为负向回归样本；它们不是新系统的生产模板。

### 19.3 验收责任

确定性检查与真实渲染缺一不可。科学验收和视觉验收使用与生产者隔离的审查上下文；验证者只能接受或否决，不能静默重写产物。每个完成结论必须关联测试输出、数据库/文件状态、浏览器截图或 Office/PDF 实际渲染等锚点。

### 19.4 完成定义

“代码完成”“happy path 跑通”“生成了文件”“QC 脚本退出 0”均不构成系统完成。只有安装包、A/B/C、所选格式、宿主适配、恢复路径、基准场景、跨格式覆盖和独立验收全部通过，才能进入最终切换。

## 20. 净重构、迁移、切换与旧工程删除

### 20.1 独立构建

新架构在独立项目根目录构建；当前旧工程在设计、开发、回归和迁移期间只读保留。新系统不得导入旧 orchestrator、旧 Skills、旧 schema、旧模板或旧 QC 作为隐藏运行依赖。

### 20.2 迁移清单

每个迁移项记录旧路径、摘要、类型、来源/许可、保留原因、新路径、转换规则、脱敏结果和验证证据。允许迁移：

- 已批准的 D01–D70 和本规格；
- 两份 v2 康哲设计合同及重新核验的正式资产；
- 未被后续决策推翻的用户原始需求；
- 经过脱敏和身份核验的权威证据样本；
- 代表性正向/负向回归输入输出。

旧 PRD、完整设计、12-Skill 文档、构建计划、测试任务书、交接和状态报告只作历史差异或回归依据，不成为新规范。明文凭据、会话、缓存、绝对路径、旧全局事实库和旧可运行代码不得迁移。

### 20.3 切换门槛

切换前必须：

1. 冻结候选新版本及包清单；
2. 完成迁移差异和摘要核对；
3. 证明新包可独立安装、打开、恢复、刷新和重跑；
4. 在 Codex、Hermes、OMP 上通过适配器合同；
5. 完成 A/B/C 和四类输出的适用验收；
6. 完成独立科学、视觉、包和安全验收；
7. 建立只含新版本、已批准迁移资料、清单和验收记录的内容寻址恢复包，并在一次性隔离目录完成安装、项目恢复和代表性重建演练；
8. 形成最终验收报告、凭据轮换/撤销确认和精确旧工程删除/残留扫描清单。

### 20.4 删除旧工程

旧工程删除是最终切换操作，不是清理性开发步骤。执行前生成干运行清单，逐项记录旧根目录及相关模板、影子副本、兼容包装器、符号链接、启动入口和消费者引用的 `realpath`、设备/inode、类型、摘要和处置；不允许宽泛路径、未解析变量、符号链接逃逸或跨根删除。迁移清单必须逐项闭合，§20.3 的新系统恢复演练和独立删除验收必须通过。

持久恢复包不得包含可运行旧流水线、旧凭据或完整旧源树；它用于恢复新版本和已批准保留资料。若具体删除机制为安全回滚临时创建旧根隔离副本，该副本必须脱离所有启动/导入入口、限制访问、完成秘密检查，并在最终删除状态前一并销毁和核验，不能成为冷藏的旧影子运行时。

删除后主动扫描已知安装根、项目根、Skill 消费端、符号链接、启动器、缓存/备份登记和导入路径，证明旧运行代码、旧模板及可继续运行的影子副本均不存在，且新系统不存在对旧路径的引用。扫描清单和非存在证据由生产者以外的验证者接受；发现任何残留即撤销删除完成状态并继续精确处置。

新项目只保留迁移清单、验收记录和已选择的证据/回归样本，不保留旧代码、兼容包装器或完整可运行备份。删除结果写入验收记录；此后以新系统修复前进，不再回切旧流水线。

## 附录 E：外部架构方案决策记录

- **问题**：需要表达分支、循环、检查点、人机中断、部分交付和恢复，同时保证科学真源不被运行时持有。
- **候选**：旧线性 Skill 链；强绑定 LangGraph/中心服务；应用持有类型图并提供本地执行器和可替换适配器。

- **官方依据**：LangGraph 官方 Graph API 将工作流定义为 State、Nodes、Edges，并支持分支和循环；Persistence 文档说明检查点、线程、恢复和重放；Interrupts 文档说明持久化中断及重启节点带来的幂等要求。项目仓库许可证为 MIT。
- **采用门槛**：若实施可选适配器，必须重新核对当时发布版本、依赖、许可证、安全、迁移兼容和本地持久化行为，固定版本/摘要，并运行适配器一致性套件。
- **拒绝与回滚**：LangGraph 适配器失败或被移除时，项目科学数据库、证据、快照和产物仍可由默认本地执行器打开、验证和继续；不得进行科学数据迁移才能回滚运行时。
