## 2. 检索与执行架构正名（修订 §5.2/§9/§11）

**追认为正式架构**（v1.2 中"来源路由与检索"内部 Skill 的自动路由语义按本节修订）：

1. **检索责任在宿主 Agent**。宿主 Agent（Codex/Hermes/OMP 中的执行 Agent）执行检索、判断来源适用性、完成下载与初筛，产出符合 schema 的 **research-package**（JSON，含来源原文引用、路由回执、抽取候选）。
2. **research-package 是引擎唯一科学入口合同**。确定性引擎（`ci-workflow`）不承担出网检索义务；引擎对 research-package 执行 schema 严格校验、身份解析、门槛求值、快照锁定与渲染。包内已有 A/B/C 三类 research-package 合同，后续新报告类型沿用同模式。
3. **connectors 定位修订**：由"自动路由连接器"修订为两层——(a) **解析器库**：对已获取来源（CT.gov JSON、登记 HTML、PDF、公众号文章等）做确定性解析、定位与规范化；(b) **白名单拉取器**（可选）：仅 CT.gov 与药智网两个 API 干净公开的来源允许引擎直接 HTTP 拉取（分页、限速、回执齐全），其余来源一律由宿主 Agent 获取。
4. **双重穷尽语义在手工模式下的落地**（修订 §10.3 的操作定义，判定标准不变）：
   - 路由完成 = research-package 内每条必需路由均有类型化回执（`completed`/`not_applicable`/`access_blocked`），且缺口账本中每个适用单元的策略矩阵已实例化；
   - 信息增益饱和 = research-package 的恢复轮次记录满足"两轮不同策略无新关键证据"；
   - 独立遗漏检查 = 科学 QC 门 + blocker audit 的独立审查节点（职责分离不变）。
5. **引擎出网边界**：除白名单拉取器外，引擎任何模块不得发起网络请求；该边界由测试固化（现有 grep 断言扩展为单元测试）。
6. 〔建议〕配套新增 CLI：`ci-workflow research scaffold`（给定适应症生成待填 research-package 骨架、schema 即时校验、来源清单模板：CT.gov 查询 URL、CDE/登记平台链接、公众号检索式、PubMed 检索式）。

## 3. 来源政策增补：药智网企业版（§11 增补，D71）

1. **资格**：药智网企业版（`vip.yaozh.com`）获得指定来源资格，作为**商业数据库**类来源进入声明—来源策略。
2. **声明域**：药物身份与别名、中国注册/批准状态、全球管线阶段、企业关系与交易线索、适应症扩展轨迹。数值疗效与安全性结果**不直接采纳**，仅作线索定位（数值仍以登记结果/监管/论文/指定公众号为准）。
3. **来源角色与冲突**：与官方登记、监管机构冲突时进冲突门，官方优先；药智网独有字段标注 `commercial_database` 来源角色与获取时间。
4. **凭据边界**：用户名/密码存本地安全配置（环境变量或本机不入库配置文件）；bundle、日志、回执、事件、快照零凭据；包级秘密扫描保持强制。用户已授权实施期使用 Edge Lite 浏览器 joincare 账户做本地联调。
5. **API 细则**（D-05 记录，实施时复核）：`https://vip.yaozh.com/api/{globaldrugs,cfdadrug,clinical,zhuce,instruct,fdadrug,company_filter}`；注意 `/api/clinical` 响应包在 `data.List.res`。
6. **拉取器实现**：走白名单拉取器模式（纯 HTTP+分页+限速+类型化回执），失败按 §10.4 技术恢复分类，不记作"无证据"。

## 4. 首版发布范围 release-scope-v1（修订 §16，新 §22）

**§22 首版发布范围（规范性）**

1. **首版（v1.0）交付格式仅为站点式 HTML 门户**。PDF、HTML-PPT、可编辑 PPTX 三条格式轨为**保留能力**：代码、schema、测试入库维护，但不进入首版验收合同、不进入默认能力预检、不出现在首版产物中。
2. 首版验收信号相应修订：`RC_FROZEN reports=3 formats=1 hosts=3 recovery=passed pending_future=1`；`FINAL_ACCEPTANCE_OK ... formats=1`。`formats` 恒由当次 artifact manifests 实际计算，不得硬编码。
3. **范围收缩的合法性**：catalog/runner 中四格式断言按本文再生成；被摘除的 case 以 `release_scope=deferred` 状态登记（引用本文档摘要），**区别于** `not_applicable` 绕过——deferred 案例不进入 owner 10.6 必闭集合，10.9 聚合时输出 deferred 计数；唯一 `pending_future_owner` 仍是 `legacy-absence`。
4. 后续版本（v1.1+）恢复任何格式时，恢复该格式全部验收断言并升版 release-scope；已冻结 RC 不回改。
5. capability preflight 按用户选择检查的本质不变（v1.2 §6.2 仍有效）；首版默认 `--outputs html`，选择 PDF/PPTX 输出时对应能力检查照常触发。
6. 投产使用（用户已确认）：首版 HTML 门户可先行用于真实报告与 QC loop，不受验收链状态约束。

**§16 相应修订**：§16.1 的 `coverage_set/coverage_projection` 机制不变，首版每报告仅 HTML 一条 projection；跨格式一致性测试（§19.1 跨格式行）在首版降级为"HTML projection 与 coverage_set 差异为零"。

## 5. 数据导出合同（§16 增补，恢复 D-33 需求）

1. 每个图表下方的完整数据表提供**导出按钮**，导出 CSV（默认）与 XLSX（可选）两种格式。
2. 导出物是**当前筛选视图的投影**：与"当前筛选视图导出"（§16.1）同类型，包含完整筛选状态、快照 ID、数据截止日于文件头注释/元数据行；不新增说明页。
3. 导出从 view model 的同一 filtered row set 生成，与页面表格逐单元格一致；导出不回写事实、不产生新的 artifact 状态（导出文件不入 artifact_records，属用户侧即时下载）。
4. 〔建议〕A/B/C 全部门户统一实现；实现优先级 B（数值密度最高）> A > C。

## 6. 呈现层增强合同（§13/§15 增补）

1. **雷达图（恢复 D-29）**：B 类矩阵/模式页提供归一化雷达图维度组合（疗效信号维度×安全性维度）；仅使用可逆归一化（每维度标注原始值域与方向），任何归一化视图必须并列提供原始值表；维度组合版本化写入视图清单（并入 §15.7 确定性默认选择合同）。chart_specs 中已声明的雷达输入合同为实施基础。
2. **证据成熟度矩阵（恢复 D-30 呈现意图）**：B 类新增"证据成熟度"视图——产品×试验矩阵，每格双轴信号（披露渠道级：同行评议全文＞会议全文＞摘要/海报＞注册结果＞新闻稿；设计类型：随机＞非随机＞单臂），叠加样本量/随访的适应症内相对分位标记。信号并列显示，**不合成单一分数**（维持 v1.2 附录 B 禁令）。
3. **安全热图补强（§13.4 增强）**：热图必须包含色标图例（率值→颜色映射与值域）；产品列旁固定显示锚定试验的对照列与分母列（或悬停可得，默认可见）；支持"率值/绝对数（分子/分母）"切换；类型化缺失状态的图例说明常驻。〔建议〕此条为 R4.3 验收清单。
4. **信息密度约束**：HTML-PPT（若后续版本恢复）除封面/章节页外，内容页主区留白 >40% 触发视觉否决；HTML 门户长表页在 1280 宽下单数据行高度与字号下限以令牌固化（修复审计实测的"字号偏小"）。
5. **刷新变化亮点（§17.2 增补）**：手动刷新接受后，门户首页顶部显示"本次更新"条目（新增试验数、字段变更数、状态迁移数、新增来源数），数据来自 refresh 前后快照 diff；条目可折叠、可下钻到变更对象。〔建议〕

## 7. 分发与安装体验合同（§6 增补，D76）

1. **分发物**：版本化 skill 安装包（bundle）。最终用户（医学同事）在其 Agent 宿主中通过**特定关键词**调用公共入口 Skill 触发工作流；关键词建议为中文短词（如"竞品调研"），最终措辞在分发任务中定稿并写入 SKILL.md frontmatter 与安装文档。
2. **SKILL.md 文案验收标准**：公共入口 SKILL.md 按"产品说明书"标准验收——包含触发词、最小输入示例（一句话发起）、能力边界一段、常见阻断与求助指引；禁止内部术语（gate/snapshot/receipt 等）出现在用户触点文案。
3. **preflight 失败指引**：能力预检的每类失败必须输出非技术同事可执行的中文修复指引（如"请联系管理员安装 Playwright：附一句话说明+链接"），不允许裸报错码；该要求进入宿主 conformance 测试。
4. 安装文档（`docs/user-guide/install.md`）随包分发，覆盖三宿主安装步骤与关键词验证方法。

## 8. 监测能力处置（§17.3 修订，D77）

可选监测 Skill 移出范围：不建设、不分发、不进入任何验收集合；已建 monitoring 代码保留为 inactive 能力，catalog 中对应 case 标 `release_scope=deferred`。增量刷新（§17.2）保持为**用户手动触发**的完整能力（含影响分析、局部重建、历史版本）；本节不改变 §17.1 修订建议流程。
