# 竞品调研多 Skill 工作流——完整设计 v1.4（待审定）

日期：2026-09-05。状态：完整设计，待审定；本文件不代表Goal已设置，也不是实现完成或发布声明。保留review文件名以维持已提供引用。涉及尚未明确裁决的新科学/来源权威/用户行为变化仍按原生Ask处理，不能把文档形成解释为对任意扩展的批准。

## 1. 产品目的、用户与成功标准

服务临床开发和医学人员，把一个适应症研究问题转为可追溯、可复核、可更新的竞品研究成果，减少人工检索、核对、整理与阅读成本。系统不是默认给出“最佳药物/最佳方案”的决策器，也不是把搜索摘要包装为图表的报告器。

成功意味着：用户只需表达问题、选择必要边界，即可得到覆盖完整竞品集合、科学语义可解释、可沿事实回到原文、中文可读、图表和完整表格一致的独立 HTML 门户。技术运行成功、资料数量多或测试全绿均不能单独证明成功。

### 1.1 三类产品

| 类型 | 面向用户的名称 | 核心问题 | 不应输出 |
|---|---|---|---|
| A | 适应症竞品全景台 | 有哪些创新竞品，机制/模态、管线、临床组合、中国/全球开发与监管、企业关系如何？ | 明星产品截断、默认总排名、以研究中断项目消失来制造完整性 |
| B | 临床结果证据室 | 各试验的人群、疗效、安全性、基线、亚组、暴露和处置结果是什么，哪些差异可以中性描述？ | 跨试验因果优劣判断、综合疗效安全分数、默认研发建议 |
| C | 试验设计图谱 | 各试验如何定义人群、终点、访视、组别、治疗期、估计目标及统计设计，有哪些可选设计模式？ | 仅凭适应症给出唯一最佳方案、用论文方法摘要替代完整登记设计 |

A/B/C 是三个独立多页面门户，不提供融合首页。可以共享同一项目研究和证据快照，不等于共享一个报告仪表盘。高密度指深、细、全且无冗余，不是小字号、空字段墙或工程信息堆叠。

### 1.2 发布范围

首版仅 HTML。PDF/HTML-PPT/PPTX 代码留开发仓，不进入安装包和真实输出验收；保留代码仍做明确范围的静态与兼容回归。PDF 原文获取、解析和必要 OCR 是研究输入，不在排除范围。

排除：CSV/XLSX 导出、雷达图、证据成熟度排名/画像、定时监测、默认竞品排名与综合分数、Meta/NMA、强制 LangGraph、RC 前同事正式分发或用户人工测试。后续恢复能力需新版本和用户明确决策，不能由旧 Skill 自动带回。

权威顺序：最新用户裁决 → 经审定的当前设计/发布范围 → 当前源代码和运行证据用于判断实现事实 → 旧设计/Skill/审计/交接用于追溯。代码现状不能反向改写需求。本文中的新技术设计是审定候选，不冒称用户逐条批准。

## 3. 入口与用户体验合同

安装后只暴露一个公共 Skill。默认接受一句话需求；高级模式接受严格类型化 research-package。用户不需手写检索式、列产品或编排节点。

入口解析适应症、A/B/C、可选历史截止日。适应症有实质歧义或类型未给定时使用宿主原生 Ask，提供带说明的选择项；仅缺普通实施细节不提问。每个新项目询问一次药智访问条件。宿主缺原生 Ask 时提供明确能力指引，不能伪造用户选择。

新报告：意图确认 → 宿主预检 → 研究 → 科学接受 → 渲染/浏览器检查 → 交付。刷新：用户明确手动触发 → 动态核查/新资料识别 → 事实差异 → 受影响研究和页面重建 → 新版接受；不增加定时触发。

用户界面只表达需要用户处理的事项和报告结论。不在首屏暴露 Gate、worker、prompt、run ID、内部路径或覆盖诊断。技术日志与报告分离。

## 4. 应用自有类型化控制图

### 4.1 编排路线

采用应用自有、可版本化控制图；不引入 LangGraph 基础依赖。图节点明确输入/输出、状态和边，LLM 负责有语义判断的研究与裁决，确定性代码负责身份、规则、文件、门控、版本与一致性。浏览器只做呈现与交互，不临时挑选临床证据或计算新的科学比较。

| 内部 Skill 节点 | 输入 → 输出 | 完成条件与失败恢复 |
|---|---|---|
| intake-preflight | 用户意图/能力 → 项目合同/能力矩阵 | 必需能力实际探测；缺独立上下文失败，不静默主线程自证 |
| ontology-universe | 适应症/版本化创新本体 → 实体与纳排候选 | 别名、靶点、企业、试验反向扩展；歧义裁决，不按名称相似度直接合并 |
| source-planning | 声明域/地域/截止日 → 必需与可选路线 | 每路线标明作用与权威；不可访问不是不适用 |
| research-acquisition | 路线/查询/缺口 → 来源版本/获取回执 | 真实获取、版本/内容校验；网络、权限、截断、解析错误分开恢复 |
| publication-resolution | 登记关联/研究角色 → 分类/必要性/补件状态 | 主要、延长期、关键安全/长期发表物检查；补件只暂停受影响报告 |
| extraction-adjudication | 来源片段 → 候选事实/实体归一/冲突 | 来源定位、上下文、数值和缺失状态完整；不得用模型总结作原始证据 |
| universe-review | 候选宇宙/路线/扩展 → 独立遗漏裁决 | 干净上下文审查纳排与遗漏，绑定候选摘要；漂移重审 |
| analysis-a / b / c | 同一宇宙和已接受事实 → 专属报告视图 | 各报告科学门独立；不共享模板换色，不擅自缩减宇宙 |
| semantic-review | 完整临床语义/模型归并提案 → 兼容分组及限制 | 硬冲突不能被模型放行；未知不等于相同；保留原值 |
| scientific-review | 报告候选/证据/门结果 → 实际独立复核回执 | 真实会话/身份/上下文与候选绑定；空、失败、PENDING 不接受 |
| render-qc | 已批准科学视图 → HTML/页面清单/浏览器回执 | 图表—表格—来源一致，全部物理页面和规定矩阵通过 |
| snapshot-refresh | 接受候选/旧版 → 不可变快照/latest/差异 | 实际产物及证据绑定，原子晋级；失败不覆盖旧接受版 |

每节点合同包含 schema_version、项目/运行/节点身份、输入摘要、规则版本、输出摘要、状态、失败类型、恢复节点、幂等键及精简证据回执。幂等键至少由项目/节点版本/规范输入摘要构成；复用只针对同一输入和仍有效的证据。动态核查与登录观察不可因为节点旧成功而免检。

独立科学复核与浏览器验收是不同能力；一个通过不能替另一个通过。宿主运行具有副作用的发布/文件晋级由单一所有者控制；并行仅用于独立路线、报告分析或只读复核。

### 4.2 状态与恢复

分别管理项目/运行、研究路线、publication 补件、事实、报告科学接受和 HTML 产物状态，不用一个 status 代表全部。运行至少区分进行中、等用户资料、能力阻断、技术失败、证据不足、可接受候选、已接受。

恢复从事件与检查点重建，核验引用的输入/输出摘要。只重做受影响节点及下游，保持已接受历史不变。任何“目录中存在 index.html”的判断均不能成为交付或接受依据。

### 4.3 候选产物引用与恢复

格式节点1.3必须同时给出候选站点与清单的规范相对路径；artifact_id只代表身份，不通过反推ID算法、扫描目录或文件未变化推定本次使用。每个完成/复用节点对应唯一同报告的引用，收集时验证当前项目、合同、报告版本、完整站点摘要与锁定快照，不能只验证清单文件或首页。完成态恢复和宿主回执复验复用同一完整链。历史节点缺少新引用时保留原事件与报告，无法验证则明确拒绝自动恢复并要求新候选，不静默补签或漏记。

## 5. 数据模型、来源谱系与信任边界

### 5.1 核心对象

| 对象 | 必须明确的身份与语义 |
|---|---|
| ProjectContract | 适应症、报告集合、时区/截止日、规则版本、输入模式、一次性药智选择 |
| SourceFamily / SourcePolicy | 官方登记、监管、publication、公司/会议、指定二级来源等家族；各声明域 direct/cross_check/lead_only/不适用 |
| SourceVersion | 来源实例 ID、家族/路线映射、外部 URL、类型/角色、内容 SHA-256、公开/生效/获取时间、历史版本依据、访问状态 |
| EvidenceFragment | 来源版本、文档/页面/表格定位、原文或可验证片段摘要；不得以内部路径代替来源 |
| Entity | 产品、试验、企业、靶点、模态、组别、终点的稳定身份/别名及纳排依据 |
| FactVersion | 实体作用域、声明域、数值/单位、分母、时间窗、分析集、方向、来源片段、披露状态、冲突状态 |
| ClinicalConstruct | 人群/治疗语境、终点定义、量表、方向、估计目标、分母口径、分析集/统计形式、实际时间窗、适用性及未知状态 |
| ReportView / ChartGroup | 可视事实 row ID 集合、语义分组、图形规格、完整折叠表、来源引用、限制；不包含新科学推断 |
| Review / Snapshot / Artifact | 实际复核与候选摘要、来源/事实/规则集合、全部页面字节摘要、验收矩阵、接受时间与版本关系 |

来源实例 ID 与政策家族 ID 不同：同一数据库可有多个页面/版本，不能用家族 ID 覆盖来源实例身份。实例→家族→路线→声明域权限需要显式校验。域名只是交叉核验信息，不是内容真实性的唯一证明。

### 5.2 研究包与报告载荷

research-package 是研究产出进入确定性引擎的正式合同，包含来源、实体、路线、扩展、缺口、publication、独立宇宙复核及 A/B/C 载荷绑定。高级输入执行同样规则，不是跳过研究质量门的后门。

信封与载荷不能仅比 source_id 集合。相同来源实例必须核对 URL/来源角色或经批准映射、内容摘要、时间/版本、关联证据；冲突失败关闭。载荷不得把商业线索改称登记事实、把摘要换成别的原文、引用信封外来源或复用不同截止日的载荷。

原始文件/网页字节摘要与抽取或规范化文本摘要分开定义，保留二者的派生关系；不得要求PDF二进制摘要等于抽取文本摘要。当前SourceCapture会去除文本首尾空白，迁移时必须明确摘要绑定的正是实际入库文本，不能悄然改变已有摘要语义。URL及身份性查询参数保留；获取时间按同一时刻比较；公开/生效日期投影须按声明时区。自由字符串capture类型需要受控type/role/publication映射，定位采用共享结构或明确可验证投影，不把字符串与结构对象直接硬比。

日期精度必须随来源贯穿入库、版本身份及科学重开。`SourceCapture.date_precisions`可逐项声明published_at/effective_at/first_disclosed_at的instant或calendar_day；省略时保持历史序列化与身份兼容，不给旧来源补造精度。calendar_day中的零时仅是已声明来源自然日的存储表示，不证明实际在零时公开；不得携带任意时分秒，未知日期不得声明day。信封日期保留该来源自然日，而instant按项目时区投影；精度纠正改变来源版本身份并要求相应复核。只有日级公开证据且截止时点落在当天内部时，沿用历史门的保守不确定性处理，不推断精确可知时刻。来源时区未明确时不得凭本机时区补造历史可知性。

原始资产派生合同：`text_derivation`绑定原始CAS路径、SHA-256、长度和媒体类型，以及规范文本SHA-256、方法与提取器版本。`research capture`保留原字节并生成供宿主读取的捕获JSON指针，不在终端回显正文。当前实现UTF8-strip及PDF真实文本层提取；扫描件/不可解析文件必须恢复，未实现的OCR不能标记完成。PDF载荷必须带原始派生回执。提交、摄取、科学重开均须重读原始资产，方法/版本变化要求重新提取与复核。来源版本身份及v2复核摘要纳入存在的派生信息；缺省旧字段不反向改变历史摘要，不把旧文本记录宣称为原文件验证。迁移0010只新增append-only关系，原始PDF与规范文本分别入库；纯文本旧记录保留可读性。

宇宙/科学复核摘要必须覆盖被其裁决使用的规范来源绑定。新增覆盖字段需版本化，不将旧回执静默解释成覆盖了原先未参与摘要的来源元数据。来源只读审查已经复现A/B/C同ID矛盾仍能提交/重载，A入库实际摘要不同于信封；故此项是实际信任边界缺陷，不仅是建议美化schema。

实施合同（2026-09-06）：`closure.review_digest_version` 为 `1` 或 `2`，缺省值 `1` 仅供旧回执历史读取并保持原摘要字节算法。新提交要求 `2`；v2在既有候选材料外加入完整规范来源集合及版本标记，按来源实例ID排序，获取时刻统一UTC表示；来源URL、定位、内容摘要、角色/分类、公开/生效日期、访问状态、限制或试验关联变化使旧复核失效。不得自动把旧版本改为2并重算当作独立复核。补件获取新来源后也需新复核；旧文件保全，未复核不晋级。

信封的公开/生效日期必须等于载荷对应带时区时间按项目合同timezone投影的日期；未知与已知不能互相代替，跨午夜必须按项目时区而不是机器本地时区比较。此项只证明信封/载荷一致，不证明历史页面版本真实性或原始文件到文本派生。

新提交的每个实际载荷来源还需`locator_detail`，复用EvidenceLocator结构并与载荷定位逐字段一致，涵盖文档角色、字段路径、页/表/行/列/段及URL。历史`locator`字符串保留作摘要，不再用它替代结构化证据位置。历史缺该字段的包可读取，但新提交不能跳过补齐和复核；v2摘要纳入非空结构化定位，缺省null不改变历史v2摘要算法。

持久化来源版本采用共享`date-identity-v2`身份算法，涵盖来源ID、正文摘要及公开/生效/首次披露的状态、精度、时间与定位；科学复核引用与入库必须消费同一算法。相同字节但日期证据修订形成新来源版本，正文blob仍去重；仅再次下载且日期证据不变则复用同一版本，获取观察应另记，不能冒充原版本首次获取日。历史content-only版本不重写；升级后重新摄取创建新身份，相关复核需重新绑定，不能把旧接受结论自动搬到新身份。

产品宇宙身份在项目级唯一。A/B/C 可有不同适用试验/分析集合，但必须有投影依据，不能把各自较小集合当作完整宇宙。规则和科学载荷任一相关字节变化使原复核失效。

## 6. 来源政策与时间合同

### 6.1 来源规划

沿用声明域矩阵，不设置通用来源总排名。全球/中国必查基础路线覆盖 CT.gov、PubMed/关联原文、CDE、中国药物临床试验登记平台及适用监管机构；根据目标司法辖区和缺口增加其他正式登记、监管、企业和会议来源。指定公众号/数据库按批准声明域使用，不能统一当作原始临床数值权威。

登记研究身份、设计及状态优先登记/历史/附件与监管来源；疗效安全及基线优先正式登记结果、主要/关键长期论文与监管临床材料；开发/批准状态按当地正式监管披露核实；企业关系使用正式披露并交叉核验。来源之间冲突按字段和时点裁决，不能无条件“最新值覆盖一切”。

### 6.2 新鲜度与历史可知性

论文的有效研究结果可复用；版本修订、撤稿/更正、相关新发表物需要作为新变化识别。管线、登记/监管及其他动态状态每次运行重新核查，缓存仅加速。网络失败保留旧记录及时间，但不能将旧值称为本次确认的最新状态。

历史报告只纳入截止日当时已公开的证据与当时状态。将公开时间、事件/事实生效时间、获取时间、报告 cutoff 分开。事后披露的旧事件不能倒填；晚获取的可验证历史版本允许使用。当前动态页面不能仅凭 first posted 日期证明其中所有字段早已公开。未知公开时间或无历史版本证明的关键材料进入缺口/限制，不默认采用。

工程应分别记录“当时可知”“当前取得”“正式 QC 是否完成”，不可混同。ClinicalTrials.gov 的 submitted 与 posted 日期不同，历史版本也可能含尚未完成平台 QC 的公开结果。[CT.gov FAQ](https://clinicaltrials.gov/policy/faq)、[NLM 发布程序说明](https://www.nlm.nih.gov/pubs/techbull/jf20/jf20_clinicaltrials_qc.html)。

### 6.3 药智访问

新项目只询问一次 available/unavailable/skipped。使用用户自行登录的浏览器会话，不读取或保存用户名、密码、Cookie、token、授权头/存储。不能将凭据放入 prompt、环境快照、日志、回执、包或文件。

运行期访问观察与项目选择分开。同运行短期复用观察，实际访问失败立即使可用性失效并重检；新运行重新观察。具体复用窗口作为显式实现策略确定和测试，不宣称用户批准了某个分钟数。会话过期提示自行登录；跳过不阻断其他来源。

当前保守实现上限为5分钟（代码唯一常量，不是用户指定值）。宿主访问前调用`yaozh check`，使用经事件与摘要校验的当前运行清单；只消费同run_id、同宿主、当前项目回答摘要及运行开始后观察。相同时刻失败优先；最新失败阻止复用，超窗要求重检。无run_id的历史回执保留但不能授权当前访问；返回reuse_available只表示缓存观察可短期复用，不代表实际页面访问、数据获取或科学验收已完成。实际浏览器失败仍须由适配层即时提交observe，不得静默忽略。

药智用于线索发现与交叉核验；临床数值 lead_only，其余适用域最多 cross_check。不能单独支撑关键临床数值、监管状态或科学结论。URL/角色/家族与载荷一致性联合防止来源重标。

## 7. Publication、补件与证据不足

登记关联 publication 用规则、模型判断和独立复核区分主要结果、延长期主要结果、关键安全/长期暴露；默认排除综述、普通 ad hoc 与无关探索。排除是本次研究用途裁决，不是删除来源记录。

必需论文无法获取时生成精简 Markdown 清单、原文链接、所需文件说明、指定目录和受影响报告；仅暂停无法回答核心问题的报告。C 的关键设计可被登记/公开附件充分支持时，不因与设计无关的结果论文缺失阻断。

接收文件验证类型、实际内容、DOI/登记号、扫描/损坏/错文与重名冲突。重命名前记录原名、SHA-256、DOI/登记号、新名；只改名、不改字节，冲突不覆盖。OCR 是抽取手段，必须保留原文与定位，不将 OCR 错误当科学缺失。

用户一次确认无法取得后，同一快照不再重复追问。官方证据可回答核心问题则带限制继续；不能回答则只交付简洁证据不足页/审计说明，不以空图表生成完整报告。恢复获取材料后从受影响节点继续，不伪造早前通过。

## 8. 完整性、科学门与空缺恢复

首次必须完成全球/中国路线、别名/靶点/企业/试验反向扩展、版本化纳排与独立遗漏审查。闭包是明确检索范围和证据支持的收敛判断，不承诺互联网绝对无遗漏；不能以固定数量或 Top-N 替代。

异常少量竞品、关键空模块和可疑零值触发两轮不同策略恢复。相同查询重放不算不同策略。区分成功有证据、无相关证据、真实未公开、网络/限流/权限/验证码、来源不可用、解析错误、工具不足和截断。零值必须有原文，空白不能变零。

GateSpec 按报告/对象/字段声明适用性、最低证据、来源权限、成熟度、时间策略、冲突策略、关键性、恢复和失败码。组别完整覆盖与不同合格事实数分别计算；同组多事实不能代另一组，同一事实不能跨组重复计数。

报告接受条件为宇宙及适用范围锁定、逐关键单元满足、关键冲突清零、独立复核通过。可选缺失可省略或一句说明，不生成固定空字段墙。限制交付和证据不足不算完整门户验收通过。

## 9. 临床语义比较

完整语义单元含疾病/严重度和背景治疗、人群、治疗组、终点/事件定义、量表/方向、估计目标、分母口径、分析集、统计形式、实际时间窗。LLM 做医学语义归并，不用精确字符串匹配替代；确定性门拦截实质冲突，模型“兼容”不能覆盖它。

ICH E9(R1) 的估计目标框架涉及治疗、人群、变量、伴发事件处理和群体层汇总。因此不得将一个术语或未知占位符视为完整可比依据；也不能要求旧试验披露其从未使用的现代术语后才允许列示原始结果。[ICH E9(R1)](https://database.ich.org/sites/default/files/E9-R1_Step4_Guideline_2019_1203.pdf)。

48 周与 50 周可在医学语境支持时同框并标实际时间，但不是所有终点统一允许±2周；短期起效、事件风险、累计暴露等须按版本化临床规则和复核决定。均值/中位数、估计目标、ITT/FAS/PP、尺度及分母的差异需显式处理，不能只统一标签。

未知值相同不证明兼容。需要保留原始事实并提示限制，以按试验相邻小图/分组展示，不能删除数据，也不能用相同“未报告”建立跨试验比较。明确不适用与未知是不同状态，必须有适用性依据。来源内描述性列示不应冒称跨试验科学可比。

兼容分组、语义裁决、原值、变换规则及来源在 Python 科学视图层确定；渲染器和 JS 不另行选数、归并、排序制造结论。事实视图测试与真实 HTML 必须核对同一输出。

## 10. 三套门户信息架构

### 10.1 A：全景台

责任页：全景、竞争格局、产品总览、全部产品档案、临床开发组合、疗效与安全性、中国/全球监管、企业交易、专利保护、历史/边缘观察、证据与局限。逐产品档案不受默认排名截断。

图形：管线全景、机制—产品网络、阶段矩阵、地域状态时间线、疗效小多图、安全性热图、多维气泡。资料适用才展示；叙事与缺失说明不机械制图。疗效不能只接受百分比或每产品只取一个配对；完整页面保留全部符合语义条件的事实及表格。

安全性按事件定义、组别、观察窗、暴露和分析口径分组。默认锚点由版本化语义与稳定身份决定，不由数值大小决定；16周和52周不能因发生率改变而自动互换。首页摘要允许明确注明范围，但不能替代完整页面。

大规模观察可分页或按完整临床上下文折叠；页数/总量可见，全部页可达，分页并集必须等于筛选后的事实集合，不得以Top-N替代。点击图形后抽屉必须保持原始事实身份与观察窗，不允许重新按最大值选取。气泡防重叠只能调整标注或提供等位点选择，禁止移动实际数据坐标；面积编码必须遵循声明的样本量比例。

### 10.2 B：证据室

责任页：证据概览、疗效、纵向/亚组支持、总体及严重安全性、基线人口学/疾病/严重度、暴露与处置、产品/试验档案、来源与局限。核心 II/III 期及按明确角色纳入的关键早期试验按适用性完整列示；特殊单臂不虚构对照。

每适用组的核心疗效、安全性和基线需有事实支撑；处置/其他扩展依实际公开程度处理。预设气泡三组：疗效×总体安全、疗效×严重风险、获益持续性×停药风险；大小分别按治疗组样本量/有效分析集/长期暴露量。只有完整语义基本可比时同图，缺必要轴不生成空坐标或捏造零值。

### 10.3 C：设计图谱

责任页覆盖设计总览/模式、研究架构、入排/人群、治疗组、终点—时间窗、访视/治疗期、样本量/统计、逐试验详情、证据版本与局限。主要图形为模式地图、时间轴、终点矩阵、入排主题分布、组别结构和方案差异。

完整入排、终点定义与方案参数放入原位折叠表。设计事实首选登记/历史/附件/公开方案/SAP；可获取方案/SAP必须获取，只有登记可得且核心充分时明确标注。方案总结可提供多条可选路径，不输出唯一最佳方案。

## 11. HTML 组件与安全

共享字体、间距、响应式、键盘、来源编号和组件质量，不共享三报告布局模板。HTML 支持 file:// 与普通静态服务，不依赖运行时读取本地 JSON；脚本数据安全嵌入。模板自动转义与安全 JSON 序列化强制启用；任何 safe HTML 必须来自受审查的组件，不来自原始研究文本。

每结构化数据域由适当图形和默认隐藏的完整表格共同呈现。同一筛选状态下图形、表格、行级证据绑定同一事实 ID 集合；不能静默漏项。缺可绘制值不生成空坐标，保留清晰原因/原文入口。

全局筛选支持 URL 状态、重载恢复和多选；图中点及表中行打开同一证据抽屉，键盘 Escape 关闭并归还焦点。图表变化不能改变科学默认锚点；跨页链接和下钻保留恰当上下文。

每页只有一个聚合来源区，从该页参与事实的 SourceVersion 生成，含真实标题、外部链接、来源类型、公开日期、数据截止、必要限制。禁止把类别名称当唯一来源链接或把所有来源固定标为 CT.gov。用户表格/图表无内部路径、回执/运行 ID；科学原文定位通过证据交互提供。

视觉验收覆盖全部物理页面：Chromium 和 WebKit × 1440×900、1024×1366、390×844、320×568。检查中文可读、溢出/遮挡、空图、筛选/折叠/键盘、来源访问；每组合需实际运行记录，不接受只有全局尺寸列表和 ok=true 的自报回执。

## 12. Skill 安装与宿主合同

一个 HTML-only 核心包，加 Codex/Hermes/OMP 轻适配。其他兼容 Agent 满足相同能力合同后可运行，不承诺未测试宿主已经兼容。公开 Skill 像产品说明书一样解释触发、输入、过程、输出和失败恢复；内部 Skills 可独立测试/替换，不暴露多个竞争入口。

安装前完整校验归档、白名单、每文件摘要和必需内容；同摘要重装也需重验安装文件及额外文件。校验后原子建立入口，失败保留原安装。不能仅比较 package manifest。

运行环境须明确 Python/依赖合同并隔离验证，不能依赖构建机绝对解释器、工程 .venv 或继承 PYTHONPATH 假装可移植。安装包不含凭据、缓存、原始运行证据、非 HTML 输出依赖；必要原文解析依赖按输入需求保留。

三宿主验证相同输入、失败/恢复、独立上下文、来源与快照语义。真实宿主 smoke 使用隔离测试安装，不改生产配置。宿主 delivery 状态只读取与当前接受版本绑定的产物，不扫描历史或候选首页判断完成。

交付查询由application只读投影承担，宿主不直接操纵科学或渲染层。必须同时核验不可变accepted继承清单和候选前驱、项目/合同与按项目时区的截止日、锁定报告快照、整站字节，以及同快照/产物/复核者的delivery_ready事件；不接受单独的accepted标签。目录/入口/清单/快照符号链接拒绝。没有对应产物的complete或partially_delivered事件不能生成已交付用户消息。该查询不签发科学/视觉接受；独立模型真实性和所有页面浏览器证据仍由上游接受流程负责。

公共`project accept-visual --report A|B|C`逐报告绑定策划、呈现、独立审阅、报告快照和格式对象；省略report仅为旧B命令兼容。不能以B的回执推进A/C，也不能因共用验收入口建立融合门户。

每类门户的`reports/<A|B|C>/latest.json`仅在已接受清单与交付事件持久化后原子更新，记录报告/合同版本、快照、整站摘要和入口。读指针必须重开已接受链及当前产物，不能信任指针标签。候选、回退、同一接受时刻的冲突不得覆盖；同一发布幂等不改写。串行发布采用项目数据库锁及指针字节比较，文件替换失败保留旧指针。刷新子合同进入开发时，旧已接受指针仍按历史合同验证且可读；新报告未验收不得抢占。接受记录已存而指针写入失败时不撤销历史，原验收入口重试恢复发布。此指针不是自动定时刷新，也不替代事实级差异流程。

## 13. 快照、刷新、恢复与资源

首次和刷新共用科学 review 请求→真实签发→候选晋级链。恢复或刷新 caller 自填不同 reviewer 字符串不能替代实际独立复核。所有接受都绑定科学载荷、来源/事实、规则、报告完整站点摘要及运行证据。

手动刷新产生新增、修订、撤回、取代及未变化事实差异；来源更新不一定改变事实，事实撤回不删除历史。重建范围由依赖图决定，接受后原子更新 latest。无法完成时旧接受版可继续查看，清楚显示时点，不将其冒充本次成功。

恢复包不仅是可解压归档：须证明包、SQLite、事件、检查点、源证据、快照、规则一致；在隔离目录实际 restore→resume→刷新/重建并检查门户。清理未发布残留先完整检查后删除；未知内容、链接或已有发布绑定拒绝且保持现场。删除阶段 I/O 失败和并发安全另做显式恢复测试，不夸大两阶段检查保证。

原始大证据内容寻址去重，仓库保留规范、精简回执和校验指针。只删除确定可再生、无引用且不在使用的精确缓存/临时目标。会话数据库、封存验收、恢复备份和旧中文工程不进入一般清理。

CT.gov当前记录获取：逐游标遍历并核对首屏totalCount（后续页允许不重复该字段）。空中间页不等于终页；网络/限流/拒绝/坏响应、重复游标、数量或平台版本变化、同一NCT版本冲突、页数/字节预算耗尽均不得声明完整。每页保存精确原始字节。原始响应经`ctgov-study-json-v1`派生单条记录时绑定数组位置和NCT号，保留JSON原始对象文本而不重新序列化数值；重开按原始页重新提取核对。来源日期若只公开到日，保留calendar_day，不凭空制造事件时刻。当前接口结果仅为当前记录查询，既不是历史as-of还原，也不是竞品宇宙闭包。

开发门：Ruff src/tests/tools、strict-mypy src/tools、活跃 unit/contract、明确保留轨兼容范围、旧路径静态引用检查。任务门：正向、负向、恢复、幂等。科学门、真实浏览器门、包装/三宿主门、恢复门和最终 RC 门分别留证，不互相替代。
