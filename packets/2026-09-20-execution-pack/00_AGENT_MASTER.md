# Agent 实施主指令：共享事实驱动的 A/B/C 交互研究系统

**来源基线**：`smkzw/competitive-intelligence-workflow @ d6cb6d51e1b5a5e2abdacea485ea84b5268dc7ca`  
**决策日期**：2026-09-20  
**用途**：直接交给开发 Agent 的实施任务；不是“全部代码审阅完成”或发布验收通过证明。

## 1. 任务

在现有多 Skill、Python、SQLite、证据/事实版本、控制图和离线 HTML 基础上改造，不另建第二套事实库，不以换框架代替修复。实现一个共同证据底座与三个独立完整门户：A 竞品景观、B 临床结果、C 设计先例。A/B/C 同等重要，全部必须达到本任务验收。

用户已经决定，禁止重复询问：

1. B 默认保留全部相关研究，用分面解释异质性；严格同口径共轴只是其中一种视图。
2. 不做医学批注。做展示配置和实际事实修订；事实保存后全项目已生成的相关 A/B/C 页面、图、表、搜索与证据下钻同步。
3. C 为深度解构的设计先例库，支持关键词、点选分类、逐条跨试验比较，不以生成候选设计路径为核心。
4. 支持个人反复使用，配置与最终报告一起分享给同事；不建设多人实时协作服务。
5. A/B/C 无产品优先级；共享基础是实施依赖，不是先交 B、延后 A/C 的理由。

## 2. 文档入口与权威

先读仓库 `AGENTS.md`、当前项目规范与实际任务，再读本包：

本包的本地编辑会话、接口名和新文件位置是审阅者给出的工程实施默认方案，不得伪称用户已逐项指定。若仓库存在等价且更小的实现，复用它，并在一个架构决策段落记录差异。不要为这些可解决的实现细节再次打断用户。

## 3. 第一轮操作：建立可重放基线，而非先改 UI

1. 记录 `git rev-parse HEAD`、`git status --short`；如 HEAD 已变化，先对基线到当前提交做增量核对，保留新修复，不强行退回旧提交。
2. 不执行 `reset --hard`、`clean -fd`、自动 stash 或清空用户工作区；不改旧报告以伪装新构建成功，不对真实历史目录做破坏操作。
3. 在现有锁定环境记录质量门、测试收集和失败基线；复现本包的问题。不要把 commit message 的测试数字当现场结果。
4. 本包窄范围探针可直接运行：

```bash
python3 /实际解压目录/probes/review_probes.py \
  --repo /实际仓库目录 \
  --output /独立证据目录/before-probes.json \
  --assert-fixed
```

在当前基线返回 1 是发现未修复不变量的预期结果，不是环境失败，也不是可忽略的通过。返回 2 表示路径或提取条件变了，应显式迁移到新公共 API 的回归测试，不可静默跳过。默认不传 `--repo` 只执行抄录片段，不算仓库集成测试。

5. 为每个实际缺陷先建立红测试，再修源代码。把 packet-only 问题移入通用生产抽取边界的回归，不以只改演示 packet 算完成。

## 4. 核心实现不可替代要求

### 4.1 一份科学事实，多种投影

复用 `domain/facts.py::AtomicFactVersion`、现有 SQLite/CAS/快照/事件。补全共享试验上下文、逐事实定位和报告行映射。`fact_id` 是逻辑身份，`fact_version_id` 绑定不可变内容；同一事实出现在 A/B/C 的不同位置必须可以追踪至同一版本，不能靠显示文本批量替换。

修复共享摄取中不完整 version identity、`INSERT OR IGNORE` 吞掉差异、逐事实 locator 未落到事实证据边的缺陷。相同 ID 相同字节幂等；相同 ID 不同字节必须冲突，不能静默保留第一条。

### 4.2 修订是实际生效，不是只提交建议

UI 在值、设计条款或证据下钻中提供“修订事实”，展示当前有效值与原始来源，支持 typed 编辑。按钮“保存并同步”即用户对本次变更的显式确认；普通小修不再要求另一轮负责人批准弹窗，不强制重新下载来源。

保存通过结构/上下文校验后生成用户修订版本，重算依赖并原子切换当前项目视图。原始来源、既有审定快照和修订历史不覆盖。用户修订明确标识，不能继承被改动内容的独立复核结论。该版本可以分享，不伪称已重新独立科学核验；需要恢复独立核验状态时，复用现有正式 review 入口。

禁止把改动只写 localStorage、当前 DOM、某张图的 option、A/B/C 中一份报告的私有 JSON。禁止让所有用户小修都退化为“等待未来 Agent 执行”。

### 4.3 B：共同工作空间不等于同口径归并

按临床问题/终点族收集所有相关试验，保持核心/支持研究角色可见；先分面，再决定各数值框允许共轴的范围。未知语义进入明确标识的描述性/缺口区，不补零，不消失。

保留原有医学否决守卫用于共轴/确定性计算，不能删除它们换取大图。试验 ID 不能是默认分面的科学依据；真实人群、统计形式、量表、单位、分母和时间语境可以形成分面。图表切换只提供语义允许的类型。

### 4.4 C：完整条款数据库，不是相似文本摘要

完整保存全部可获取的入排、组别、给药、主要/次要终点、访视、统计设计与版本。保留 AND/OR/NOT、例外、先后关系、人群、时间锚点和小数/阈值。分类依据为设计主题及结构化字段，不是字符串签名相等。

删除活跃路径的“至少两条候选设计路径”交付门槛，保留旧数据只作兼容/历史读取。单项完整试验可以交付先例页；不充分的可选字段标缺失，不伪造模式。不得截断前十条、只抽首个主要终点、把全试验剂量归到第一组。

### 4.5 A：完整竞争对象与开发轨迹

A 与 B/C 同步建设实体/地域/阶段/机制筛选、产品→试验→事实下钻。区分计划/实际样本量及未知/明确零，保留终止、撤回、早期和临床前适格项目；不以有疗效数据作为整个景观的纳入条件。

## 5. 编辑和分享的默认工程方案

复用现有本地 Python 程序提供按需启动的 loopback 编辑会话；浏览器仍为原生 A/B/C 页面，不引入常驻云服务。双击配套启动器或现有工作流入口打开本地编辑模式；仅允许受控项目目录和 typed 修改命令。

分享导出为无需 Agent/Python 的静态离线 HTML 目录/压缩包，直接包含当前有效事实、共享资源和用户视图配置。读者双击 HTML 可读、筛选、下钻、切换图表与恢复配置。继续修改事实须由本地工作流编辑器打开包；不要把纯 `file://` 阅读承诺为无需权限、跨浏览器自动写回多个文件。

新命令（例如 `workspace open` / `share build`）只是拟新增名称，实施时接入现有 CLI、安装/宿主合同与测试，不能把它们当作现有可执行能力。

## 6. 多 Skill 与回环

保留宿主 Agent 的检索/解构/复核职责和 Python 的确定性状态/存储/计算职责。共用 SourcePlan/任务账本，只获取一次同内容、抽取一次同版本证据，A/B/C 需求按域合并。独立复核不由生产者自证。

实际运行必须记录任务输入/输出摘要、来源、变更量、未解缺口、失败分类、重试和恢复位置。重复同查询不算新策略；无进展应转到明确恢复或技术阻断，而不是无限循环。已完成的共享节点不会因另一个报告缺口重跑。不能用“多模型审阅 N 轮”代替可验证产物。

## 7. 工作编排及完成定义

按 `work_items.json` 建依赖。公共合同稳定后 A/B/C 三条工作线并行推进；受限单 Agent 环境则每轮同时推进三条垂直验收，不优先宣布某一报告完成。

最终至少交付：源代码、迁移、自动化回归、实际安装包、三份独立门户、包含用户修订与视图配置的分享包，以及命令/浏览器/数据库验证证据。A/B/C 任一未完成，不报告整体完成。

每个工作包的回报只需：改了哪些真实入口；修复前后证据；新增测试；未解决问题与具体影响；对应提交/产物。不要堆叠多份互相竞争的主计划，不要用删除失败测试、扩大豁免、填充字段或伪造回执宣告成功。

本审阅包没有证明全仓、三宿主、真实来源和浏览器均已通过。实施 Agent 必须完成本包列出的剩余审查和集成验证，不把本文件当作发布许可证。
