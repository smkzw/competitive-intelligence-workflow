# 产品决策与实现架构

基线：`d6cb6d51e1b5a5e2abdacea485ea84b5268dc7ca`。本文将“用户确定的目标”与“建议采用的实现”分开。

## 1. 已确定的产品合同

| 领域 | 本轮决定 | 被替代的旧方向 |
|---|---|---|
| B | 保留全部相关研究，异质性通过分面表达 | 严格语义等价作为进入共同工作空间的前置条件 |
| 编辑 | 展示配置 + 实际事实修订；全报告/图表同步 | 医学批注模块；只修改 DOM；仅创建不生效建议 |
| C | 深解构、可检索、可分类横比的设计先例库 | 强制设计路径综合、重复签名数量门槛、候选方案组合器 |
| 分发 | 个人重复使用；分享配置和最终 HTML | 多人实时协作、云账号、常驻服务 |
| 优先级 | A/B/C 同等验收，共用高效证据底座 | B-first 产品交付 |

继续保留：三个独立完整门户；HTML-only；原文及历史不可静默覆盖；来源和事实缺失状态；无跨试验池化、无默认排名或综合指数；不用模板化摘要冒充完整研究。JSON 视图配置和修订记录不等于恢复 CSV/XLSX 科学数据导出。删除医学批注功能不等于删除必要的修订原因/历史。

## 2. 目标结构：一份真源，三个研究视角

```text
宿主多 Skill：研究规划 / 来源获取 / 解构提案 / 身份解析 / 独立复核
                   ↓ typed task outputs
共享 EvidenceRepository / CAS / SQLite / EventStore
  来源版本 → 精确片段 → AtomicFactVersion → 试验上下文及依赖
                   ↓ 可重建、非第二真源
共同语义查询与视图计划
  A 产品开发关系投影 | B 结果/分面投影 | C 设计条款索引投影
                   ↓
独立 A/B/C HTML 门户 + 共同选择/筛选/事实编辑/版本服务
                   ↓
当前有效版本的静态分享包（事实、配置、来源入口、版本）
```

### 2.1 必须复用的现有能力

`domain/facts.py::AtomicFactVersion` 已有逻辑/版本身份、来源、上下文、规范化记录和取代关系；`graph/impact.py` 已有确定性依赖传播；`CorrectionService` 已有追加事件、幂等与版本登记；`fresh_research_ingestion.py` 已有通用摄取。先补齐并打通这些边界，避免新建互不相识的“前端事实库”“C 数据库”“修订数据库”。[S1–S4]

### 2.2 逻辑身份与上下文

建立或补齐下列身份关系，不规定必须新建同名表：

- 产品、研发/授权关系、适应症、试验、注册记录及方案版本。
- 试验期间、队列、治疗组、给药方案、分析人群。
- 终点定义、评估时点/区间、统计形式、估计目标、事件定义。
- 事实逻辑 ID 与其版本；派生输入和规则版本；页面/图表/表格/声明使用关系。

产品名、试验标题、终点显示文字、source URL 不得作为单独事实身份。`planned enrollment` 和 `actual enrollment`、24 周值和52 周值、总体队列和亚组、不同复合终点，必须可明确区分。同一登记/论文的重复披露先建立来源关系，不直接累计为新研究。

事实版本内容摘要至少覆盖其所有科学字段、披露状态、上下文和来源绑定。取得时间等审计字段如何影响版本由统一合同明确；不能只把数值/源页面片段放进 hash，而把状态和定义变化排除。相同版本键遇到不同完整载荷必须拒绝或创建合法新版本，禁止 INSERT OR IGNORE 消除冲突。

### 2.3 计划与结果分开，源值与派生值分开

C 的计划终点/样本量与 B 的实际分析/结果可能不同，A 可以引用两者但不能强行统一。共享意味着消除重复事实，不是消除真实差异。

登记/论文原始百分比、调整后效应是来源报告事实；由明确 n/N 推导的粗率是另一条可追溯派生。更改 n/N 只自动更新后者。禁止凭 n/N 覆写 LS mean、调整率、模型估计、置信区间或 p 值。

## 3. 高效研究：合并任务，不合并证据语义

### 3.1 获取与抽取

先合并 A/B/C 的实体和证据域需求，形成一张项目 SourcePlan。单个研究的登记主体、结果、附件、论文、方案/SAP 只登记一次获取任务，各报告复用其结果。

建议缓存层次：

| 层 | 建议键 | 复用规则 |
|---|---|---|
| 来源内容 | 内容 SHA-256 / 规范 source identity | 相同字节复用；保留本次访问回执 |
| 文本/表格派生 | 原始字节 hash + 提取器/参数/版本 | 同内容同规则复用，不能把“没重新下载”当已核查动态状态 |
| 规范事实提案 | 片段 hash + schema/policy 内容 hash + 提案模型/方法版本 | 新规则需重新规范化，旧事实不覆写 |
| 语义裁决 | 被裁决完整事实/定义摘要 + 政策内容 hash | 相同上下文复用；事实、时间或政策变化失效 |
| 报告查询 | 当前有效版本 + QuerySpec + 规则版本 | 只重算受影响投影 |

动态管线/监管/试验状态每次研究应重新核查；已取论文同内容可复用。A/B/C 可拥有不同使用理由与覆盖回执，但不能重复下载/重复完整抽取来证明“独立”。技术失败仍是技术失败，不能视作新增为零或来源无数据。

### 3.2 Skill 调度

研究规划输出 typed 任务；获取与解构可并行，规范写入单一协调器处理。记录每个任务的输入摘要、写域、版本、尝试、恢复点和完成条件；可用租约/幂等任务身份避免双写。读取型投影可并行，SQLite 写事务短且受控。

科学复核针对新/变更证据及其影响集，不因为修改显示布局就重读全文。初始竞品宇宙与重大实体/来源改变仍需要独立遗漏检查。保留现有主图和宿主入口，不以新框架迁移作为本任务前置。

## 4. B 的比较合同

用三层替代一个 compatible 布尔值包办所有功能：

1. **WorkspaceMembership**：是否与当前临床问题相关；包含理由、核心/支持角色、已知限制。
2. **FacetPlan**：按真实差异组织；允许整体快速对照，不要求所有分面共轴。
3. **NumericFrameEligibility**：哪些记录可共用某个数值轴/计算；沿用确定性医学守卫及必要语义复核。

所有相关研究默认可达；支持研究标注且可由用户筛除，不默默混为核心。不能安全绘制的记录保留在同工作空间的描述性/缺口模块，并告知原因。用户的明确筛选可缩小范围，不自动回退到未筛选结果。

分面的优先维度取决于临床语义，例如人群/治疗背景、量表或终点形式、统计量/单位、时间点/区间。试验 ID 只是身份标签，不能在语义兼容时必然拆出独占画布。若确实只有一个研究进入某分面，应如实说明，不为了降低“单试验图比例”强行并图。

时间模型保存 `anchor`、`kind=point|interval|schedule`、起止/时点、单位与原文。28 天=4 周仅在同锚点/同统计语义下精确换算；接近时点可按版本化规则比较并显示实际时点；累计0–24周不等于24周一次评估；自然月不默认等于固定4周。缺失工具不应伪造工具值，真实不适用通过领域适用性表达。

**查询守恒**：匹配事实集 Q = 可绘制集合 P ∪ 明确显示的不可绘制集合 U；两者不交叠。图表点并不必须与全部事实一对一（例如多事实派生一点），但必须有显式输入映射，完整表/证据覆盖 Q，不以 P 冒充 Q。

## 5. C 的设计先例库

### 5.1 条款结构

每条 `DesignClause` 至少保留：研究/方案版本、领域/主题、原文/译文、source locator、适用队列/期间/组别、原始顺序、父子/引用关系、结构化变量/运算符/阈值/单位/时间锚点，以及解析状态。复合标准使用表达式树，不能把所有条款摊平成彼此无关系的标签。

例子（合成示例，不是临床建议）：

> 筛选时指标 X≥阈值 A，且过去6个月满足条件 Y；已用治疗 Z 者还需满足附加条件。

至少分别保存数值条件、时间范围、AND 关系、条件性子句。主题筛选可以同时命中多个主题；明细仍显示完整母条款，不能仅显示被检索到的半句话。

### 5.2 完整抽取范围

身份/阶段/人群；全部入选和排除；随机化/分层/盲法；各组干预、剂量、频次、背景/救援；全部主要/次要终点及配对定义/时间；访视/疗程/随访/延伸；计划/实际样本量；分析集、公开统计模型、估计目标、缺失处理与多重性。缺失字段区分未知、未报告与真正不适用。

建立原文条款 inventory→解析条款→索引行的覆盖账本；输入18条不能输出10条。多主要终点必须全部保存；多剂量不能全部挂 arm1。原文页/段/表定位精确到条款或统计字段，不能只落到整个登记检索页。

### 5.3 查询与呈现

关键词/词组搜索 + 受控中英同义词 + 主题点选 + 可选组合条件。搜索结果默认基于项目已收录事实，不临时生成臆测条款。

用户可以选择研究列、固定基准研究、选择设计主题、按期别/给药/人群分类、切换共同点/差异点、展开逐条原文。缺失显示为缺失，不是“不使用”。阈值差异保持运算符、单位和时间锚点；未能对齐的条款仍并排可查，并标记“未确认同一条件”。

结构化内容用时间轴、终点—时间矩阵、组别结构图；长入排条款用可检索对照表是主呈现之一，不为“图先表后”把临床句子强制变成无意义柱图。

不开发方案组合器，不强制形成两条候选路径，不以相同全文签名出现两次才视为可用先例。一个有充分来源的试验也可交付 C；无充分核心设计的试验保留缺口说明。

## 6. A 的景观交互

A 的任务链为：机制/模态/地域/阶段 → 产品集合 → 产品开发轨迹 → 核心与支持试验 → 结果/监管/企业关系证据。必须保留完整适格宇宙、非结果性项目和未启动临床项目；关系/时间显示不能暗示默认优劣。

A 的最高阶段、地域监管状态等为规则投影；修改上游具体开发事件可改变这些派生，但不能把不同地域状态互相覆盖。药物显示名修正与实体合并是不同操作；后者必须检查所有别名及外部标识引用。

## 7. 统一视图与 ECharts 合同

`ViewState` 保存门户/页面、当前项目修订、筛选表达式、选中事实/实体、列、排序、分面、允许的图形类型、下钻路径、图例选择及缩放范围。布局变化只改视图状态，不改事实。URL 保存轻量状态及稳定 ID；完整配置可以保存/导入，不把临床事实塞进 URL。

在适合表格型数据的图中使用 ECharts `dataset/dimensions/encode/transform`；关系图/树等可以用对应 typed data adapter，不强迫全用 dataset。图上 click/brush/dataZoom、图例动作与表格/主题选择经共同状态派发。完整 row/fact ID 与 series/item ID 显式绑定，禁止用临时 dataIndex 充当事实身份。[D1–D3]

分面使用清晰的轴/图例/差异标签；同单位相同统计量才能考虑共享尺度；原始记录与派生对比不得混为一列。提供可逆的字段/分面/图形组合、固定比较对象、下钻返回和保存视图，不要求全局排名。

图组件按需初始化，离屏/销毁正确 dispose，容器尺寸变化 resize；大列表虚拟化或分页必须保留总量和可达性。共享脚本只保留一个人工维护来源，安装副本通过构建同步及摘要测试；目前两个 charts.js/portal.js blob 相同，不把“有两份”误判为已漂移。[S9]

## 8. 实际事实修订与一致性

### 8.1 当前有效值与来源记录

原始来源及审定快照不变；当前报告查询使用用户确认的新事实版本。保存记录包含：变更对象、预期旧版本、typed 字段变化、操作身份/时间/原因、已有或新增证据引用、基础内容摘要及幂等键。来源 quote、源文档发布日期不由普通“改数值”编辑器修改。

一般细微修订不要求用户手写理由长文或再找资料；可选择简短原因，既有来源入口自动带入。结构不合法直接报字段错误。需要新语义裁决的内容可以标识待复核并安全分面，不因“未重新独立审阅”禁止保存整个用户版本。

### 8.2 保存事务

```text
读取当前版本 → 校验 expected revision/fact version → 校验 typed change
→ 计算完整受影响依赖 → 生成新事实版本/确定性派生/视图索引
→ 失效相关旧科学判断与叙事 → 生成受影响 A/B/C 产物
→ 核验实际文件字节与影响集合 → 原子切换项目 current revision
→ 各打开页面读取同一修订，保留可迁移的视图状态
```

任何受影响页面失败，当前已提交版本不切换，失败原因可恢复；禁止 A 已换值、B 仍旧值却显示“全部同步”。不同历史版本可以不同，但同一当前修订不能混合。

校验至少覆盖：有限数、类型、单位、n/N 类型和范围、阈值运算符、统计形式、试验/组别/时期身份、披露状态。事件发生次数可以大于人数，不能把所有 n/N 都当“有事件受试者数”。更改0/缺失/不适用必须重新校验状态，不允许隐式互换。

### 8.3 派生与叙事

现有 ImpactGraph 只有相邻层边；应明确支持 FACT→DERIVATION→FACT/VIEW 等有效 DAG，或复用等价现有依赖表达。不得用字符串 replace 模拟传播。[S3]

有确切公式的值重算；没有可证明公式的报告统计量不重算。依赖旧值的模型生成叙事和语义回执应失效，随后重新生成/核验；在无法重生成时不把旧结论作为当前有效正文，可在历史区保留并说明。纯模板化事实描述可确定性更新。

### 8.4 状态与历史

仅新增最小的有效版本/核验标识并映射现有状态，不再创造平行科学复核体系。原审定版本、用户修订版本、重新独立核验后的版本必须分辨。用户修订可保存和分享，但不沿用旧科学验收回执为新内容背书。撤销用新反向版本保留历史；重复点击相同命令幂等，旧标签页提交通过乐观锁检测冲突。

源数据刷新时进行旧底本/用户修订/新来源三方对照，不能自动覆盖用户有效值或无条件让用户修改赢过新证据。

## 9. 编辑模式与分享模式

**默认建议：本地按需编辑服务 + 静态离线分享。** 这不是取消离线 HTML，而是把写入职责放回已有本地程序。

- 编辑者从工作流/启动器打开 loopback 会话，A/B/C 保持各自页面，共用当前项目修订。确定性修订不依赖联网或模型调用。
- 分享包导出当前有效数据及选定配置；同事解压双击 HTML，即获得一致结果，不需先导入 patch 才看到正确数值。视图配置可直接恢复；分享后继续编辑可由安装的本地工作流打开。
- 原生 `file://` 阅读保留；纯静态包不保证无需授权写回全部物理文件。`localStorage` 对 file: 的行为不保证，`showSaveFilePicker` 兼容性有限，不能作为唯一持久化基础。[D4–D5]
- 文件夹可能包含 `A/ B/ C/ shared/ workspace-config.json fact-revisions.json bundle-manifest.json`；可有仅提供打开入口的 start 页面，但不能合成新的医学超级门户。
- 导出单份 A 或 B 或 C 仍须依赖闭合，不要求同时选其他报告。

**安全边界**：仅127.0.0.1/明确 loopback；精确 Host/Origin/会话校验和防跨站请求；拒绝任意路径、符号链接、穿越目录及执行任意代码的接口。不得开启宽泛 CORS 给任意 file/null origin；静态包使用本地编辑启动器而非绕开校验。会话令牌不进入分享包。外部证据只包含允许分享的内容及原始来源链接，不默认分发商业数据库全文、登录信息、内部运行日志或用户文件绝对路径。

## 10. 与规格的必要对齐

正式升版至少修改：B §8.2 的 workspace/facet/共轴三层；C §9 的先例库和完整条款要求；HTML §10 的可编辑配置与主表/图责任；§12 的即时用户修订生效与核验状态区别；安装/安全的按需本地编辑入口；相应 schema、Skill 输入输出、页面目录和验收条款。

不修改历史审定产物，不伪造新研究覆盖。旧候选路径数据可读取，不再必填。旧报告型事实通过显式映射迁移；上下文无法确认的不能静默合并。
