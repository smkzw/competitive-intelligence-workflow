# 竞品调研工作流

## 开始前只确认三件事

1. 适应症。
2. 需要 A、B、C 中的哪一类或哪几类报告。
3. 除默认网页报告外，是否同时需要 PDF、HTML 演示稿或可编辑 PPTX。

用户已经给出上述信息时直接启动，不追加技术性问答。用户未指定附加格式时，仅生成网页报告。

## 运行方式

1. 在目标目录运行 `ci-workflow package verify --root <安装包目录>`。
2. 运行 `ci-workflow project create`，逐项传入适应症、报告类型和交付格式。
3. 运行 `ci-workflow capability preflight` 检查当前宿主是否具备所选任务所需能力。
4. 运行 `ci-workflow project run --root <项目目录>`；被中断后只使用同一项目的 `--resume` 恢复。

执行期间只向用户呈现需要其决定或补充的事项。检索过程、证据检查和技术诊断写入项目记录，不放入医学报告主页面。

## 用户沟通

- 使用中文临床试验语境，不显示程序内部状态名、日志标签或无必要的中英混排。
- 证据不足时不得生成草稿；先穷尽适用检索与替代路线，再说明缺什么、为何阻断、用户最省事的补充方式。
- 用户提供原文件即可，不要求重命名；工作流负责识别、标准命名、归档和重新抽取。
- 不把“流程跑通”当作完成。只有当前项目的证据、报告和实际渲染验收均通过才可交付。

内部能力只能由应用控制图按版本化合同调用，不得绕过控制图直接编排。
