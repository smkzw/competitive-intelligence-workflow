# 修订与刷新

## 输入合同

接收用户修订、新来源版本、当前项目合同、事实谱系和已发布快照。

## 输出合同

输出差异、受影响事实与视图集合、不可变新快照和实际提交的当前版本；来源候选与未解决冲突保持待核，不能冒充接受。

## 现有执行接缝

用户显式保存本身就是保存授权，使用既有用户事实修订服务，不另加审批或医学批注。清除显示“用户清除，待重新核实”，原来源不改；实际合法依赖报告同版本重建，失败保留旧 current。

原源基线scalar消费者使用现有来源登记和用户保存事务，不制造疗效行来
取得可编辑资格。当前开发接缝接通B的明确单位均值/中位数/标准差；人数、
N和上下限编辑尚待验收，不冒称全字段。只绑定B的事实只重建B，同一current
generation可保留未受影响A的旧消费revision；不能为“同步”复制无依赖结果。
来源值/原文不可变，用户清除只影响当前值；失败或辅助输出探针报错时先读
已提交current。若save已经成功，不重复save以恢复分享或检查点输出。

来源刷新与用户保存是不同操作。Agent 先完成本次来源核查、精确原文和科学上下文验证及独立复核，再准备符合 `SourceCurrentRefreshCommand` 的项目内 builder 输入/摘要、来源事实版本、expected_revision 和 request_id，通过 `ci-workflow project refresh-source --root <现有项目> --command <命令JSON>` 调用现有事务服务。未接受来源拒绝，不用用户修订伪装来源更新；用户层用 base/user/new-source 三方比较，分歧不自动覆盖。命令成功只证明当前事务提交，不代表竞品完整性、科学/视觉终验或发布已完成。

## 禁止行为

纯呈现升级不是来源刷新或用户改值。使用既有
`project rebuild-presentation` 与 CurrentPresentationRebuildCommand，复用已存
current、原输入及真实消费者；未选择报告保持原版。字段省略/报告不存在/
绑定损坏/安装资源漂移均须明确拒绝，不能借虚假临床编辑升级前端。
此操作只追加呈现事务/generation，不写源/事实/派生/用户编辑表；新分享
从新 committed current 导出。版本/幂等/故障恢复按实际回执，不继承旧PASS。

不得直接覆盖原始来源、旧事实或历史快照；不得替用户擅自保存修改；用户已经明确保存时不得要求第二次审批。不得无差别重建未受影响产物或把未审候选写为 accepted。

## 失败与恢复

无法定位影响范围时停止发布并扩大谱系检查；新快照通过门槛和验收后再以明确版本关系发布。
