# 报告生成与交付

## 输入合同

接收当前科学快照、报告页面内容计划、共享PresentationPlan、图表配置和候选清单。科学/来源守卫保留；开发候选可以明确未验状态生成，不以新增视觉审批或另造策划平台阻断无依赖实现。正式交付仍须当前版本完整验收。

## 输出合同

输出相互独立的 A/B/C HTML 门户，以及页面覆盖清单、候选摘要和生成回执。生成者只能报告候选已生成或生成失败，不能自行写入视觉接受。

## 候选与美化回环

A、B、C同等优先，可以在共同合同owner协调下并行各自有界工作；各用独立页面目录和业务投影，不得套同一模板换色或以截图冒充页面。
- 候选必须先在真实浏览器中产生符合 `visual-render-evidence` 合同的诊断证据，再按具体页面/组件缺陷定向修订；截图摘要、候选摘要与策划书摘要必须来自同一轮。
- 按根因族集中反例、完整最小修复和相关回归；里程碑才跑宽门。保留当前候选摘要、缺陷和复测，不展开无限全页会商；两次同因失败无新证据时调整方法，不缩字、不删事实。
- 文字精简只去掉冗余和工程化表达，不能改变事实、口径、比较方向或不确定性。

## 禁止行为

不得静默删减已选内容；不得把内部口径说明、检索日志或提示语放进面向用户的主页面；不得用“无溢出”、文件存在或退出码 0 替代完整视觉检查；不得把候选移动到正式交付目录。

## 失败与恢复

已存 current 的仅呈现升级由既有 `project rebuild-presentation` 执行：先全批
核验，再以原事实/用户层/源绑定重建选择报告，末尾原子切换 current。
禁止用虚假save或未审新来源让页面升级。原版保持不可变，当前分享必须读取
新generation；重试前读真实selector，恢复记录候选不重新混用新安装资产。

单一门户失败时保留历史验收并标记当前缺口；修改后重建所有实际依赖门户、核验页面与事实一致性，不继承旧PASS。不阻断其他无依赖工作；正式交付不得带未处理阻断缺陷。四档桌面实屏、L1/L2、配置及同候选编辑/分享旅程分别记录。
