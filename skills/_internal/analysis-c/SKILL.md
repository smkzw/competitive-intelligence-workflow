# C 类试验方案设计分析

## 输入合同

接收已锁定且通过门槛的 C 类快照、登记平台设计字段、方案资料、研究角色和必要统计设计信息。

所选官方登记版本公开的入选与排除标准必须逐试验完整摄取，不得只摘取一条
“代表性标准”。在生成报告数据前，应把报告中的入排原文与锁定登记记录的
完整 `eligibilityCriteria` 字段做确定性一致性核对；条目缺失、来源文件缺失或
试验身份不一致属于数据组装缺陷，必须恢复采集或抽取，不得标成“未公开”。

## 输出合同

输出可精确定位到药物、试验、设计要素、入排评分与时间点的视图，并提供图表、表格和综合判断。

与A/B共用同一项目合同、CAS、身份绑定和消费者库，不建立隐含C副项目。
开发来源工具 tools/materialize_ctgov_c_candidate.py 的 --project 可指定已有ABC
项目，输出须在项目内；适应症、截止日或C范围不符必须在摄取前拒绝。
登记号大小写不改变科学研究身份，原始来源拼写仍保留。review预览仅作未接受
候选，不能通过该参数或消费者注册绕过科学门、Publication门或切换current。
方案/SAP缺口与已有登记字段分别披露，不把完整登记字段删除成空报告。

干预名/完整给药/终点定义不得凭试验product_id、药名词典或指标关键词压缩
成错误事实。组内背景/安慰剂保留原名，规格不冒充剂量，体重分叉、否定、
负荷与维持、量表变体/阈值/估计量完整可读；明确源绑定译文与原引文分开。
没有可靠译文就保留原文，不把该兜底宣称中文阅读或科学验收通过。
公开来源版本从核验闭包显式映射，不以采集ID冒充版本；证据快照与报告快照
分别绑定。新review-only候选不得为跑通ABC保存链而改标记或伪造正式报告快照。

## 禁止行为

不得从论文替代登记平台的设计事实；不得把唯一设计方案包装成结论；不得因缺少 Protocol 或 SAP 而否定字段完整的登记信息。

## 失败与恢复

登记字段足够时按合同标注来源范围继续；关键人群、分组、干预、终点、时间点或统计设计不足时返回证据缺口。入排标准完整原文的组装校验失败时先修复来源链，修复前不生成 C 类草稿。
