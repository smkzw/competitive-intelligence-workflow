# 视觉与交付包验收

## 输入合同

接收当前候选、实际渲染的 A/B/C HTML 门户、视觉策划书、康哲设计合同、页面验收标准、当前运行清单和内容锚点。审阅者身份必须与生成者不同，所有摘要必须绑定同一当前运行。

## 输出合同

输出符合 `visual-render-evidence` 和 `visual-verification-reference` 合同的逐门户记录、缺陷定位和接受或否决结论。真实呈现证据必须绑定当前候选与策划书摘要，并记录 Chromium/WebKit、视口或页面、截图路径及摘要、遮挡裁切指标、不可见必需字段及其用户可见替代入口、关键交互和可见文字扫描。独立结论必须逐域引用具体截图、页面或组件证据。

## 真实使用审阅

- 以资深临床试验医学人员的任务完成路径审阅：先看首屏能否迅速判断格局和差异，再实际使用筛选、多选、排序、下钻、返回和证据定位。
- 当前发布仅桌面，逐页检查 Chromium 与 WebKit 的1440/1600/1920/2560 CSS px；记录实际视口/DPR，覆盖稀疏、密集、筛后稀疏及证据侧栏。真实操作加载、筛选、L1/L2下钻、搜索、键盘和减少动效；图表、完整折叠表和URL使用同一查询。旧手机/1024竖屏只保留历史，不作本轮发布门。
- 响应式布局可以折叠次要列，但每个当前视口不可直接读取的必需字段都必须有已实际验证的用户可见入口；没有入口即为内容缺失，不能用“无横向滚动”抵消。
- 动效、阴影和立体感要帮助识别层级与状态；同时检查减少动态效果、键盘焦点和 200% 缩放/重排等适用状态。
- 图表不仅检查能显示，还要检查主旨、比较方向、直接标注、视觉通道、图例、色彩辅助编码、标签碰撞、数值可读性及图后表格完整性。

## 禁止行为

不得仅凭源码、文件存在、自动检查通过或“没有溢出”判定通过；不得以伪截图或旧运行产物冒充当前验收；不得在审阅中静默修改候选、科学快照或验收标准；不得用“酷炫”掩盖低可读性。

## 失败与恢复

缺陷定位到报告、页面、组件和当前摘要；按根因修复并批量复测受影响及相邻路径。两次同因失败无新证据时改变假设或分解，不展开固定多轮全页审查。未关闭阻断不得接受；浏览器不可用明确NOT_RUN，记录可恢复材料及最短恢复动作，不私换用户指定浏览器。ZIP/Node通过不能替代实屏。
