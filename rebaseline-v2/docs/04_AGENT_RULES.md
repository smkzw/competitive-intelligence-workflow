# 04 · v2 项目开发规则

本文件约束 v2 实施，不替代宿主全局 AGENTS 或用户授权。历史重写、强推、删除和全局路由变更不由本包授权。根 Trellis 仅作任务索引；v2 产品计划和状态仍分别只在 03_PLAN/STATUS。

## 必须
1. 开工先读：`README.md` → `docs/STATUS.md` → 当前里程碑在 `docs/03_PLAN.md` 中的条目。
2. 按同一根因成组验证：bug 先形成一组真实 RED，再完成最小完整修改，集中运行相关回归；失败按根因补正。稳定候选/里程碑再运行一次完整 `pytest -q`、Ruff及结构门，并绑定检查字节。不得每改一行或每次文档提交重复全仓检查；纯记录更新核对原回执、差异和链接即可。新功能须有必要测试，未执行不能记 PASS。
3. 自动回归中的网络相关测试一律离线（monkeypatch / 小夹具 ≤50KB）。真实来源/模型检查与 pytest 分开，使用有明确输入、版本和恢复记录的独立 smoke 或正常产品运行；常规 smoke 放 `scripts/smoke_*.py`，已有长程真实项目的保全入口留在忽略的 `ciw-data/`，不得混入离线开发门或仅为换名重跑。
4. `docs/STATUS.md` **替换式更新**（不是追加日志），≤150 行：当前里程碑、已完成、进行中、阻塞、下一步、最近一次真实运行结果。
5. 里程碑结束时附一次真实运行的证据（数字 + 截图路径），并更新 03_PLAN 的勾选。
6. 来源请求只记录安全头白名单（Content-Type、Content-Length、ETag、Last-Modified）、状态和规范来源地址；不落 Set-Cookie、Authorization、会话值或临时跳转参数。发现新未接受的请求元数据含会话值时，仅对该元数据显式脱敏并记录前后摘要，科学原件与历史manifest不改。
7. 领域规则改动（semantics / tiers / quote）必须同时改测试并在 STATUS 说明原因。

## 禁止
1. 提交运行产物、数据库、CAS、日志、第三方全文（PDF、HTML 页面、论文全文）、截图以外的大文件。
2. 在提交的文件中写个人目录绝对路径或密钥。
3. 在渲染器/流水线里写任何适应症、药物、NCT 专用逻辑（v1 P1-3 的教训）。
4. 新建 packets / prompts / reviews / handoff 之类的「过程文档」目录。计划只在 03_PLAN，状态只在 STATUS。
5. 用 LLM 判断能用代码确定的事情（解析结构化 JSON、算比例、比对字符串）。
6. 把 blocked/failed 当作「无结果」；把缺失写成 0；把事件次数当受试者人数。
7. 单个函数超过 80 行、单个文件超过 600 行（超出就拆；唯一例外：`web/app.py::create_app` 的路由注册，路由超过 20 个时拆成 APIRouter）。

## 遇到阻塞
- 外部来源被拦截：记 `coverage.status=blocked`，继续其他路线，在 STATUS「阻塞」写明，不要绕过网站访问控制以外的手段。
- 需求不清：在 STATUS「待用户决定」列出选项与推荐，继续做不受影响的部分。

外派续接按当前工作流guard的登记格式准备task/role/route、提示词与回执绑定，预检通过后再运行；预检不是已执行或流程审计通过。同会话多个回执逐文件核SHA和真实session，不将“最新log”冒作旧输出。命名/格式审计失败保留原件及原因，不事后改历史伪造PASS。


测试命令默认固定项目`.venv/bin/python`与`.venv/bin/ruff`；不要用系统Python/其他环境替代本项目门。只有观察到具体受支持解释器兼容缺陷时，增加对应有界多版本回归。正向缓存测试必须实际存入匹配CAS字节；篡改/缺失必须由独立负向用例拒绝，不能用假摘要和空CAS证明复用。
