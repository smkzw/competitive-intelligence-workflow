# 竞品调研工作流专属设计合同

本文件在康哲 `core.md` 之后、各格式 track 之前加载。冲突优先级固定为：用户当前指令 > 已批准 v1.2 > 本文件 > 通用 `core/track`。本文件只能增加项目专属细节或采用更严格规则，不得缩减 v1.2 的报告范围、证据门槛、四格式独立性，也不得降低品牌、字号或真实渲染要求。

## 1. 用户与阅读任务

- 默认用户是**资深临床试验医学人员**，业务经验丰富，但可能懒惰、视觉敏感、不熟悉计算机和 AI 操作。
- 用户只需选择 A/B/C 中 1–3 种报告、输入适应症，并选择是否需要 PDF、HTML-PPT 或 PPTX；系统负责其余默认配置。
- 首屏必须让用户直接看到最重要的竞品格局、疗效、安全性和开发状态，不要求理解工作流、证据引擎或程序状态。
- 详情页必须支持从总体结论下钻到具体药物、具体试验、具体治疗组、具体终点、具体时间点和证据定位。
- 默认信息密度高且完整，不以“简洁”为由删掉用户已批准的页面、字段、图形或完整表格。

## 2. 中文原生与用户可见边界

- 标题、标签、筛选器、提示、空状态、阻断说明、下载说明和讲者稿必须为**中文原生**的临床试验语境表达，不采用逐词翻译腔。
- 药物通用名、试验编号、标准缩写和必要统计符号可保留；首次出现的非通用缩写应给出中文含义。
- 不得展示程序状态、日志标签、提示词或后端字段名。
- `gate`、`signal`、`registry-only`、`AI evidence synthesis`、`accepted`、`pending`、`not_run` 等内部状态不得原样出现在报告。
- 搜索过程、证据门槛计算和技术诊断属于运行记录；如需交付，应单独生成中文 Markdown，不放在报告主要页面。
- 阻断信息只回答三件事：缺了什么、系统已经尝试了什么、用户可以提供什么；网络/技术故障必须与确实未公开或穷尽后未找到分开说明。

## 3. 门户与页面责任

- 门户首页与详情页共同构成完整报告：首页负责总体格局和默认比较，详情页负责全字段、全终点及证据下钻。
- A、B、C 每种报告都是独立的门户首页 + 多个物理详情页；不得以一张首页、单一长页或抽屉集合替代。
- 门户首页默认按靶点分组，不默认做疗效或安全性排名；用户可按疗效、安全性或疗效—安全性综合水平切换排序。
- 用户可任意多选药物、试验、终点、时间点、人群、治疗组和对照组；筛选状态在图、表、矩阵和 URL 中一致。
- **图在前、完整表格在后**。疗效先用柱状图、折线图或森林图；安全性先用热图；疗效—安全性矩阵先用气泡图；随后提供相同数据行的完整表格。
- 首页疗效展示 CDE/FDA 指导原则推荐或多数竞品采用的一个或多个主要终点；详情页保留全部终点并允许用户精简。
- 横向比较必须同时显示试验组和安慰剂/对照组效应，醒目标注时间点、人群和口径差异。
- 安全性不做简单名次；用颜色深浅和分维度视觉同时呈现 SAE、AESI、常规 TEAE、常见 AE 与发生率。
- 气泡图默认：横轴为常用主要终点疗效量化，纵轴为 TEAE 发生率，气泡大小为试验组样本量；允许用户更换疗效、安全性和气泡维度。
- B 类必须提供基线人口学、基线疾病严重程度、随机/治疗/完成/退出、依从性、失访、筛败、退出原因、补救治疗、禁用药、PD 等图表和完整表；未披露值明确写“未公开”。
- C 类必须能精确定位到某药物某试验的具体设计要素，例如入选标准中哪个评分、哪个时间点、采用什么阈值，并与竞品同字段并排比较。

## 4. 四种格式

### 4.1 门户

- 使用 `site + interactive` 组合路线；全局导航、搜索、筛选、返回路径和证据抽屉必须可用。
- 首页不解释 A/B/C 的定义，不显示运行流程、证据门槛卡片或提示词式文案。
- 所有声明的物理页面必须真实存在、互通并逐页验收，不能只验首页。

### 4.2 原生 PDF

- 使用 `stream + pdf` 组合路线；内容是筛选后的结果或默认全量结果。
- 信息密度高、完整、段落逻辑清楚；保留原生文字、矢量图、书签、续表和页码。
- 不专门解释筛选范围、证据版本或交互方法；必要可比性提示就近放在相关图表旁。

### 4.3 HTML-PPT

- 以视觉表达为主，有图时不重复放完整表；重点结论直接进入画面。
- 使用固定运行时：方向键/Home/End/全屏、逐页页码、`S` 讲者窗口、当前页与下一页预览、逐字稿、计时器、`R` 重置、双窗同步。
- `N` 只控制笔记，不得与下一页冲突；每页讲者稿为 150–300 个中文字符并与当前页定量结论一致。

### 4.4 PPTX

- 可编辑 PPTX 必须使用 PPT Master；结构化来源包、策略、规格锁、逐页 SVG、逐页质检、备注、拆分、后处理和原生导出均有阶段收据。
- 任何直接生成的 PPTX、整页位图、网页截图替代、伪造收据或复用旧导出均不得接受。
- PPT 以视觉反馈为主，有图时不重复放完整表；不单列筛选范围、关键口径、证据版本等说明页。

## 5. 字号与超高密度例外

- PPT/PPTX 普通正文和标签下限为 12 pt；HTML-PPT 普通正文和标签下限为 16 px。
- 只有元素显式标记 `data-density=ultra`、**仅限表体或坐标轴标签**，并同时满足以下全部条件，PPT/PPTX 才可降至 10.5 pt、HTML-PPT 才可降至 14 px：主体行不超过 18 行；行高不低于 18 px；文字与背景对比度至少 4.5:1；逐页原分辨率人工可读；存在机器可识别的 `data-detail-ref` 或真实详情链接。
- KPI、流程标签、图例不得使用上述例外；参考文献按 `core.md §0.7` 的独立下限处理。
- 条件不满足时必须拆页或精简短标签，不能缩字、裁字或转成图片。

## 6. 设计输入的类型化来源

- 每个设计验收 source pack 必须有机器 schema，并把数字 token 分为互斥类别：`audience_fact`、`page_number`、`date`、`section_number`、`brand_constant`。
- `audience_fact` 必须包含稳定 ID、来源定位、语义角色、原始值、单位、分母及适用人群/治疗组/时间点；一个 token 不得同时归入两个类别。
- 不得把兄弟 fixture 的数字加入宽泛白名单，不得把业务数字伪装成页码、日期或章节号。
- HTML 的受众可见层和隐藏 `aside.notes` 分开提取；notes 绑定 slide ID 与 claim ID，并与页面、图、表、PDF、PPTX 共同重算。
- 缺事实时可使用明确的无数据版式 fixture，不得猜数、借数或为填满画面补造结论。

## 7. 当前产物完成判定

- 生成者只可报告 `generated` 或 `generation_failed`，**生成者不得写入 accepted**。
- 完成判定由 runner-owned immutable run manifest 持有，并绑定当前 run、锁定报告快照、设计合同摘要、source pack 摘要、产物 SHA-256、渲染摘要、机器检查结果和独立验证者身份。
- 独立验证者与生成者必须是隔离角色；验证者只可接受或否决，不能静默改写产物。
- 旧产物改写 mtime、复制旧截图、伪造验证者名称、复用旧收据或只有退出码 0 均不得通过。
- 本 Task 仅接受“设计合同包已经内化并通过合同测试”，不接受任何报告实产物；门户、原生 PDF、HTML-PPT、PPTX 的当前 run 验收必须在对应渲染阶段完成。

## 8. 内容真源与视觉检查

- 所有可见数字、排序、比例、列表长度和定量结论必须从同一结构化事实集计算，并绑定稳定 claim/fact/row ID。
- 首页、详情页、图、表、讲者稿及四格式之间出现 5/9 与 6/9 一类矛盾时直接失败。
- 文件存在、对象可编辑、截图生成、结构扫描或通用检查“0 项问题”都不是视觉接受。
- 门户必须在 Chromium 与 WebKit 的真实用户视口逐页检查；HTML-PPT 必须检查最大化窗口和观众/讲者双窗；PPTX 必须逐页查看最新原始分辨率渲染；PDF 必须检查原生文本、分页、续表、书签和图表清晰度。
