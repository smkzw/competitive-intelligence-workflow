**核心操作轨迹**：
1. 打开 efficacy.html → 点击柱图（SVG 容器）→ 右侧“数据依据”面板展开（URL hash 变化）→ 点击“固定此条”。
2. 点击热图（`#kz-chart-1`）→ 打开产品丙数据 → 点击“固定此条”；再点击表格单元（产品乙安全数据）→ 固定第二条。固定对照表格成功显示两列，可核对定义、时间点、分母、冲突。
3. 点击“筛选条件”→ 选择“产品甲”→ 页面结果过滤；观察到固定对照表格从两列变为一列（产品乙固定项被移除），URL 中 `e=` 参数只剩一条。
4. 清除筛选 → 恢复全量结果。
5. 按 Esc → 数据依据面板关闭；焦点回到“筛选条件”按钮（非原触发元素）。
6. 复制带 hash 的网址到新标签页/刷新 → 固定对照表格保留，但当前打开的数据依据面板未自动恢复。
7. 导航到 baseline.html → 点击后退 → 回到 efficacy.html，hash 状态保留。
8. 1024×768 下：热图、状态矩阵点击均可打开数据依据；但右侧抽屉面板宽度（560 px）在 1024 宽屏下占比过半，多次遮挡主内容区图表的后续点击（Playwright 报 `aside subtree intercepts pointer events`），必须先 Esc 关闭才能继续操作图表。
9. baseline.html、disposition.html 均只有“当前数据”表格（无图表），点击表格单元可正常打开数据依据面板。三页中文文案专业、无英文系统术语暴露。

## 医学经理使用判断

- **一眼找到入口**：主导航“疗效与安全性概览 / 人口学 / 试验完成情况总览”清晰，页面标题与面包屑明确。
- **中文自然度**：页面使用“治疗组/对照组”“主要终点/次要终点”“已报告值/已报告零值”“披露状态”等临床试验常用术语，符合医学经理认知习惯，无机器翻译感。
- **视觉层级**：标题 → 筛选栏 → 当前数据表格 → 图表 → 固定对照/重点模块，层级分明，颜色对比度足够。
- **数据可核对性**：固定对照表格横排对比，字段含定义、产品、试验、组别、时间点、值、单位、分子、分母、披露状态、来源版本、冲突、原文定位，满足医学核对需求。
- **异常反馈**：筛选后固定项被静默移除，没有任何提示，医学经理会误以为之前固定的对照数据丢失了。

## P0/P1/P2 问题

### P1（必须修订）

1. **筛选后固定对照项被静默移除，未提示用户**
   - 复现：固定两条（产品甲 + 产品乙）→ 筛选“产品甲”→ 固定对照表格只剩产品甲一列，URL `e=` 参数中产品乙被删除。
   - 影响：医学经理在筛选后会发现对照数据“消失”，产生恐慌或误判。成功标准明确要求“筛选后不错误保留或扩大范围”，当前行为属于错误缩小范围。
   - 证据：`06_efficacy_two_pinned.png`（两列）→ `08_efficacy_filter_product_alpha.png`（只剩一列）。

2. **1024×768 下数据依据抽屉遮挡主内容区点击**
   - 复现：在 1024×768 打开数据依据面板后，直接点击左侧状态矩阵（`#kz-chart-2`）或柱图，Playwright 连续报 `aside subtree intercepts pointer events`，点击被抽屉拦截。
   - 影响：窄屏用户必须多一步关闭抽屉才能继续浏览图表，打断操作流。医学经理若不会按 Esc，会以为图表坏了。
   - 证据：操作日志中的 TimeoutError 与截图 `15/16/23`。

3. **柱图具体柱子点击难以通过精确坐标触发**
   - 复现：直接点击 SVG path（柱子）或容器 div 的特定坐标，仅容器点击有效；通过 `dispatchEvent` 向 SVG path 发送 click 事件无响应。
   - 影响：用户可能因点击位置不准而无法打开数据依据，降低交互成功率。需要确认 ECharts 图表的点击热区是否足够大。
   - 证据：`02_efficacy_click_bar_detail.png`（容器点击成功），JS dispatchEvent 无 URL 变化。

### P2（建议优化）

4. **刷新/复制网址后数据依据面板未自动恢复**
   - 复现：打开某条数据依据后复制 URL 刷新，固定对照保留，但数据依据面板关闭。
   - 影响：医学经理分享链接给同事时，同事需要重新点击才能看到具体依据。

5. **Esc 关闭后焦点未回到触发元素**
   - 复现：从表格单元打开面板 → Esc 关闭 → 焦点落在“筛选条件”按钮。
   - 影响：键盘/辅助技术用户需额外 Tab 才能回到原位置。

6. **演示数据未覆盖“未公开/技术暂不可用”状态**
   - 复现：全站文本搜索（`未公开`/`技术暂不可用`）计数为 0。仅观察到“已报告值”“已报告零值”“不适用”。
   - 影响：无法验证这些边缘状态的视觉呈现和颜色区分是否符合设计合同 §15.4–15.6 的 fail-closed 要求。

7. **1024×768 固定对照表格可读性受限**
   - 复现：1024 宽下两列固定对照加核对字段列，横向空间紧张（截图 `23`）。
   - 影响：字段名与数值可能折行或挤压，长时间对照阅读易疲劳。

## 结论

**REVISE**

理由：
- P1-1（筛选后固定项静默丢失）直接违反“筛选后不错误保留或扩大范围”的成功标准，且对医学经理的“固定对照”核心使用场景造成实质性误导。
- P1-2（窄屏抽屉遮挡主内容）在 1024×768 这一必须支持的分辨率下导致交互阻断，用户无法连续操作图表。
- P1-3（柱图点击热区）影响数据依据打开的成功率。

即使页面能打开、流程能跑通，上述问题在真实工作流中足以让医学经理产生“数据丢失”或“系统不稳定”的误判，故不满足 PASS 条件。建议修复后复测。
