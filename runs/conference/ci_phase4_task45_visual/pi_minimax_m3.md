## 临床信息可读性

**正面**：
- 全中文自然语，标签术语恰当（疗效·产品甲·治疗组·HbA1c 变化值，比"row1/productA/arm1"直白）。
- 抽屉的字段分层（产品 / 试验 / 组别 / 时间点 / 值 / 阈值 / 单位 / 分子 / 分母 / 披露状态 / 规范化说明 / 来源版本 / 原文定位 / 简短原文 / 冲突 / 历史版本）就是医学经理日常核对报告的口径；冲突来源 + 数值 + 章节 + 页码齐全。
- 来源版本（ClinicalTrials.gov 登记结果 2026年5月1日）写在每个 drawer 顶部，对内部审计友好。
- 颜色对比（橘色治疗组 / 蓝色对照组）易读。
- "匹配 3 项结果"提示过滤后行数，让经理清楚当前数据集大小。

**缺陷**：
- HbA1c 单位写作 **mg/dL**，临床正确单位是 **% 或 mmol/mol**。资深内分泌/皮肤科医学经理看到会立即皱眉，这是临床准确性问题，不是审美问题。
- 热图（次要终点）8.4 vs 9.6 颜色几乎相同（rgb(253,158,16) vs rgb(255,153,0)），热度图应有的梯度对比几乎为零；图例写"比较" 二字过简，应直接叫"值越深越高"。
- 状态矩阵 Y 轴显示两次相同的指标名（"主要终点 HbA1c 较基线变化值"重复两行），Y 轴本应区分 治疗组/对照组；legend 显示"治疗组 / 对照组"用橘 / 蓝色块，但两条柱都是橘色，对照组本应蓝色却用了浅橘，视觉与图例不符。
- 状态矩阵的表里"比较值"列填了"已完成 / 进行中"状态字符串，"单位"列写 mg/dL — **比较值列被误用来显示状态，单位列与内容不匹配**。
- "当前数据" 表只列了 7 行原始数据，无值/单位/披露状态/时间点/分母 —— 经理要查具体值必须挨个点击进 drawer，跳转成本高。
- 标题"重点模块"下的"01 主要终点 / 02 安全性事件"卡片是不可点击的纯文字（无 href、无 onclick），从位置 + 卡片样式看像入口但点了无反应，会让经理怀疑自己没点对。

## 交互可发现性

**正面**：
- 行点击 / 图柱点击 / 热图单元 / 状态矩阵单元都映射到同一 drawer，`data-row-id` 一致，"图 / 热图 / 表格打开同条数据"硬指标达成。
- 固定一条 → 双列对照表 13 行核对字段（定义/产品/试验/组别/时间点/值/单位/分子/分母/披露状态/来源版本/冲突/原文定位）= 完全满足"两条对照后比较定义/时间点/分母/冲突"硬指标。
- URL 状态（`eo=` 当前 / `e=` 固定 / `ps=` 筛选）刷新 + 前进后退保留。
- Esc 关闭 drawer 干净，hash 回退到父级。

**缺陷**：
- 筛选产品乙后，**bar 图 / 热图 / 状态矩阵全部消失**，只剩 3 行表 + 大片空白。经理会误以为"产品乙没数据"或"页面坏了"。正确做法：图表对缩窄后的数据仍应渲染（如产品乙·治疗组 vs 产品乙·对照组的 HbA1c 单组对照图），而不是整段空白。**这违反了"筛选后范围不放大"，且"信息密度在筛选后显著下降"，是真实可用性回归。**
- 顶部"菜单"（汉堡）按钮在 ≥1024 视口下被收掉，经理想跨页必须先开菜单 → 多一次点击。1024 是常见笔记本分辨率，这不是 mobile-only 场景，应保留 nav。
- 抽屉宽度固定 ~580px，1024 视口下挤压页面至 ~440px；800px 抽屉宽度 / 80% 视口宽度自适应会更稳。
- "重点模块"卡片 不可点击 → 视觉假入口。
- 顶部搜索框视觉像个搜索框，但输入+Enter 无任何反馈（无下拉、无跳转、无提示）→ 视觉假功能。
- 筛选条件条上"0 无筛选条件"标签 + 橘色椭圆样式，橘色让人联想到主要操作，但实际只是入口标识；点击后才能展开筛选器，初次使用者会犹豫"是不是点了它会清空筛选"。
