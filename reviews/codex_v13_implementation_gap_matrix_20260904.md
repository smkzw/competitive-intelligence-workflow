## 3. R0 已关闭但继续生效的事实

1. 预变更 inventory 只记录路径与 Git 状态，不能单独证明完整、可恢复的 R0 基线；这一来源缺口已在治理记录中永久保留，没有被补造。
2. 当前树已建立两个逐节点哈希、外置只读恢复点。首个恢复点保留 R0 修复后的状态；M1 恢复点保留 R0/R1 会商收口和精确缓存清理后的状态。两者都不是“所有变更前”的字节级备份。
3. 两份现有 source-set JSON 是历史 candidate baseline，包含 422 个文件和非 HTML 内容，且 `release_ready=false`。它们只作审计证据，不能作为最终 v1 release source-set。
4. 最终 HTML-only source-set 仍只能在 R2-R4 产品面、CLI、包合同与适配层完成后生成并冻结。
5. R0 的 `GATE_OK status=quality-only steps=4` 只证明声明范围内的 Ruff、strict mypy、单元/合同测试和旧路径扫描，不证明 clean provenance、bundle、宿主、门户、RC 或 release。
